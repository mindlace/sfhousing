## Legs

1. **Coverage.** Checked every interface row, ruling, global constraint, subsystem scope sentence, "Presets" item and dependency-order statement against the specs, with "Row ownership" as the map. Carried by none: step 0 (X2) and the `marketLevel` switch (X1). Claimed twice: step-0 types (X2), the release dataset builds (X6), validators of one field (X10). Every preset of "Presets" is in `fl` §4.7 (the state bond is not offered at all where the design allows a user amount; that follows OD-F3 and is stated).
2. **Seams and signatures.** Checked `fundBundle` (shape, tiers, per-item fields, subset calls in `fe`, re-pricing in `fs`, page use in `ui`), `inflowArrivals` (signature and window use in `fl`, `fs`), `SimInput.finance` and `off` (inclusive `to`, arrivals on off days, scaled inflows), `Schedule.funding`, the ledger events and `ProjectCard` (`fe` against `fs`, `ui`), `TimelineScore.tiers` and `.money` (`lost`, `lostCredit`, `publicSpent`, `perAddedHome`, `cityOf`, `displacedShare`, `owedAt`), `Calibration.market`, `marketSteps`, `marketLevel`, the 95% flag, `baselineFunding` ids and kinds and the fixture shape, `resolveTerms`, `TermKey`, `POOL_KIND_DEFAULTS`, `valueSource`, `FundingLoadReport`, draw purposes against `rng.ts`. Mismatches: X1, X4, X12, X13, X14, X15. Rounding of asks (`fe` per item against `fm`'s one rounding of the sum) agrees, because each item has one non-zero part.
3. **Contradictions.** Found X3, X7, X8, X10, X16, X17. The stale numbers −1.10, "about a third" and "about 30%" survive only as labelled history in OD-F9a and OD-F11. "Every pool must pay", "the first programme in its bundle" (`fl:268` copies `minHomes` and `tiers` from the first baseline programme, which is data, not a fill rule), a fixed fill order of City kinds and "upper bound" for loans appear nowhere as live rules.
4. **Fidelity to the source documents.** Checked each Traceability row against the levers spec (Phasing 2, Goal 3, anti-goals, constraints, rulings), the sim design's OD-8 and the timelapse design's evidence hierarchy; each claim is quoted fairly and its carrier exists. Gaps are X18 only. The V19 size budget does not apply (it bounds `parcels.bin`, which nothing here changes); V20 and V25 budgets were not measured against the new fields.
5. **Rows verbatim.** `node .superpowers/superconductor/sim-financing/sync-rows.mjs … --check`: every spec reports 0 lines differ (`fd` F1 F4 F5 F6 F12; `fe` F1 to F12, F18; `fl` F5 to F9, F12, F15 to F17; `fm` F1 F4 F5 F6 F8 F9 F13 F14; `fs` F1 F4 F5 F6 F8 F9 F10 F12 F13 F14; `ui` F5 F6 F7 F8 F10 F12 to F16; `mb` F1 to F4), exit 0. Rows built against but not embedded: X11.
6. **Dependency order.** Uses of a later subsystem: `fe`'s ledger identities from `fs` (X9); `fe`'s Release 2 golden step after `fs`, `fl`, `ui` (X6). Step 0 is a prerequisite with no owner (X2). Everything else each subsystem needs is provided by an earlier step.

Not done: the Behaviour sections were read in full for `fm`, `mb`, `fd`, `fe`, `fs`, `fl` and `ui`'s §4.1 to §4.16, but the numbers inside them (preset arithmetic, bench counts, worked bundles) were spot-checked, not recomputed; the code was read only for `rng.ts` purposes, the hashed `PATHS`, the type files' locations and imports; the evidence digest and the primary sources behind each constant were not opened (another checker's leg).
