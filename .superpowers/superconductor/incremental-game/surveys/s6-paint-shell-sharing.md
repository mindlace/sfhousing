## Headlines (facts a designer will trip over)

1. Nothing from a Paint plan reaches `/sim` at runtime. Paint's plan is autosaved under `sfhousing:plan:v1` (src/lib/sharing/doc-codec.ts:56); no file under `src/lib/{sim,sim-page,timeline}`, `src/routes/{sim,s,sims}` reads that key or `PLAN_CODEC` (grep, section 5). The only localStorage key shared by both pages is `sfhousing:view` (map layer toggles). /sim even constructs its `BrushState` with `storage: null`, so Paint's brush size/height setting (`sfhousing:brush`) is not shared (src/lib/sim-page/SimPage.svelte:498).
2. "Goal met" has no state in Paint beyond a text swap: line 2 of the header reads "Goal reached" instead of "N% of the goal" (src/lib/paint/headline.ts:24). No unlock, no navigation change, no persisted flag (section 3, 13).
3. The header "steps" (1 Paint, 2 Simulate) are two unconditional links; nothing decides whether `/sim` is reachable (src/lib/shell/SiteHeader.svelte:119-132).
4. Publishing is anonymous: no session, user id or account is read or stored by `POST /api/plans|policies`; the `plan` table has no user column; one table holds plans and policies (section 7).
5. Paint's goal code imports sim modules (`$lib/sim/timeline-client`, `$lib/sim/world/months`, `$lib/sim/world/score/types`, `$lib/fzp/*`) (src/lib/goal/goal.ts:6-13). Paint's page imports `$lib/timeline/results` and `$lib/timeline/TimelineHeaderScore.svelte` (src/routes/+page.svelte:29-30). BrushEditor imports `$lib/sim/client` (SimClient, spawnSimWorker) (src/lib/brush/BrushEditor.svelte:49-54). So Paint and /sim share the score/worker/header-score code, not just types.
6. The goal's amount (82,069) is defined in `src/lib/scoreboard/targets.ts:12`; its deadline in Paint is not used at all (Paint says "Goal: 82,069 homes" with no date); /sim's deadline is computed from the dataset date; the RHNA statutory deadline constant lives outside scope in `src/lib/sim/scenario/score.ts:293`.
