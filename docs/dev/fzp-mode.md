# /fzp: the Family Zoning Plan timelapse

Developer notes for `src/lib/fzp/`. The design is `docs/superpowers/specs/2026-10-16-fzp-mode-design.md`; this file records what the code does for people who change it or write tests against it. The page composition is `src/lib/fzp/FzpMode.svelte`.

**Routing (plan 3).** `/fzp` is no longer a page: its load (`src/routes/fzp/+page.ts`) is a 307 redirect to `/sim` with every query parameter kept except the retired `start`. `/sim` itself opens on the Family Zoning Plan comparison (`DEFAULT_LEVERS`: FZP as written against pre-FZP zoning). The `/sim` route (`src/routes/sim/+page.ts`, `+page.svelte`) loads the manifest and calibration, owns the `?seed=` URL and renders `SimPage`, which wraps FzpMode with the policy dock. See [sim-page.md](sim-page.md). The header link is "Simulate" (`/sim`).

## The scrubber contract

`TimeScrubber.svelte` is a native `<input type="range">` over `[asOf, horizon]` in days (`step=1`), where `asOf` is `calibration.asOf` and `horizon` is `HORIZON` (2066-12-31, `src/lib/fzp/time.ts`). Its accessible name is "Date in the simulation" and `aria-valuetext` is the readout ("October 2026").

| Key                 | Effect                                                                    |
| ------------------- | ------------------------------------------------------------------------- |
| Left / Down         | the previous first-of-month strictly before the day, clamped up to `asOf` |
| Right / Up          | the next first-of-month strictly after the day, clamped to `horizon`      |
| Page Down / Page Up | twelve months back or forward from the month start, clamped to the range  |
| Home / End          | `asOf` / `horizon`                                                        |

Keys with Alt, Ctrl or Meta are left to the browser. Every handled key, a drag on the track, the start and end marker buttons and the marker buttons under the track **pause** playback and move the day (`jump`).

**Transport.** Left to right: Pause (`fzp-pause`), Play (`fzp-play`), Faster (`fzp-faster`, `title` "3 years per second"), the readout (`fzp-readout`), then the track row: the start marker (`fzp-start`, text `startLabel`, default the short month and year of `asOf`; `/sim` passes "Today"), the range, the end marker (`fzp-end`, the horizon year), and the marker row under the range. Pause stops. Play plays at 1 year per second (`year`); Faster plays at 3 years per second (`threeYears`). Either one, pressed at `horizon`, restarts from `asOf` first (Replay). Play and Faster carry `aria-pressed` (`playing` and their speed), so a test reads the play state from `fzp-play`'s `aria-pressed` and the speed from `fzp-faster`'s, not from a label. There is no speed select.

**`ontoday`.** Called when a user jump lands on `asOf` outside setup: Home, the start marker, an arrow or Page key clamped to `asOf`, or a drag released there (the range's `change`; `input` events passing through `asOf` do not count). Not called by Replay, by the frame loop or by a programmatic `day` change. It fires even when the day was already `asOf`.

**Fixed width.** The Play button (`fzp-play`) and the readout (`fzp-readout`) stack every label (Run, Play, Replay; the 12 month names of the current year, `monthYearLabels`) in one grid cell, the extras `invisible` and `aria-hidden`, so the bar never shifts. The visible text has its own testid (`fzp-play-label`, `fzp-readout-label`); assert on those, because the readout's own text contains every month. There is no "Simulation" pill.

**Setup mode.** With `setup` Play reads "Run" and calls `onrun`; Pause and Faster are `invisible` (they keep their space and leave the tab order, so the bar does not shift); the range, the start and end markers and the marker buttons are `disabled` and keys do nothing.

**Run phase (`FzpMode`'s `runPhase`, `/sim` only).** `/sim` passes `runPhase` (`'setup' | 'run'`, `src/lib/sim-page/run-phase.svelte.ts`) and `onrun`; without `runPhase` (a bare FzpMode) nothing changes. While `'setup'`, FzpMode passes `setup` to the scrubber, stops playback and pins the day at `asOf`: any move away (a calibration reload included) is put back through `onDay`, the path a scrubber jump takes. TimeScrubber does not pin the day itself. The Run press sets FzpMode's `playWhenCurrent` flag and calls `onrun`; once the page has moved `runPhase` to `'run'`, playback starts as soon as the score is not busy (a timeline at or after the latest levers' rev) and the page has no levers pending (`leversPending`, `/sim`'s `LeverSync.pending`), so Run never plays a timeline computed before the latest policy. While the flag is set the scrubber stays in `setup` (the button reads Run, `aria-busy`), so no press can play an older timeline; `leversPending` also marks the header score busy. Playback starting and a return to `'setup'` clear the flag.

**Scrubbing back to Today (`onrewind`).** With `runPhase` given FzpMode passes `startLabel="Today"` (the start marker reads Today, not the date; a bare FzpMode keeps the date) and `ontoday={() => runPhase === 'run' && onrewind?.()}`. `onrewind` is the page's cue to end the run: `/sim` passes `resetRun`, so a user jump to `asOf` (see `ontoday`) returns to Setup, and the Setup effect then pins the day and stops playback. Replay and the frame loop never call it.

- **Speeds** (`playback.ts`, a tier 4 UI choice): `Speed` is `year` ("1 year per second", the default, Play) or `threeYears` ("3 years per second", Faster; `SPEED_NAME`), as days of simulated time per second of wall time (`12 x MONTH_DAYS`, `36 x MONTH_DAYS`). `window.__sfhFzp.speed` reports the current one.
- **Frame step:** only while `playing`, through `requestAnimationFrame`: `t += min(dt, 100 ms) x daysPerSecond`, `day = min(floor(t), horizon)`. The 100 ms clamp stops a background tab from making the clock jump. If something else moves the day mid-play, the clock continues from there.
- **No autoplay:** playback never starts on its own; the page opens paused at `asOf` and waits on Play (on `/sim`, on Run in Setup).
- **`onday`:** called exactly once per day change (`setDay` compares with the current day first). FzpMode's `onDay` does O(1) work: `handle.setTime(day)`, and a card refresh only when the month changed.
- **Opening the sources dialog pauses** (`onopen` sets `playing = false`). Opening a card does not.
- The readout is not a live region (it changes every frame). The header score's live region (`HeaderScore`, `data-testid="score-live"`) speaks only when playback is paused, 1000 ms after the day settles.

The page always opens paused, so tests get a stable day without any media emulation. `gotoFzp` emulates `reducedMotion: 'reduce'` only to keep the map's generated-building animation off (`SimMap` reads `prefers-reduced-motion`).

A notice never changes it. `--map-controls-br-block-size` includes that inset.

The top-right scoreboard card, `FzpScoreboard` with its phone score bar and sheet, and `--scorebar-h` are gone (plan 3, layout ruling 1): the header score (`src/lib/scoreboard/HeaderScore.svelte`, `data-testid="score-bar"`: "{n} homes added", a 4 px RHNA meter, and in a run that compares your policy with the FZP a `score-delta` "vs FZP +N") replaces them. FzpMode takes `scoreExpanded`, `scoreControls` and `onscore` for it; on `/sim` the button flips the dock to its Results face (FzpMode's `panel` snippet receives the Results snippet, `SimResults`) and back. The button's name is the count alone: the delta describes it and the meter sits beside it. A default-policy run shows no delta: it compares the FZP with the old zoning, so "vs FZP" would mislabel it. With no bottom score bar, the scrubber sits at the bottom on phones.

Every notice is a pill (`PILL` in `src/lib/shell/pill.ts`) in one stack, `NoticePills` (`data-testid="fzp-notices"`), the first row of `FzpMode`'s root (a flex column; the map and everything positioned over it, card, tooltip, scrubber, panel and dialog, are in the second row). The stack holds the loading, failed (Retry) and no-scenario notices, the page's `notices` snippet (`SimNotices`), and the ready-phase ones: the stopped pill with Retry, "Making another future…", the dismissible reroll alert, and on `/sim` the lever notices in `data-testid="fzp-lever-status"` and the failed-revision alert in `data-testid="fzp-lever-failed"` (their regions are `display: contents`, so an empty one adds no gap). From md the stack is an overlay at the top centre of the map (`absolute top-2`, centred right of the dock by `--dock-w`, `pointer-events-none` with `pointer-events-auto` pills): it takes no space, so a notice never moves the dock, the scrubber or the map inset. Below md it is in flow under the header, full width, and pushes the map down while a pill shows (no height when none does). `e2e/sim.spec.ts` and `e2e/fzp.spec.ts` check both rules.

## The debug hook

`window.__sfhFzp` (`src/lib/fzp/debug.ts`) is read-only and exists only in a build made with `VITE_E2E=1` (the e2e build sets it; otherwise the branch is constant-false and dropped). Each field is a getter over the live page state.

| Field             | Meaning                                                                                                                                                            |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `phase`           | `'loading'`, `'ready'`, `'failed'` or `'no-scenario'`                                                                                                              |
| `seed`            | the shown future's seed, `null` until the first timeline                                                                                                           |
| `representative`  | true for the representative future (no `?seed=` in the URL)                                                                                                        |
| `day`             | the scrubbed `Day`                                                                                                                                                 |
| `asOf`, `horizon` | the scrubber's range                                                                                                                                               |
| `playing`         | whether the frame loop is running                                                                                                                                  |
| `score`           | the latest `TimelineScore`, or `null`; `score.band` and `planEffect` may be incomplete until the band runs finish (the Results face marks those lines `aria-busy`) |
| `runPhase`        | `/sim`'s phase, `'setup'` or `'run'`; `null` without `runPhase`                                                                                                    |
| `levers`          | `/sim`'s lever status: `{ status, done, total, sentRev }`, see [sim-page.md](sim-page.md)                                                                          |

`window.__sfhMap` (`src/lib/map/debug.ts`) gives the MapLibre map. Test helpers: `e2e/helpers/sharing.ts` (`jumpAndIdle`, `projectToPage`, `FRAME`, `headerAction`, `openHeaderMenu`) and `e2e/helpers/a11y.ts`. The specs are `e2e/fzp.spec.ts`, `e2e/fzp-sim.spec.ts` and, for `/sim`'s own controls, `e2e/sim.spec.ts`.

## /sim props: `view`, `onmanifest`, `onheights` and `onchunks`

- **`view`** (`ViewPrefs`, default `HIDDEN_VIEW` from `src/lib/view/prefs.ts`: every layer off) is passed to SimMap as is. `/sim` passes the viewer's prefs in Setup and `HIDDEN_VIEW` during a run.
- **`onmanifest(m)`** reports the manifest SimMap renders, once at setup and again whenever a Retry replaces it (as BrushEditor does for `/`). `/sim` builds its View rows from it.
- **`onheights(city)`** gets a `heights` message's `HeightCity` (city-wide contour chains and labels) for a lever revision at or above the latest rev sent ([sim-levers.md](sim-levers.md)); a stale one is dropped. `/sim` draws it as the height limits ([map-interfaces.md](map-interfaces.md), "Height limits"). The glass lids are not a prop: `SimClientApi.heightLids(bbox)` forwards to the worker's `heightLids` request, and SimPage calls it per view.
- **`onchunks()`** fires when the worker reports newly loaded parcel chunks. `/sim` uses it to re-ask for the eraser's outlines while the last answer had lots in chunks not yet loaded ([sim-page.md](sim-page.md), "Map overlays").

## Request flow

- **Scenario:** `FzpMode` owns a `ScenarioClient` (`src/lib/sim/scenario-client.ts`) over the simulation worker. `startScenario` is the only caller of `initScenario`; "Another future" and "Back to the representative future" go through `requestReroll`. Each request carries a revision; timelines and errors for older revisions are dropped. The page writes `?seed=N` through `onurlseed` only for the answer to a reroll (a null seed is the representative future and removes the parameter). Unknown query parameters are kept.
- **Prefetch:** after the first timeline following each `initScenario`, and on every `moveend`, the page asks the worker to fetch the parcel chunks for the viewport. The worker fetches only those chunks, the three `scenarios/fzp/` timelapse files and, because `/sim` always initialises with levers, `policy.bin`. `transit.json` and `neighborhoods.geojson` are fetched only for brushes (see [sim-page.md](sim-page.md), "Request flow").
- **Picks:** SimMap reports `timelinePick` events. A hover over a part feeds the tooltip's requester; a tap or mouse click feeds the card's requester; a tap or click on nothing closes the card. Hover shows a tooltip only. Existing buildings keep SimMap's own tooltip. Parts of a simulated project are pickable only while visible at the scrubbed day.
- **Summaries are latest-wins** (`summary-request.ts`). One `SummaryRequester` per surface (card, tooltip): at most one request in flight and one queued behind it, and only the latest query's answer reaches the UI. While a card is on show, a request for the same parcel and project keeps it on show until the answer replaces it (no flash of "loading" on every month). A `not-loaded` answer is retried on each worker `chunks` message.
- **Card refresh:** the open card asks again when the scrubbed month changes, when a reroll or crash Retry answers, and when the worker crashes (then it reads "Details unavailable" until Retry).

## The T9 lookups seam

The card's chance lookup (`chanceTable`) and the map's stage-duration lookup (`typicalMonths`) start from the base `calibration.json` (`lookupsFor` in `FzpMode.svelte`, one object per calibration object, because SimMap compares lookups by identity). `pushLookups` is the single call site that hands them to the map.

The seam is switched on `/sim` (plan 3). Every session initialises with levers (`startScenario({ seed })` sends the current `levers` with `initScenario`), and once a lever revision is `current` the worker's posted `lookups` (`{ inFlight, fresh }`, [sim-levers.md](sim-levers.md)) replace the calibration's: the map gets `{ ...lookups.fresh, inFlight: lookups.inFlight }` (Call 15; one object per posted `lookups`, for the identity check), and each card picks its cohort's table (`card.lookups`, `'inFlight'` or `'fresh'`, shifted by `chanceShift` for an in-flight project in a rescaled stage). Until then the main-thread tables stand in, with no `inFlight` (as on `/fzp`). Nothing else in the page should read the calibration for these tables.

Cohort-aware bars (Call 15). On a run whose input has `newProjects` (every `/sim` run), the engine sets `Schedule.inFlight: true` on each schedule whose job ran on `calibration`: pipeline rows past `preApplication`, and phases. `packTimedCell` writes it to `slotCohort` (0 fresh, 1 in flight). The chance texture is 36 rows, `chanceRow(pathway, stage, cohort) = cohort · 18 + pathway · 6 + stage`: rows 0 to 17 hold the top-level (fresh) chance, rows 18 to 35 `inFlight.chance`, or the fresh rows again when `inFlight` is absent. A bar's `segRow` and `segTypicalDays`, and a part's construction typical days, read its slot's cohort. Without `newProjects` (`/fzp`) no schedule carries the flag, every slot is cohort 0, and the bars are unchanged.

## Known gap: no keyboard access to cards

Map picking is pointer-only (mouse click, touch tap, hover), a gap shared with the editor's tooltips (see "Known gap" in [map-interfaces.md](map-interfaces.md)). A keyboard user can drive the scrubber, the Results face and the sources dialog, but cannot open a project card. Once a card is open it is a normal region with a Close button, and Escape closes it (unless the sources dialog is open, which takes Escape first).

## The chart's y domain

`ScoreChart` (`chart.ts`) draws every series on one y axis. The domain covers every drawn value, the references and the RHNA target. It starts at 0, **unless a drawn value is negative**: the plan-effect series can be early on. Then the axis reaches down to `-niceCeil(-min)` so the negative part stays inside the plot, and a floor gridline is added when it is clear of the zero line. Spec section 4.6 says "0 to niceCeil"; the extension is deliberate.

## e2e notes

- Run on port 4206 with one worker: `SFH_E2E_PORT=4206 SFH_E2E_WORKERS=1 npx playwright test e2e/sim.spec.ts e2e/fzp.spec.ts e2e/fzp-sim.spec.ts`.
- `e2e/fzp.spec.ts` opens the timelapse at `/sim` (`gotoFzp`; a reroll's URL is `/sim?seed=N`). `e2e/sim.spec.ts` covers the `/fzp` redirect itself (`/fzp?seed=5` lands on `/sim?seed=5`).
- The fixture dataset (`fixture-0`) has two parcel chunks (cell 50_25, 15 parcels; cell 51_25, 3 parcels, lots 15 to 17) and four scenario files, all read by `/sim` at load (`parcels.bin`, `projects.json`, `calibration.json`, `policy.bin`). Tests read `projects.json`, `calibration.json`, `parcels.bin` and the chunk from disk and derive counts, ids and labels; do not hard-code them.
- fixture-0's two parcel chunks are neighbouring cells about 700 m apart, so they cannot show over-fetching by themselves. `e2e/fzp-sim.spec.ts` adds a third, far-away chunk to the manifest the page loads (route on `manifest.json`, reached by client navigation as below), asserts it is not requested while the viewport is elsewhere, then pans to it and asserts it is.
- The score details are the dock's Results face, one region ("Results", `data-testid="score-details"`); the header score (`data-testid="score-bar"`) flips the dock to it, and a run shows it. Its Sources disclosure (`data-testid="fzp-sources"`) holds "Back to the representative future" and "Where these numbers come from": open it first. Below 768 px the header's links and actions ("Policy", "Another future") wait in the Menu: use `headerAction` / `openHeaderMenu` (`e2e/helpers/sharing.ts`). The phone sheet is not modal; its handle (`data-testid="dock-handle"`) opens and folds it, and opening the Menu folds it.
- A first load of `/sim` takes the manifest from the server's render, so `page.route` on `manifest.json` has no effect there. To test a dataset without scenarios, navigate to `/sim` from `/about` (a page that loads no manifest) with the route in place.
- Axe and the footer check: `expectNoA11yViolations` runs with the card open, with the sources dialog open (scoped to the dialog, `structure: true`), with the Results face open and, in `e2e/sim.spec.ts`, with the dock open on each tab, on Results during a run, and with the transit rule form open. At 375 px the footer links must stay unobscured with the scrubber, the card, the Results face (a run's peek included) and the phone tool bar showing.
