Overview

Goal: Build the game-lane unit: the browser store and server table hold the v2 game (rows G7, G8), the header carries GameCell and GamePanel (row U1, part B), /sim's page plays the run, tally, tree and workshop loop under bought limits, and / becomes the one address whose opening is Paint.

Architecture: Four parts in one branch, merged once. Part S (game-save) moves GameStore, the sync, game_save and /api/game to GameState and deletes the five-level rule files. Part T (tally-tree B) adds GameCell and GamePanel under src/lib/game/ui/. Part M (game-sim) gives TimelineMode and SimPage the phases, the run clock, settling, the tree and limits in every editor. Part H (game-shell) renames the site, rewrites the header, and puts the opening and the simulation behind /.

Tech Stack: SvelteKit 2, Svelte 5 runes, Tailwind 4, Cloudflare Workers, D1 with Drizzle (npm run db:generate), Vitest (server and client projects, browser tests via Playwright), Playwright e2e.

  • state and limits are reactive. limits is OPEN_LIMITS for the open game, else limitsOf(state).
  • Every save the store reads, from storage or from the server, passes through parseGameSave and then its state through fitGame (G6).
  • won sets firstWinAt once and writes.
  • startRuns sets phase to 'runs'. It does nothing while firstWinAt is null.
  • buy writes the new state when the purchase is good and returns what buy of G3 returns. A refused write returns { ok: false, reason: 'short' } and changes nothing.
  • The store does not hold the policy document. The page applies the grant (G5).
  • Each write calls sync.changed(id), as today.
  • The open game is in phase 'runs' with the last rung met, every node bought and no units; its methods that write do nothing.
  • settle does nothing for a result already settled.

Unchanged: the saved-games methods, touched, beforeLeave, the storage keys, SaveSync. Removed: progress, allowed, offer, setOffer, levelUp, remix, Offer.
