Planafoot auth port plan

Port planafoot's accounts, sessions, roles, membership and invitations into sfhousing, with "quest" renamed to "sim".

For agentic workers REQUIRED SUB-SKILL: use superpowers:subagent-driven-development to implement this plan task by task. Steps are checklist items; progress is kept in the workspace ledger, not in the plan.

Overview

Goal
sfhousing gains planafoot's identity model (pseudonymous accounts that upgrade by email magic link, plus password, passkey and Google behind a switch), the capability ledger, sims as membership containers at /sims/[simId], invitations, an /account page, account deletion and the reaper functions, as a foundation for the later per-sim Durable Object log.
Architecture
A port, not a redesign. Each task copies named planafoot files, applies the rename map and the listed cuts, ports their tests, and makes them pass. Membership is D1-only: a sim_index row plus role grants on the capability_event ledger; the future Durable Object attaches through the no-op onSimRosterChanged(simId) seam. Better-Auth runs per request only when a session cookie is present or the route needs it. Which sign-in methods are live is read from one var, AUTH_METHODS, defaulting to magic link only.
Tech Stack
SvelteKit 2, Svelte 5 runes, Tailwind 4, Cloudflare Workers, D1 with Drizzle 1.0 rc, better-auth 1.6.25 with @better-auth/passkey, better-svelte-email, Vitest (server and browser projects), Playwright.

The owner's instruction ("steal everything auth related from planafoot auth/invite/etc via s/quest/sim/"), the dispatch's fifteen decisions as amended (sign-in methods switch; BETTER_AUTH_SECRET already set), and the port manifest docs/superpowers/design/2026-11-14-planafoot-auth-port-manifest.md, with the corrections in Manifest corrections.

Review Focus

The failure modes a mechanical port most likely ships. Each names the task whose tests pin it.

  1. Signed-out visitors see exactly today's site. /, /sim, /s/[id], /p/[id] and /data/... with no cookie never construct Better-Auth, never set a cookie, and keep their cache headers; /data/ skips the session even with a cookie; a missing BETTER_AUTH_SECRET breaks only auth routes.   2. Hook order and cookies. The session handle runs before the header handle, and the header handle's immutable-headers re-wrap keeps every set-cookie (two cookies in, two out). Pinned in Task 9.
  3. Disabled methods are unreachable. With the default AUTH_METHODS, password, passkey and Google endpoints (Better-Auth paths, form actions, /forgot-password, /reset-password, /api/account/password) answer 404 and no page renders their controls; the e2e cookie override is ignored outside an e2e build. Pinned in Tasks 8, 9, 11, 12, 17.
  4. Severed couplings left half-attached. No import of a Durable Object stub, Money, Stripe, MCP OAuth, PostHog, Paraglide, user_settings, groups or OAUTH_KV survives, and every former syncQuestRoster call site calls onSimRosterChanged. Pinned by a grep step in Task 19 and by sims.spec.ts (Task 5).
  5. Foreign-key actions frozen right in the one migration. capability_event.principal_id cascade; user, session, account, passkey, user_version, sim_invite.invited_user_id and invited_by_user_id cascade; sim_invite.accepted_by_user_id set null; user_identity → principal, superseded_by_id and handle_tombstone.released_by no action; no foreign key on sim_invite.sim_id, which is NOT NULL.
