Run play implementation plan

Drops, the collecting ring and sound: build unit run-play of the incremental-loop design.

For agentic workers REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps are checklist items; progress is kept in the workspace ledger, not in the plan.

Overview

Goal
Everything the player sees, hears and does inside a run: planDrops, a pure run model with the ring, a 2D canvas drawing, RunLayer.svelte, four Web Audio sounds and two stored preferences, all under src/lib/game/run/.
Architecture
A DOM-free state machine (run-model.ts) is stepped once per frame with every varying input as an argument; draw.ts paints it on a 2D context; RunLayer.svelte owns the canvas, the window listeners, the frame loop and the live region, and takes its clock from clock.ts, which component specs mock. Sound and preferences are standalone modules with injected dependencies.
Tech Stack
TypeScript, Svelte 5 runes, Canvas 2D, Web Audio, Vitest (server, client and client-perf projects), vitest-browser-svelte, axe-core.
Spec
docs/superpowers/specs/2026-11-24-run-play-design.html (sections sec-d-modules through sec-tests); design docs/superpowers/design/2026-11-24-2120-incremental-loop.html; build graph row run-play in docs/superpowers/design/2026-11-24-2120-incremental-loop-build-graph.md. Read from the package worktree when this branch's copy is older.

Global Constraints

Every task's requirements include this section. G2, G4 and the design's constraints below are copied verbatim from the design doc; R1 is copied verbatim from the run-play spec's sec-if-r1.

  • No setTimeout or setInterval in any spec or test helper (signoff rejects timing crutches). Time moves only through the mocked ./clock or explicit now arguments; waiting on the browser uses expect.poll or expect.element.
  • After each task's last commit, npx chreode timing-check --head HEAD is clean.
  • Conventional Commits. No Claude attribution anywhere: no trailers, footers or notes.
  • 2-space indent, single quotes, no trailing commas, 100 columns.
  • npm run test:perf is not a gate. run.perf.svelte.spec.ts must exist and run; its wall-clock result is not judged on a busy machine.
  • Write only under src/lib/game/run/. Nothing here imports $lib/sim, $lib/sim-page, $lib/timeline or ../store.svelte; only draw.ts imports $lib/map/palette, and only TOKENS (spec sec-d-modules).

G4 Limits

// src/lib/game/limits.ts
import type { StopType } from '$lib/sim/levers/brushes';
import type { Policy, PolicyKind, SimPolicy4 } from '$lib/timeline/policy4';
import type { GameState } from './state';
import type { TreeNode } from './tree';

export interface Hands {
  radiusPx: number;
  lingerMs: number;
  auto: boolean;
}

export interface Limits {
  open: boolean;
  presets: ReadonlySet<string>;
  measures: ReadonlySet<string>;
  stops: ReadonlySet<StopType>;
  bands: number;
  stories: number;
  reachM: number;
  custom: boolean;
  hands: Hands;
}

export const OPEN_LIMITS: Limits;
export const BASE_HANDS: Hands;
export const START_BANDS = 1;
export const START_STORIES = 4;
export const START_REACH_M = 402;
export const FREE_MEASURES: readonly string[];

export function limitsOf(s: GameState, nodes?: readonly TreeNode[]): Limits;
export function within(kind: PolicyKind, p: Policy, l: Limits): boolean;
export function runnable(doc: SimPolicy4, l: Limits): SimPolicy4;
export function isGiven(p: Policy): boolean;
open
The open game: every control, no limit (call 9).
presets, measures
The permitting preset ids and funding preset ids that run.
bands, stories, reachM
The most bands a transit rule may have, its tallest band and its furthest band. All 0 before the first stop type is bought.
custom
Custom timing and custom route shares may be set.
FREE_MEASURES
state-off and federal-credits-off.
  • limitsOf folds the grants of every level bought. The largest stories, reach, bands, radius and linger win.
  • Once a stop type is bought, bands, stories and reachM are at least START_BANDS, START_STORIES and START_REACH_M.
  • BASE_HANDS is a radius of 48 px, a linger of 4,000 ms and no auto. Every Hands step in the catalogue is above it.
  • Once the last rung is met, stories is 80, bands 3, reachM 3219, every stop type is in, custom is true, and presets also holds observed, the preset a custom timing policy carries.
  • within does not read a policy's on.
  • A permitting policy is within the limits when its preset is in presets, and, unless custom, it has no custom edit and no custom route shares.
  • A transit rule is within the limits when its stop types are in stops, it has at most bands bands, no band is taller than stories and none is further than reachM.
  • A protection is within the limits once stops is not empty.
  • A painted area is within the limits only when open (P11).
  • A money policy is within the limits when it is given and its preset is in measures, or its preset is in FREE_MEASURES and measures is not empty. Any other money policy only when open (D4).
  • runnable keeps the policies within the limits and returns the same document when it drops none.
  • With OPEN_LIMITS, within is always true.

Unchanged: isGiven. Removed: Allowed, ALL_ALLOWED, allowedAt, unlocksAt, runs, playable, levelNeeded, simLocked, needsHigher.

export function readCollectForMe(storage: Storage | null): boolean;
export function writeCollectForMe(storage: Storage | null, on: boolean): void;

export function writeMuted(storage: Storage | null, muted: boolean): void;

completed
The marker's completed day; NaN when it has none.
worth
{ home: homes - existing }.
policy
The project carries the map's policy mark, the diamond: its CityDelta.flags are not 0. A drop takes its marker's value.
project
The point's position in CSS pixels from the map box's top left, or null when it is off the map.
ontake
The run's totals so far, sent whenever they change and once when running turns false.
  • planDrops returns one drop for each marker completed after asOf and at or before to whose worth is above 0, ascending by day, then by row.
  • feed.drops may be replaced during a run, as the forecast fills. Drops are matched by row: one already shown stays as it is, and none is counted twice.
  • A drop appears when feed.day reaches its day and is counted in dropped then.
  • A drop whose policy is true pops as a diamond, the shape of the map's policy mark, in that mark's colour (tl-halo-policy); every other drop pops as a circle in the accent. The shape tells the two apart in every theme. Its worth and how it is collected do not change.
  • A drop is collected when its projected point is within hands.radiusPx of the ring's centre. It is counted in collected once.
  • A drop not collected is gone the larger of hands.lingerMs and 400 ms of wall time after it appeared. When the run ends before that, it is gone 400 ms after the end, or at the end under reduced motion.
  • With collectForMe or hands.auto, every drop is collected as it appears.
  • The ring's centre is the last pointer position over the map. Arrow keys move it by a fixed step; holding Shift moves it further.
  • The layer is a canvas over the map with pointer-events: none. It listens on the window.
  • Nothing the layer does reaches the worker or the policy document (P9).
  • With reduced motion, drops and counts appear and disappear without movement.
  • Nothing flashes more than three times a second.
  • A screen reader is told the run's totals at its end, never each drop.
  • The layer's root carries data-dropped and data-collected, the totals in homes.
  • onPrefs calls fn after either preference is written in this page, and returns its own removal. A change applies to a run in progress.
  • The layer's words are in src/lib/game/run/words.ts.
  • createSound makes its sounds with the Web Audio API and loads no file. It makes no sound while muted() is true or before a user gesture.

Per contracts (its rule on stub imports), drops.ts does not import Hands or RunTake; RunLayer.svelte does.

The design's global constraints

  • One future: the same policy document always gives the same forecast. No game state reaches the worker except through the policy document.
  • No file the dataset version hashes is changed: pipeline, src/lib/config.ts, src/lib/{data,generator,timelapse}, src/lib/plan/{geometry,types}.ts, src/lib/sim/finance (pipeline/lib/version.ts:41). The dataset version stays as it is.
  • A policy node acts on a lever the code already has, at a value the code already sources. No node invents a value.
  • The painted area, own pools, the City funding scale and market terms are never offered in a game.
  • Published plans and policies open and play in full, as today.
  • WCAG 2.2 AA: everything works from the keyboard; targets are at least 24 px; motion follows the reduced-motion setting; nothing flashes more than three times a second.
  • Page text is short. A node is a name, a line and a price.
  • The CSP is not widened. Sound is made in the browser; no audio file, font or script is added.
  • A runtime dependency is not added without a credit in src/lib/attribution.ts. None is expected.
  • Code style: 2-space indent, single quotes, no trailing commas, 100 columns.
  • Vitest runs with expect.requireAssertions. Tests are colocated.
  • A schema change goes through npm run db:generate. Migrations are never edited by hand.
  • Signoff fails on server stderr, on timing crutches and on retried flakes. Timing is measured only on a quiet machine.
  • Port 4173 belongs to whichever session started the preview. Never kill it; wait.
  • Commits use Conventional Commits and carry no Claude attribution.
  • Work happens in git worktrees under .claude/worktrees/.

Review Focus

Inputs the spec implies but its test list does not exercise, most likely to bite first. Each has its test in the owning task.

  1. Unmount mid-run. The page leaves while a run plays: no further ontake, the pending frame is cancelled, and a later arrow key on the window is not prevented. Test in Task 9 (t9-s1).
  2. A NaN feed day while running (the forecast not filled yet): nothing appears, highDay keeps its value, and the next real day drops what is due. Test in Task 6 (t6-s1).
  3. A muted call between two plays: it does not move the last-played time, so an unmuted pop 0.08 s after the last played one still plays. Test in Task 3 (t3-s1).
  4. Arrow keys inside a widget: a key whose target sits inside role="slider" or a contenteditable element is not prevented and does not move the ring. Test in Task 9 (t9-s1).
  5. A stop on a model that never started, and a second stop: ended is false, the take is unchanged, nothing is counted. Test in Task 6 (t6-s1).
