Homes waiting for money: implementation plan

Implements the money-wait unit: a per-month count of homes waiting in the plan's funding line, recorded in the world and carried by SeriesChunk.waiting to TimelineView.waitingMoney.

For agentic workers REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps are checklist items; progress is kept in the workspace ledger, not in the plan.

Overview

Goal
Record, at the end of every funded step, the homes waiting in the funding line, and carry that count per calendar month through the chunk to the view.
Architecture
The count (waitingHomes) and the record (recordWaiting) live in funding/system.ts and run last in the shadow hook (system 7), writing two new FundLine fields (waitHomes, waitThrough). funding/columns.ts gains the reader waitingAt. The series' Extras gains waiting(world, from, through), mapping calendar months to model months with the series' own finalTable; chunkOf fills waiting from the money feed's world; viewOf joins it into waitingMoney and chunksBefore trims it. The series data layout is unchanged.
Tech stack
TypeScript, Vitest (server project), typed-array world columns.
Spec
docs/superpowers/specs/2026-11-24-money-wait-design.html (read it from the package worktree /Users/mindlace/Projects/sfhousing/.claude/worktrees/incremental-feel/.claude/worktrees/incremental-loop). Sections implemented: #sec-design-where, #sec-design-count, #sec-design-record, #sec-design-month, #sec-design-chunk, #sec-design-view, #sec-design-restore, #sec-design-cost, #sec-design-docs; tests per #sec-tests.

// src/lib/sim/world/score/types.ts
export interface SeriesChunk {
  from: number;
  rows: MonthRow[];
  planEffect: PlanRow[];
  money: MoneyRow[] | null;
  tiers: TierUnits[] | null;
  waiting?: number[] | null;
}

export interface TimelineView {
  // every field it has today, and:
  waitingMoney?: number[] | null;
}
waiting
Per calendar month of the chunk: homes in applications waiting in the plan's funding line at the end of the model month that holds the calendar month's last day.
  • Both fields stay optional. An absent field reads as null.
  • Null or absent exactly when money is null.
  • Homes are an application's gross units.
  • A row marked gone is not counted. A lot that is no longer free is not counted.
  • A lot with two applications counts once, by the larger.
  • Two calendar months that end in one model month share a value.
  • The value is of the plan's world, never the comparison's.
  • waitingMoney is null when any chunk of the view lacks waiting.
  • No file under src/lib/sim/finance changes.

Review focus

  • Funding columns made after month 1. A timeline whose money starts later gets its columns from the first hook (ensure); its first recordWaiting fills months 1..m-1 from waitHomes[0] = 0. Test: Task 1, "a record after a gap fills the gap with the last value" and "a fresh line's first record at month 5 reads 0 for months 0..4".
  • Months with no funding hook after the last record. A frame with finance null skips every hook, so world.month moves past waitThrough; waitingAt must return the last value, not throw or read 0. Test: Task 1, "waitingAt for a month after waitThrough and not after world.month gives the last recorded value".
  • Restore from a copy, then re-step. A restored world re-records each quiet step after the copy's waitThrough; the order check must not fire and values before the edit must match. Test: Task 1, "a structuredClone stepped on alike records the same values" (covers the clone path); existing host.edit.spec.ts with the updated before covers the runner path in Task 2.
  • Two calendar months ending in one model month. A February between two model month ends shares a value with January. Test: Task 2, "every entry equals waitingAt at finalTable" checks all 480 months on the funded mini, which includes such Februaries; the test asserts at least one pair finalTable[i] === finalTable[i + 1] exists so it is not vacuous.
  • A view mixing a chunk without waiting. A chunk posted by an older worker, or a fixture literal, lacks the key; with money present, waitingMoney must be null rather than shorter than filledThrough + 1. Test: Task 2, "waitingMoney is null when a chunk with money lacks waiting (absent or null)".
