Money-wait cost fix plan

Brings the funding system's shadow hook back within money-wait's cost bars by counting the homes waiting without the line index.

For agentic workers REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps are checklist items; progress is kept in the workspace ledger, not in the plan.

Overview

  • Goal: waitingHomes returns the same values at a cost of a few µs per funded world-month, so the shadow hook is at most 10 µs mean above main's and the funded world-month mean at most 10% above main's.
  • Architecture: Measured (timing logs 08-test-perf-rerun.log:144 vs main-perf-2.log:92): shadow mean 903.4 µs on the branch, 0.5 µs on main; serve stays near 10 µs on both. The only change to shadow is recordWaiting → waitingHomes, which calls lineIndex(line) (src/lib/sim/world/funding/system.ts:37). That call rebuilds the whole index (a prototypeFor call and a string key per market row, segment trees) whenever its version is stale (line-index.ts:43-51); unverified that it is stale every month, but nothing else in the month accounts for ~900 µs. The fix replaces the walk of byLot with one linear pass over the line's columns, deduplicating a lot's two applications with module-level scratch typed arrays stamped per call: no index, no sort, no allocation per lot or per month (only when the scratch grows).
  • Tech Stack: TypeScript, Vitest (server and perf projects).
  • Spec: docs/superpowers/specs/2026-11-24-money-wait-design.html §sec-design-count, §sec-design-cost, §sec-tests (read from the package worktree /Users/mindlace/Projects/sfhousing/.claude/worktrees/incremental-feel/.claude/worktrees/incremental-loop); closing §sec-design-checks (a budget held to main: the funded month is money-wait's).

Global Constraints

  • Writes: src/lib/sim/world/funding/system.ts (waitingHomes, recordWaiting), src/lib/sim/world/funding/columns.ts (waitingAt, the record's fields) only; no spec, perf spec or document is edited.
  • "On a machine where main itself is over 90 µs, this unit is held to main: the funding system's shadow hook costs at most 10 µs mean per funded world-month more than on main, and the funded world-month mean is at most 10% above main's, both measured in the same session on the same quiet machine, main and this branch run one after the other."
  • "The count reads the same values whatever makes it cheap: a walk that rebuilds the line index, sorts or allocates per lot each month is replaced by one that does not, and every test of the count, the record and the chunk passes unchanged."
  • The counting rule (§sec-design-count): a row marked gone is not counted; a lot with two applications counts once, by the larger units (a lot's count starts at 0); a row whose lot has a lot row in a state other than LOT_FREE is not counted; a row whose lot has no lot row is counted; 0 for a world without funding columns.
  • Imported names used per call are bound once at module top (system.ts:24-29). No Math function the determinism rule forbids and no ** (eslint.config.js:65-125).
  • "If a bar fails, the implementer stops and reports the numbers to the conductor; the counting rule is not changed to meet it."
  • Conventional Commits; no Claude attribution anywhere.

Review Focus

  • A lot id at or beyond the scratch arrays' length: the scratch grows (doubling) before it is indexed; a typed-array write past the end is silently dropped, which would miscount.
  • A lot with two live rows where the smaller comes first on the line: the sum must add only the difference when the larger arrives (covered by system.spec.ts "counts 30, whichever comes first").
  • A clone and its original share the module scratch: the stamp must make each call independent of the one before (covered by the clone cases in system.spec.ts).
  • The stamp's wrap: at the Int32 limit the stamp array is cleared and the stamp restarts at 1, so a stale stamp never matches.
  • The cost moves rather than vanishes: no other hook's mean (serve, apply, onProjectEvent) rises against main because the index is no longer built in shadow.
