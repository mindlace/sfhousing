# `finance-score` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Put homes by income tier (`TimelineScore.tiers`) and the public-money results (`TimelineScore.money`) into every shown run's score, with the pure helpers and source lists `funding-ui` will read.

**Architecture:** One new pure module, `src/lib/sim/scenario/finance-score.ts`, holds `tiersOf` and the tier series (built on `completedNet`'s own month rules), the per-pool ledger series, `moneyOf`, `addedBorrowing` and the page helpers. `simulateDetailed` becomes the one ledger collector; the scenario host computes tiers and money once per shown run and passes them to `assembleScore`. The net fast path (`addNet`, `simulateNet`), the twin, the band and `/lesscars` are untouched.

**Tech Stack:** TypeScript, Vitest (server, client, perf projects; `fast-check` for properties), Playwright, SvelteKit 2 worker host.

**Spec:** `docs/superpowers/specs/2026-11-09-finance-score-design.md` (binding; this plan copies its values and rules). Engine contract: `docs/dev/finance-engine.md`. Model: `docs/dev/finance-model.md`. Design: `docs/superpowers/design/2026-11-09-1911-sim-financing.md` ("Dependency order", "How a release is built", "Global constraints", Reappraisals 1 and 2).

## Global Constraints

Copied verbatim from the spec, section 3:

- **Evidence hierarchy.** Every number the simulation uses carries a `Provenance` with its tier and source, and the interface can show both. A value that cannot be sourced is `Unsourced` with a reason; what depends on it is unavailable, or runs on a value labelled "custom, not sourced" that the user typed. No tier 3 or 4 number is presented as data.
- **Money never decides alone.** A funded project needs a lot the user's zoning makes hostable and free, takes its size from the same draw, and passes through the same stage tables as every other project. Only a fully funded project is exempt from drop-out (R6).
- **Deterministic and paired.** A run is a pure function of (dataset, levers, seed). The plan and the twin share draws: no draw purpose changes from what the paired-draw fix leaves (ruling R17; F11), and a lot's draws do not depend on the order lots are processed in. That fix draws a stage step's kind and its time apart, so a change to timing alone never changes how a project leaves a stage. This package keeps that property for every stage step: nothing in it draws a kind and a time from one number, and a fully funded project's time in a stage comes from the stage's time draw (F9 (i)). Through money, a timer can still change which applications are awarded and when, because releases and repayments fall on exit and completion days (F9 (g), (h)). That is an effect of the money, not of the sampler.
- **No public money means no change.** With `finance` absent, the engine's output is identical, schedule for schedule, to its output before `finance-engine` under the same `market`. A test asserts it. The site's default is not that case: it runs the baseline funding.
- **The engine is in the dataset version.** `src/lib/sim/scenario`, `src/lib/sim/levers`, `src/lib/scoreboard`, `src/lib/timelapse` and `pipeline/` are hashed into the dataset version. The finance model shapes published data too, because the `/lesscars` build step runs the baseline funding: `src/lib/sim/finance/` (the functions and constants of F4 and F8) is added to the hashed paths in `pipeline/lib/version.ts` by `market-baseline`, the first subsystem whose pipeline code imports it. Any change in a hashed path needs a dataset build and upload before signoff ([pipeline.md](../../dev/pipeline.md), "Finishing a branch that changes the dataset"). The page's code stays outside them, in `src/lib/sim-page/`. `PATHS` in `pipeline/lib/version.ts` is the full list of hashed paths. A path added to it is also added to the dataset rule in `chreode.config.ts` (what signoff runs) and to the path filters of `.github/workflows/pipeline.yml`.
- **Goldens change only at the two releases.** The pipeline fixture goldens, the lesscars fixture goldens and `fixture-0` are regenerated by their documented commands for Release 1 (`market-baseline` with `finance-data`) and for Release 2 (`finance-engine`, when the default starts running the baseline funding), each reviewed as an engine or data change. Between the two, and outside this package, the paired-draw fix regenerates them once, together with `golden-seed1.json` and `model-golden.json` (ruling R17). The fixture build emits a fixture market model and fixture baseline funding, labelled tier 4, so the page and its e2e tests have both. `golden-seed1.json` and `model-golden.json` (the mini city and the small calibration, which have no market model and no funding) do not change in this package: Release 2 leaves them as the paired-draw fix wrote them. They are the lock on "no public money means no change".
- **Open data only.** The dataset stays ODbL and PDDL. New sources go in the lock and the attribution list.
- **Worker-safe and client-side.** The simulation stays in the worker; nothing here adds a server computation or a binding. Shared policies stay in the `plan` table's `body`: no migration.
- **Stored documents keep loading.** A schema-2 policy, saved locally or published, opens with default funding. It is never treated as corrupt.
- **Constant dollars.** Every dollar figure is in the dataset year's dollars except bond repayment, which is nominal and labelled.
- **House rules.** Svelte 5 runes, Tailwind 4, colocated Vitest with `expect.requireAssertions`, Playwright e2e, WCAG 2.2 AA, compact results with detail on demand, status apart from controls, Conventional Commits, work in worktrees, signoff as the only merge gate.

Engine facts that bind this plan (verified in `docs/dev/finance-engine.md`, "Order within a day" and "The ledger identities"):

1. Within a day, a guarantee that exits after construction began emits `release H` **before** `loss X` (the conductor's ruling, 2026-11-11). E4/I4 holds after every event, so I4 holds at every month's end with no carve-out. `ledger-model.ts` follows this order.
2. **Open with the partner (M1):** a partly covered application keeps its month's first-day bundle, so for up to about a month it can commit from a pool switched off, or a programme ended, mid-month. Nothing here may assume that a commit never comes from a pool inside an `off` span. Checked: none of I1–I6 depends on it (I4 is availability, which `off` does not change; I6 concerns uncapped pools only). If any test or identity turns out to fail on such a commit, stop and escalate (Review Focus item 1); do not design around it.

## Review Focus

Inputs the spec implies and no numbered spec test exercises, most likely to bite first. Each has a test in the task named.

1. **A commit from a pool inside its `off` span (M1).** The series and I1–I6 hold; nothing rejects or reclassifies it. Pinned in Task 4 (hand ledger "commit while off" and an off span in `ledger-model.ts`). If an identity fails on it: escalation point to the operator, not a code change.
2. **A guarantee exiting after construction on a pool whose whole balance is held.** `release H` then `loss X` on one day keeps I4 at month end, and `lostCredit` takes X once. Pinned in Task 4 ("guarantee lost on a fully held pool").
3. **A paying programme with zero project dollars and no ledger event** (`finance-engine.md`, "The schedule and the card": a typed share below about a dollar over the homes). `tiersOf` still weights it by its exact grant-equivalent; the split still sums to the units; `moneyOf` is unaffected. Pinned in Task 2 ("a near-zero paying programme").
4. **Phase allocation when not every phase is in the run** (a phase dropped or still open at the horizon). Allocation is over all of the master's `phases[j].units`, so a phase's count does not depend on which other phases complete. Pinned in Task 2 ("allocation ignores which phases run").
5. **`aboveModerate` negative in a month** (existing homes demolished at a construction start before any completion, or a project that exits after construction). The series and the above-moderate fraction go negative uncapped, as `completedNet` does. Pinned in Task 3 ("negative above moderate").

Rules the code implements (spec 4.1, copied, not re-decided):

- `splitByShares`: each field `floor(n × s_f + 1e-9)`; the leftover homes go one each to the largest remainders `n × s_f − floor(…)`, remainders within `1e-9` tie, ties to the earlier field in `TIER_FIELDS` order. Sums exactly to `n`.
- `allocatePhases`: `total × u_j ÷ Σu` floored, leftover by largest remainder, ties to the lower index (same tolerance). Builder's call: share the largest-remainder core with `splitByShares` (one private function), because the two rules are the same rule.
- `tierContext`: `affordable` from `input.projects`: a row with `phases` maps `'<id>:phase:<j+1>'` (`engine.ts:195`, 1-based) to `allocatePhases(a, phases.map(p => p.units))[j]`; any other row (an unenriched multi-phase row included, simulated as one schedule with `projectId` the row id, `engine.ts:690`) maps its id to `a`; `a = affordableHomes ?? 0`; rows with `a = 0` may be omitted. `programmes` from `input.finance.programmes` with `poolKind` the kind of the pool whose `id` is `programme.pool`. `terms` = `input.finance?.terms ?? null`. `weights` empty.
- `tiersOf`, final units `u = revisions.at(-1).units`, in this case order: (1) `sc.kind === 'affordable'`: spec 4.1 case 1 steps 1–6 exactly (no `funding` or empty `programmes` → all `unrecorded`; unknown id throws `Error('tiersOf: unknown programme <id>')`; one programme → its `tiers`, no `fundBundle` call; several → `fundBundle(items, 'affordable', prototypeFor(r0.stories ?? 0, r0.units), ctx.terms)`, `w_k = items[k].grantEquivalent ÷ grantEquivalent`, equal weights when `grantEquivalent` is 0; shares `s_t = Σ w_k tiers_k[t]`, `s_unrecorded = Σ w_k` over null `tiers`; memo key the sorted ids joined by `,`); (2) `origin === 'simulated'`: `inclusionaryUnits(u)` plus `aboveModerate = u − Σ`; (3) `origin === 'pipeline'`: `unrecorded = min(ctx.affordable.get(projectId) ?? 0, u)`, rest `aboveModerate`.
