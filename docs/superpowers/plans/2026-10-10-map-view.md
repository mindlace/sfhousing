# map-view Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the MapLibre GL + deck.gl map (`SimMap.svelte`) that renders the SF basemap, existing-building extrusions, hidden/replaced parcels and generated buildings with rise-in, and that exposes `SimMapHandle` (I17) plus the pure `packCell` that the worker host (brush-tool, next wave) imports.

**Architecture:** Pure TS modules under `src/lib/map/` hold every decision that can be tested without a GPU: the packer, the palette, the style builder, camera maths, the hide mirror and tooltip copy. A `GeneratedController` class owns deck layer state, revision ordering, the rise-in animation and hide batching. It gets its overlay and map through injected deps, so client tests can drive it with fakes or a real map. `SimMap.svelte` is the thin Svelte 5 shell. It SSRs a static frame, lazy-imports maplibre/pmtiles in `onMount` and deck after the first `load`, and implements `SimMapHandle` as exported functions (`bind:this`).

**Tech Stack:** SvelteKit 2, Svelte 5 runes, TypeScript, maplibre-gl ^6.13, pmtiles ^4.5, @deck.gl/{core,layers,maplibre} ~9.4, @protomaps/basemaps ^5.7, Vitest (server + browser projects), Playwright.

**Spec:** `docs/superpowers/specs/2026-10-10-map-view-design.md` (design: `docs/superpowers/design/2026-10-10-1749-sf-housing-sim.md`). Every task's implementer reads the spec sections named in its task.

## Global Constraints

Verbatim from spec §3:

- **Free and open source.** No paid APIs and no vendor keys are needed to run or build it. Licence: MIT for code (OD-3). Data attribution is shown in-app (ODbL for the OSM/Protomaps basemap and Overture, PDDL/public domain for DataSF).
- **Determinism.** The same `Plan` + `datasetVersion` gives the same buildings and the same score, on every machine.
- **Overshoot is meaningful.** No readout caps at 100% of a target.
- **Honesty of numbers.** Every unit count is labelled with what it is (M1: *theoretical max buildout*). Net counts are shown, not gross. Sources and vintages are visible.
- **Performance targets.** Existing-city view pans at 60 fps on a 2022-era laptop. Generated buildings appear within 150 ms of pointer-up for strokes covering ≤ 500 parcels. A whole-city repaint (≈150k parcels) finishes within 5 s, off the main thread. The first meaningful paint transfers ≤ 5 MB (parcel chunks load lazily under the brush).
- **Mobile works.** Touch painting uses an explicit mode switch. Layout works at 375 px.
- **Data is static and versioned.** The worker does no geo computation at runtime.
- **Cross-project conventions apply:** Conventional Commits, worktrees for all work, bare-name Cloudflare resources (`sfhousing`), and the migration workflow via Drizzle.

Project and assignment constraints:

## Review Focus

1. **A building feature with no `parcelId`** (remainder pieces) gets hovered or tapped. It must show "Existing building / Not matched to a parcel", must never be hidden, and must not throw. Pinned in Task 3 (tooltip row) and Task 6 (pick path test with a feature lacking `parcelId`).
2. **An update arrives while a large diff is still slicing, or a cell is touched mid-rise.** Order must be preserved: a building is never hidden before its replacement exists, and the mid-rise cell finalises first. Pinned in Task 5 (queue tests).
3. **A revision-0 snapshot arrives mid-animation or mid-slice.** It must cancel pending rises and slices, clear all feature-state and replace all cells, with no animation. Pinned in Task 5 (C6 extended).
4. **A plex shows 1 or 2 units** (house or duplex) and **plural/singular unit copy** ("1 unit" vs "3 units"). Pinned in Task 3.
5. **Component destroyed before the dynamic imports resolve, or before `load`.** There must be no map leak, no `overlay.finalize()` on undefined and no errors. Pinned in Task 4 (unmount-during-load test).

  const c = [1, 3, 5].map((i) => parseInt(hex.slice(i, i + 2), 16) / 255)

Packing rules (spec §2, §4.6):
- Sort items by `building.parcelId` (code-unit compare) so the output does not depend on input order. If a `parcelId` is duplicated, throw.
- Parcel slot `s` = sorted index. `parcelMeta[4s..4s+3] = [units, existingUnits, stories, TYPOLOGY_ORDER.indexOf(typology)]`.
- Parts in building order. For each part ring: drop the closing vertex if it equals the first; if the signed area (shoelace in lng/lat, x = lng, y = lat) is > 0 (CCW), reverse it to make it CW. `startIndices[k]` = vertex offset; the last entry is the total vertex count.
- `positions` Float64Array `[lng,lat]*`; `partTopM` Float32Array; `partSlot` Uint32Array; `partTypology` Uint8Array.
- A building whose `parts` is empty contributes a slot and no parts.

  ```ts
  // hide.ts
  export function applyHideDiff(mirror: Set<ParcelId>, d: { add: readonly ParcelId[]; remove: readonly ParcelId[] }): void; // removes first, then adds
  export interface Slice { cells: GeneratedUpdate['cells']; add: ParcelId[]; remove: ParcelId[] }
  export const SLICE_IDS = 2000;
  export function planSlices(u: GeneratedUpdate): Slice[];
  // camera.ts
  export const CENTER: [number, number] = [-122.4194, 37.7749];
  export const CONSTRAINTS = { minZoom: 11, maxZoom: 18, maxPitch: 70, maxBounds: [[-122.56, 37.69], [-122.33, 37.84]] as [[number, number], [number, number]] };
  export const NARROW_PX = 640;
  export function defaultFrame(widthPx: number): CameraFrame;
  export type InitialCamera = { kind: 'jump'; frame: CameraFrame } | { kind: 'fit'; bounds: [[number, number], [number, number]]; options: { padding: number; pitch: number; bearing: number; maxZoom: 16; animate: false } };
  export function initialCamera(widthPx: number, initialFrame: CameraFrame | 'plan-bbox' | undefined, planBBox: BBox | undefined, bottomInset: number): InitialCamera;
  export function pixelRatio(dpr: number): number; // min(dpr, 2)
  // tooltip.ts
  export function typologyLabel(t: TypologyId, units: number): string;
  export type TooltipHit =
    | { kind: 'generated'; parcelId: ParcelId; typology: TypologyId; stories: number; units: number; existingUnits: number }
    | { kind: 'existing'; parcelId: ParcelId | null; chunk: ChunkStatus | 'unknown'; summary: ParcelSummaryLike | null };
  export function tooltipLines(hit: TooltipHit): [string, string];
  ```

Rules:
- `planSlices`: if `add.length + remove.length ≤ SLICE_IDS`, return one slice holding everything. Otherwise, slice 0 holds all `remove` ids plus any `add` id not found in any cell's packs. Then walk `u.cells` in order. Each cell's add ids are the `add` ids present in its `settled.parcelIds ∪ rising.parcelIds`. Accumulate cells (with their adds) into the current slice until its add count reaches ≥ `SLICE_IDS`, then start a new slice. A cell is never split. Every cell and every id appears in exactly one slice, in original cell order.
- `defaultFrame`: ≥ 640 gives `{center: CENTER, zoom: 13, pitch: 55, bearing: -20}`; < 640 gives `{zoom: 12.2, pitch: 45, bearing: -20}`.
- `initialCamera`: `'plan-bbox'` with a `planBBox` gives `fit` with `padding: 48 + bottomInset`, the default pitch/bearing for that width, `maxZoom: 16`. `'plan-bbox'` without a bbox, or `undefined`, gives `jump` to the default. A `CameraFrame` gives `jump` to it.
- `tooltipLines` rows (spec §4.7, exact). `Intl.NumberFormat('en-US')` for every number. `unit`/`units` by count. Line 1 is `Parcel ${id}`, or `Existing building` when `parcelId === null`.
  - generated, non-ADU: `${label} · ${stories} stories · ${units} units · replaces ${existing} (net +${units-existing})`. Use "1 story" for a single story.
  - generated ADU: `ADU · adds ${units} unit(s) to ${existing} existing (net +${units})`.
  - existing, `summary` non-null, eligible: `Existing building · ${n} units`.
  - existing, `summary` non-null, ineligible: `Existing building · ${n} units · not eligible for change`.
  - existing, `summary` null, chunk `error`: `Existing building · units unavailable`. Chunk `ready`/`loading`/`unknown`: `Existing building · units loading…` (U+2026).
  - existing, `parcelId` null: `['Existing building', 'Not matched to a parcel']`.

Behaviour (spec §4.5, §4.6):
- **Ordering.** Track `lastRevision` (initially −1). `revision === 0` is a snapshot. Anything else must equal `last + 1`. Otherwise discard the update and call `deps.onResyncNeeded()`. If the first message is not 0, that's a gap too.
- **Snapshot (0).** Cancel all pending rises and slices. Clear cells, the mirror and `clearAllReplaced()`. Install every `settled` concatenated with `rising` as settled (no animation). Then apply `hide.add` (sliced by `planSlices` if large; the first slice runs synchronously).
- **Incremental.** First, finalise (scale 1 + merge, synchronously) any rising cell touched by this update's `cells` or `removedCells`. Then `planSlices(u)`. Slice 0 applies synchronously in `apply()`. Later slices go on a FIFO queue drained one per `raf`. A later update's slices are appended after earlier pending ones, never jumping ahead. Applying a slice:
  - `removedCells` (slice 0 only) delete the cell and its layers;
  - `remove` ids get `clearReplaced` and the mirror update;
  - each cell gets `settled` → `generated-<cellId>`; if `rising` has parts and `!reducedMotion()`, it gets `rising-<rev>-<cellId>` with `elevationScale` 0 and an animation start time; otherwise rising is merged straight into settled;
  - `add` ids get `setReplaced` and the mirror update;
  - then one `setLayers(...)`.
- **Animation.** One rAF loop is active while anything rises. Per frame, `scale = easeOutCubic(min(1, (now - start) / RISE_MS))`, and only rising layers get rebuilt (new instance, same `data` object, so no re-tessellation). Finished cells go on a merge queue: one cell per frame, `concatPacks(settled, rising)`, the rising layer removed.

- **Layer order** passed to `setLayers`: settled `generated-*` sorted by cellId, then `rising-*` by start order, then the overlay layers.
