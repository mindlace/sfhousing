Remove the scenario engine implementation plan

Deletes the old Monte Carlo engine, its worker mode and every test that compared the step engine with it, and moves what the step engine still calls into src/lib/sim/world/, without changing a single simulated number.

For agentic workers REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps are checklist items; progress is kept in the workspace ledger, not in the plan.

Overview

Goal
src/lib/sim/scenario/ and src/lib/sim/scenario-client.ts no longer exist, no test compares the step engine with the old engine, and the live remainder sits under src/lib/sim/world/.
Architecture
Four cuts, each ending green: the parity tests outside scenario/; the worker side (the 'scenario' router mode, the scenario host and client, the scenario message types); the run side (simulate.ts, engine.ts pruned to four functions, the funded pass, the old treasury and line); then one move of what is left into world/ by a scripted import rewrite. Docs and a dataset upload close the branch. The step engine's own byte-for-byte pins (world.golden.*, funding/funded.golden.*) and the fixture reach check prove nothing moved.
Tech Stack
TypeScript, SvelteKit 2, Vitest (server, client, pipeline projects), a throwaway Node codemod in the session scratchpad, git mv, perl -pi for word renames, ripgrep for the gates.
Spec
docs/superpowers/specs/2026-11-26-remove-scenario-engine-design.html

Global Constraints

  • "Anti-goal: a change in what the game shows. Every simulation number, map frame and card stays as it is today." Proof used throughout: src/lib/sim/world/world.golden.* and src/lib/sim/world/funding/funded.golden.* pass, and their JSON fixtures (world/fixtures/world-events-mini-seed1.json, world/funding/fixtures/funded-events-mini-seed1.json) show no diff against main.
  • "Non-goal: rewriting the borrowed rules in the world's own style, or changing any model behaviour." Code moves verbatim; only imports, names in the rename table and comments change.
  • "Dataset keys and the manifest's on-disk field names do not change." Also unchanged (builder's call, they name data or wire values, not the engine): $lib/data/scenario-codec and ScenarioParcels, scenario-yield, manifest.scenarios, MINI_SCENARIO_URLS, the pipeline's scenario step, the error codes 'manifest-invalid' | 'scenario-missing' | 'scenario-invalid' | 'bad-request' | 'internal' and the page phase 'no-scenario'.
  • "Specs and plans under docs/superpowers/ are history and stay as they are."
  • Hot-path world modules bind imports once through import * as xModule and a destructure (stage.ts:15-25, docs/dev/world-core.md "Cost"). Keep that pattern for every moved import in those files.
  • Vitest runs with expect.requireAssertions: every kept or new test calls expect.
  • No new dependencies. Never compound cd ... && cmd; run every command from the worktree root. Conventional Commits, no attribution trailers.
  • Port 4173 may belong to another session: never kill a process on it; e2e runs go through signoff.
  • Baselines and scratch outputs go in .superpowers/remove-scenario/ (gitignored, .gitignore:3).
