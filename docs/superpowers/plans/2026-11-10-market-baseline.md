# Today's market (`market-baseline`) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Measure today's market as a start-odds shift against the published start model, ship it in `calibration.market` with provenance and a report section, apply it in every engine input through `SimInput.market`, and say so in the results' sources.

**Architecture:** The pipeline gains the affordable-cohort flag, a per-start record in the initiation panel, and a pure `marketModel` that turns the panel, the published model and a committed enrichment file (`pipeline/enrichment/market.json`) into `MarketModel` plus a report. `calibrate` emits it after `phaseGap`; `parseCalibration` validates it. The engine adds a piecewise-constant log-odds shift to the initiation hazard, merged with the dated regimes into one segment list. `buildSimInput` applies `marketSteps(calibration.market, asOf, marketLevel(calibration))` (`'all'` in Release 1); the page states it in the Results' Sources and the sources dialog.

**Tech Stack:** TypeScript, SvelteKit 2 / Svelte 5 runes, Vitest (server, client, pipeline projects), zod (pipeline only), Playwright.

**Spec:** `docs/superpowers/specs/2026-11-09-market-baseline-design.md` (binding). Design context: `docs/superpowers/design/2026-11-09-1911-sim-financing.md` (rows F1-F4, F12; "Dependency order"; "How a release is built").

## Global Constraints

Copied verbatim from spec section 3.

- **Evidence hierarchy.** Every number the simulation uses carries a `Provenance` with its tier and source, and the interface can show both. A value that cannot be sourced is `Unsourced` with a reason; what depends on it is unavailable, or runs on a value labelled "custom, not sourced" that the user typed. No tier 3 or 4 number is presented as data.
- **Money never decides alone.** A funded project needs a lot the user's zoning makes hostable and free, takes its size from the same draw, and passes through the same stage tables as every other project. Only a fully funded project is exempt from drop-out (R6).
- **Deterministic and paired.** A run is a pure function of (dataset, levers, seed). The plan and the twin share draws: no existing draw purpose changes, and a lot's draws do not depend on the order lots are processed in.
- **No public money means no change.** With `finance` absent, the engine's output is identical, schedule for schedule, to its output before `finance-engine` under the same `market`. A test asserts it. The site's default is not that case: it runs the baseline funding.
- **The engine is in the dataset version.** `src/lib/sim/scenario`, `src/lib/sim/levers`, `src/lib/scoreboard`, `src/lib/timelapse` and `pipeline/` are hashed into the dataset version. The finance model shapes published data too, because the `/lesscars` build step runs the baseline funding: `src/lib/sim/finance/` (the functions and constants of F4 and F8) is added to the hashed paths in `pipeline/lib/version.ts` by `market-baseline`, the first subsystem whose pipeline code imports it. Any change in a hashed path needs a dataset build and upload before signoff ([pipeline.md](../../dev/pipeline.md), "Finishing a branch that changes the dataset"). The page's code stays outside them, in `src/lib/sim-page/`.
- **Goldens change only at the two releases.** The pipeline fixture goldens, the lesscars fixture goldens and `fixture-0` are regenerated by their documented commands for Release 1 (`market-baseline` with `finance-data`) and for Release 2 (`finance-engine`, when the default starts running the baseline funding), each reviewed as an engine or data change. The fixture build emits a fixture market model and fixture baseline funding, labelled tier 4, so the page and its e2e tests have both. `golden-seed1.json` and `model-golden.json` (the mini city and the small calibration, which have no market model and no funding) never change: they are the lock on "no public money means no change".
- **Open data only.** The dataset stays ODbL and PDDL. New sources go in the lock and the attribution list.
- **Worker-safe and client-side.** The simulation stays in the worker; nothing here adds a server computation or a binding. Shared policies stay in the `plan` table's `body`: no migration.
- **Stored documents keep loading.** A schema-2 policy, saved locally or published, opens with default funding. It is never treated as corrupt.
- **Constant dollars.** Every dollar figure is in the dataset year's dollars except bond repayment, which is nominal and labelled.
- **House rules.** Svelte 5 runes, Tailwind 4, colocated Vitest with `expect.requireAssertions`, Playwright e2e, WCAG 2.2 AA, compact results with detail on demand, status apart from controls, Conventional Commits, work in worktrees, signoff as the only merge gate.

## Review Focus

1. **A start with fewer than 25 homes and no recorded stories.** It must land in prototype E (spec 4.3), not be counted unbinned and not throw: `prototypeFor` (row F4) takes `stories: number` and throws on a non-finite value (`src/lib/sim/finance/prototypes.ts:95-98`). Test in Task 5.
2. **A market step on the same day as a regime day.** The two must merge into one boundary (no empty extra segment), the project's view must still be the regime's, and `skipAbove` must count months per merged segment. Test in Task 9 (6c, equal days).
3. **A large negative shift that underflows a row's hazard to 0 under `s0` while a later step is finite.** The row must stay a candidate (through the later step) and `skipAbove` must stay a safe bound. Test in Task 9.
4. **A calibration that carries `market` plus keys this page does not know** (finance-data's `affordableRoutes`, `baselineFunding`, or a future key). `parseCalibration` must accept it, and `marketLevel` must still return `'all'`. Tests in Tasks 6 and 8.
5. **A live hold-out refit that failed (`holdOut` is `{ error }`).** The build must not fail, `market` must be unchanged, the report must print the error in the hold-out's place and contain no `null`, `undefined`, `NaN` or `Infinity` (`calibrate.test.ts:223`). Tests in Tasks 4 and 7.

   * The merged segment list: `days` = regime days ∪ later market days, ascending, equal days merged;
   * for segment j (0 .. days.length) its regime view (0 = this input's parcels) and its log1mh array.
   * Without later market steps: days = regime days, view[j] = j, log1mh[j] = j === 0 ? log1mh : regimes[j − 1].log1mh.

Algorithm (spec 4.8; pinned):
```ts
// steps in force
const steps = input.market ?? [];
let s0 = 0, k0 = -1;
for (let k = 0; k < steps.length; k++) if (steps[k].from <= input.asOf) { s0 = steps[k].logOdds; k0 = k; }
const later = steps.slice(k0 + 1);            // from > asOf
// per hostable, sized, finite-feature row i:  z = initiationLogit(model, f)
//   hazard[i] = 1 / (1 + exp(-(z + s0)));  log1mh[i] = ln(1 - hazard[i])        (s0 = 0 ⇒ z + 0 = z: bit-identical)
//   stepLog1mh[m][i] = ln(1 - 1 / (1 + exp(-(z + later[m].logOdds))))          (other rows 0)
// candidate: (hostable && ((hazard > 0 && log1mh < 0) || some m: stepLog1mh[m][i] < 0)) || inRegime[i]
// segments
const rd = (input.regimes ?? []).map((g) => g.day);
const md = later.map((s) => s.from);
const days = [...new Set([...rd, ...md])].sort((a, b) => a - b);
for (let j = 0; j <= days.length; j++) {
  const start = j === 0 ? input.asOf : days[j - 1];
  const view = rd.filter((d) => d <= start).length;      // regime in force
  const step = md.filter((d) => d <= start).length;      // 0 = s0, m = later[m - 1]
  const pre = view === 0 ? this : regimes[view - 1];      // each view's own precompute (same market)
  log1mh[j] = step === 0 ? pre.log1mh : pre.stepLog1mh[step - 1];
}
```
