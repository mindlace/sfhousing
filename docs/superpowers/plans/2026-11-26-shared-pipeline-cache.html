Shared pipeline cache plan

Implements the shared pipeline cache spec: one cache per machine, a boxes that reuses earlier work, and cache import for the caches already on disk.

For agentic workers REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps are checklist items; progress is kept in the workspace ledger, not in the plan.

Overview

  • Goal: a new worktree builds without downloading again, boxes finishes in seconds when its exact code, config and inputs have run before, and the 70 GB already on disk moves into the shared cache.
  • Architecture: one resolver (pipeline/lib/cache-root.ts) gives every shared directory; writes into it go through temp-then-rename helpers (pipeline/lib/atomic.ts). The skip is a wrapper step (pipeline/steps/boxes-reuse.ts) around the unchanged boxesCommand, keyed by the artifact's own inputs.json and guarded by a lock file per key (pipeline/lib/key-lock.ts, pipeline/lib/boxes-index.ts). cache import (pipeline/steps/cache-import.ts) moves an old pipeline/.cache in and indexes its boxes artifact.
  • Tech Stack: TypeScript on Node 24 (node:fs, node:crypto, node:os), Vitest pipeline project, no new dependencies.
  • Spec: docs/superpowers/specs/2026-11-26-shared-pipeline-cache-design.html

Global Constraints

  • Cache root, in order: SFH_CACHE_DIR if set; otherwise $XDG_CACHE_HOME/sfhousing; otherwise ~/.cache/sfhousing.
  • Shared under the root: raw/, ept/, lidar-work/<hash8>/, boxes-index/. Stay in the worktree's pipeline/.cache: derived/, review/, logs, lidar-venv/ (pipeline/steps/build.ts:79, scripts/building-review.ts:370-373, pipeline/lib/lidar/python.ts:13 are not touched).
  • A file in the shared cache is written to a temp name in the same directory, then renamed into place. A file whose sha256 name is already present is not written again.
  • A reused building-boxes entry is byte-for-byte the entry a full run with the same key wrote, retrievedAt included; the lock and the dataset version come out the same either way.
  • The skip prints exactly boxes: reused <key> and exits 0. --force skips the check and runs in full.
  • Do not edit any file under BOXES_CODE_PATHS (pipeline/lib/version.ts:67-74: pipeline/lib/lidar, pipeline/steps/boxes.ts, pipeline/boxes-config.ts, pipeline/project-records/union-find.ts, pipeline/lib/road-lots.ts, pipeline/geom.ts). The boxes code hash is in the skip key: it is 472f4d15c2df today, the same as the locked artifact's, so an edit there would make every imported artifact a miss and make every build warn that the boxes are stale. New boxes-related modules live outside those paths.
  • Tests never touch ~/.cache/sfhousing: the pipeline Vitest project points SFH_CACHE_DIR at a fresh temp dir in every worker (Task 1), and every default path is resolved at call time, never at import.
  • No new dependencies. Portable Node only (linkSync, renameSync, process.kill(pid, 0)).
  • Tests are deterministic: no real sleeps, no wall-clock waits, no retries. Anything that waits takes an injected sleep. Every test calls expect.
  • Messages to the user go to stdout (console.log or the injected out) unless they explain a non-zero exit.
  • Code style: 2-space indent, single quotes, no trailing commas, 100 columns. Conventional Commits, no attribution trailers.

Review Focus

  1. A boxes run killed with Ctrl-C leaves boxes-index/<key>.lock. The next run must take the lock over when the holder's pid is dead on this host, not wait forever. Test: Task 3, t3-s1 "breaks a lock whose holder is dead".
  2. An index entry whose files were since deleted or corrupted in raw/ must fall back to a full run, never write a lock entry whose files are missing. Test: Task 3 reusableEntry cases and Task 4 "missing raw file runs in full".
  3. Two worktrees storing the same sha256 at once, or a crash mid-write, must never leave a short file under the sha name. Test: Task 1 storeBytes and restoreRaw cases (temp sibling, no rewrite of a present file, no .part name shared between processes).
  4. cache import run twice, or on a cache the shared one already holds, must be a no-op that exits 0 and clears the local copies so the notice stops. Test: Task 5 "is idempotent and silences the notice".
  5. An odd environment: SFH_CACHE_DIR empty or relative, XDG_CACHE_HOME relative, or SFH_CACHE_DIR pointing at the worktree's own pipeline/.cache. Expected: empty is unset, relative SFH_CACHE_DIR resolves against the cwd, relative XDG_CACHE_HOME is ignored (XDG spec), and no notice fires when the local dir is the shared root. Test: Task 1 cacheRoot and localCacheNotice cases.

Builder's call The key is sha256(canonicalJson(inputs) + '\n'), which is the sha256 of the inputs.json a full run writes (pipeline/steps/boxes.ts writes exactly those bytes). It carries the full code, config and input hashes that upstreamVersion abbreviates to 12 hex, it is a safe file name, and cache import reads it off an existing artifact without recomputing anything.
Builder's call The lock is taken by writing the holder JSON to a tempSibling and linkSync-ing it to <key>.lock (fails with EEXIST atomically, and a lock file is never half-written). A holder on this host whose pid is dead, or an unparsable lock file, is stale: remove it and try again. Known limit: two waiters breaking the same stale lock at the same instant can both proceed; on one machine after a crash this is rare enough to accept.

export interface CacheImportReport {
  raw: { moved: number; duplicate: number; mismatched: string[]; left: string[] };
  ept: { moved: number; duplicate: number };
  lidarWork: { moved: number; duplicate: number; partial: number };
  boxesIndex: string | null; // the key written, or null
}
export async function cacheImport(o: CacheImportOpts): Promise<{ code: number; report: CacheImportReport }>;

Rules. raw/: a regular file named by 64 hex is a duplicate when the shared raw has that name (the local copy is removed), else it is moved when its sha256 matches its name, else it is left and listed in mismatched; anything else (.part, .tmp-, subdirectories) is left and listed in left. ept/: each file (relative path kept) is moved when absent from the shared ept/, else the local copy is removed. lidar-work/: per <hash8>/<tile> directory, moved when absent, else removed; dot-named partial tile directories (.<tile>.tmp) are removed and counted in partial.
