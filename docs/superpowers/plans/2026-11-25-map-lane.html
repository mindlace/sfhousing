Map lane implementation plan

Builds city-net (row E1, the homes a project replaces in the city feed), then map-run (row M1, the map's run view), on one branch.

For agentic workers REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps are checklist items; progress is kept in the workspace ledger, not in the plan.

Overview

Goal
The city feed carries each project's replaced homes (existing) from the worker to ActivityIndex.markers(), and SimMapHandle.setRunView(on) fits the whole city flat and north up, locks the map, and puts the camera back.
Architecture
city-feed.ts reads existing from scheduleAt into a widened marker; the wire, the type, CityStore and ActivityIndex carry it per row. The run view is a pure runFrame in camera.ts plus handle state in SimMap.svelte that outlives a remount; one applyInteraction sets every MapLibre handler from the pan and run switches.
Tech Stack
TypeScript, Svelte 5 (runes), MapLibre GL 6.13, deck.gl (MapLibreOverlay), Vitest (projects server and client, the latter real Chromium through Playwright).
Spec
docs/superpowers/specs/2026-11-24-city-net-design.html (tasks 1 and 2) and docs/superpowers/specs/2026-11-24-map-run-design.html (tasks 3 to 5), read from the package worktree .claude/worktrees/incremental-feel/.claude/worktrees/incremental-loop/. Context: docs/superpowers/design/2026-11-24-2120-incremental-loop.html and docs/superpowers/specs/2026-11-24-contracts-design.html (the optional stubs this plan makes required).
Precondition The contracts unit must be merged into this branch first: CityDelta.existing?: Uint16Array, SimMapHandle.setRunView?(on: boolean): void, and SimMap's empty export function setRunView(_on: boolean): void {} as the last entry of handle (contracts spec, sec-design-map). They are not on this branch at a458b998 (src/lib/map/types.ts:70-83, :118-146). Line numbers below for SimMap.svelte are pre-contracts; past :452 they shift by about four lines.

// src/lib/map/types.ts
export interface CityDelta {
  rows: number;
  from?: number;
  row: Int32Array;
  lngLat: Float32Array;
  days: Float32Array;
  homes: Uint16Array;
  existing: Uint16Array;
  flags: Uint8Array;
}
existing
Per changed row: the homes the project takes off the goal's count, capped at 65,535. That is the homes on its lot once it has entered construction after the dataset date, and 0 otherwise.
  • homes - existing of a completed row is that row's effect on the series' completedNet.
  • A row whose marker has not begun carries 0, as homes does.
  • A marker that differs only in existing is a changed marker and is sent.
  • validateCityDelta checks the new array's length.
  • The map's store and the page's index keep it per row.

Unchanged: every other field and rule of the feed.

// src/lib/map/types.ts
export interface SimMapHandle {
  // every method it has today, and:
  setRunView(on: boolean): void;
}
  • true: the map remembers its camera, jumps to the whole city, flat and north up, and locks.
  • Locked: no drag, wheel, pinch, double click, key or control moves the camera, and the canvas container has touch-action: none.
  • Locked: hover picks, taps and clicks are not made or delivered, and no tooltip or card shows.
  • Locked: the map's bounds and zoom floor are lifted so the city fits a small box. They return at unlock.
  • Locked: a resize or a change of the bottom inset fits again.
  • false: the map unlocks and jumps back to the remembered camera.
  • The jump is not animated.
  • A call with the value already in force does nothing.
  • The state survives a remount of the map, as the pan state does.
  • The fit keeps the city inside the map box less the bottom inset.

The design's global constraints (verbatim)

  • One future: the same policy document always gives the same forecast. No game state reaches the worker except through the policy document.
  • No file the dataset version hashes is changed: pipeline, src/lib/config.ts, src/lib/{data,generator,timelapse}, src/lib/plan/{geometry,types}.ts, src/lib/sim/finance (pipeline/lib/version.ts:41). The dataset version stays as it is.
  • A policy node acts on a lever the code already has, at a value the code already sources. No node invents a value.
  • The painted area, own pools, the City funding scale and market terms are never offered in a game.
  • Published plans and policies open and play in full, as today.
  • WCAG 2.2 AA: everything works from the keyboard; targets are at least 24 px; motion follows the reduced-motion setting; nothing flashes more than three times a second.
  • Page text is short. A node is a name, a line and a price.
  • The CSP is not widened. Sound is made in the browser; no audio file, font or script is added.
  • A runtime dependency is not added without a credit in src/lib/attribution.ts. None is expected.
  • Code style: 2-space indent, single quotes, no trailing commas, 100 columns.
  • Vitest runs with expect.requireAssertions. Tests are colocated.
  • A schema change goes through npm run db:generate. Migrations are never edited by hand.
  • Signoff fails on server stderr, on timing crutches and on retried flakes. Timing is measured only on a quiet machine.
  • Port 4173 belongs to whichever session started the preview. Never kill it; wait.
  • Commits use Conventional Commits and carry no Claude attribution.
  • Work happens in git worktrees under .claude/worktrees/.

Review Focus

Five inputs the specs imply but no spec test exercises, most likely first. Each has its test in the owning task.

  1. Lock, unlock, move, lock again. The second lock must take a fresh remembered camera (unlock cleared it); unlock then returns to the camera before the second lock, not the first. Test in Task 4 (t4-s1).
  2. Resize while locked, then unlock. The spec says the remembered centre and zoom are kept (no camera computed from the old box), but lists no test. Unlock on the grown box lands on the remembered camera. Test in Task 5 (t5-s1).
  3. Calls before the map exists that cancel out. setRunView(true) then setRunView(false) before the first map: the map starts unlocked at its initial camera, no class, no data-run-view, deck pickable. Test in Task 5.
  4. A locked SimMap unmounted, a new one mounted. No error, and the new component starts unlocked with all handlers on (spec: "A new SimMap component starts unlocked"). Test in Task 5.
  5. The index after a delta with a smaller rows. markers() must drop rows at or past the new rows even with no from. Test in Task 2 (t2-s1).
