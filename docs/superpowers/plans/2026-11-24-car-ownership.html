Car ownership implementation plan

Builds a synthetic SF household population with cars, a car-ownership choice changed at moves, a car system in the world step, parking that shifts start odds, the results row and map layer, and a back-cast.

For agentic workers REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps are checklist items; progress is kept in the workspace ledger, not in the plan.

Overview

Goal
The sim knows how many cars SF households keep, zone by zone and household type by household type, changes them when households move and when new homes fill, sizes new buildings' parking to that demand, and lets the parking cost difference from today move start odds (only with a cited SF cost per space).
Architecture
The pipeline fetches Census sources, builds the start population per block group (PUMS reweighted to ACS margins, homes placed by existingUnits), fits a 0/1/2/3+ multinomial logit, and ships scenarios/fzp/cars.bin, scenarios/fzp/car-zones.json and a cars section in calibration.json. Pure model code lives in src/lib/sim/cars/ (relative imports only; the pipeline and the engine both use it). The engine gets a CarSystem hook beside FundingSystem: state as typed columns on the world, run between systems 3 and 4. Parking reaches start odds through a derived timeline (the closedTimeline precedent, src/lib/sim/world/funding/closing.ts:171): a zone's parking shift change is a frame change whose touched lots are that zone's, so rules 6, 7 and 20 hold unchanged. The series gains an optional cars field (version 6); /sim shows one Details row and a map layer.
Tech stack
TypeScript, SvelteKit 2 / Svelte 5 runes, MapLibre, DuckDB (pipeline), Vitest (server, client, pipeline, perf projects), Playwright.
Spec
docs/superpowers/specs/2026-11-24-car-ownership-design.html (approved; binding). Read it before your task.

Global Constraints

  • Evidence ranking for every parameter: per-record data, then official aggregates, then inferences, then literature, then invented. Every parameter records its source and tier (a Provenance, src/lib/timelapse/types.ts).
  • Cost per space: a real, cited SF source (Controller feasibility studies, Planning or SFMTA cost work, published SF project pro formas) or no link. No national rule of thumb, no invented figure. Without one the parking-to-odds link ships switched off; the car model still runs and reports spaces per home; the searches are reported.
  • One future, no random bands. Every draw is counter-based (src/lib/sim/scenario/rng.ts); one seed gives one future regardless of event order (world-core rule 20).
  • Determinism: exp/log from src/lib/timelapse/math.ts (fdlibm) on every engine and pipeline-fit path; never Math.exp, Math.log or **.
  • Census data from Census directly (public domain), never NHGIS extracts. Census sources do not join AS_OF_SOURCE_IDS. Every source records a licence in sources.lock.json.
  • Odds only: the parking saving never changes costPerHome, subsidy need, awards or re-pricing in the finance engine.
  • Current law's results do not move at month one (per-lot baseline = the model's prediction at the start of the window).
  • Stop condition: if the back-cast or level2-check shows the goal month moving by more than 3 months against cars off, stop and report to the owner; do not tune to hide it.
  • scripts/level2-check.ts must exit 0 on the built dataset before it is uploaded; the dataset is uploaded before signoff (docs/dev/pipeline.md, "Finishing a branch that changes the dataset").
  • Speed is per world (/sim steps one world per side): the car system's time per world-month and the whole-window fill (about 4 s today) are printed, never gated in signoff; chunk stays within 1 ms per month. Time only on a quiet machine; otherwise record ballpark numbers and carry on.
  • src/lib/sim/cars/ uses relative imports only (the pipeline imports it, like src/lib/sim/finance/). Every src/lib path the pipeline reaches joins PATHS in pipeline/lib/version.ts (pipeline/test/version-paths.test.ts enforces it).
  • Hot world modules bind imported names once at the top through namespace imports (docs/dev/world-core.md, Cost); keep that pattern in src/lib/sim/world/cars/.
  • Code style: 2-space indent, single quotes, no trailing commas, 100 columns. Vitest runs with expect.requireAssertions: every test calls expect.
  • Terse UI copy, details on demand. Cars are not in the header and not in the goal.
  • Conventional Commits. No Claude attribution anywhere: no Co-Authored-By trailer, no generated-with footer, no "written by" note.
  • Never cd … && cmd; issue cd on its own. Work only in the worktree /Users/mindlace/Projects/sfhousing/.claude/worktrees/fewer-cars.
  • Port 4173 (preview) is shared between sessions: never kill a server on it; wait for it.
  • chreode signoff fails on server stderr, on timing crutches (sleep, waitForTimeout, polling with fixed delays) and on retried flakes: write tests that wait on conditions and print nothing to stderr.
  • A runtime dependency that ships in the bundle gets a SOFTWARE credit in src/lib/attribution.ts; data sources are credited on /about through their lock entries.

Review Focus

  1. Homes the population cannot place or remove. A completion on a lot with no zone (lotZone -1), a score-only master with no parcels, or a construction start that removes more homes than the zone has households must not throw: unplaced homes are counted in CarColumns.unplaced, removals clamp at zero and count the shortfall. Test in Task 8 (t8-s1).
  2. Empty zones. A zone whose households reach 0 gives NaN cars per household, never a division error or 0; the map draws it as no data and the Details row ignores it. Tests in Task 8 (zoneCarsPerHousehold) and Task 12 (cars-layer.spec.ts).
  3. Restore and refill mid-window. A world cloned at any month, with its due list rebuilt by planDue, gives the same car counts, the same parking frames and the same events as one that never stopped. Test in Task 9 (t9-s1, "rebuilt plan").
  4. Funded months and parking frames. A frame change that changes only parking runs funding's policyChanged; with every shift quantised to 0 the ledger and events must equal the run without cars. Test in Task 9 (t9-s1, "funded, zero shift").
  5. Datasets without car data. Older dataset versions (saved games, published policies) and the fixture before Task 7 have no cars.bin: the series' cars is null, the Details row and the layer switch are absent, nothing logs an error. Tests in Task 11 (t11-s1) and Task 12 (t12-s1).

Open questions

Q1. Where the parking shift lives. The spec says the shift is applied per lot in startRates with the memo keys grown, and expects it to move as density and household mix move. But start odds today are a pure function of policy frames (rates.ts:22-44; world-core rule 6, nothing accumulated; rule 20, a rebuilt plan equals a carried one), and population state is not a frame. The plan keeps those rules by carrying the shift as derived frames from world state (the pool-closing precedent, funding/closing.ts:171), refreshed yearly and quantised to 0.01 spaces per home, so a change is a rule-7 replan of that zone's lots. Recommendation: accept this. The alternative, a shift fixed for the window, makes the link inert under current law until transit levers exist.
Q2. Funded and affordable starts. The funded clocks compute the market odds directly (funding/clocks.ts:180-202, z + market), not through startRates. The plan adds the shift to the funded market clock as well, so a lot's market odds agree on both paths, and leaves affordable odds unchanged. Recommendation: market only for now, since the baseline argument (post-2018 starts built to demand) is about market buildings.
Q3. "A few months". The plan stops at a move of more than 3 months in the goal month. Recommendation: 3.
