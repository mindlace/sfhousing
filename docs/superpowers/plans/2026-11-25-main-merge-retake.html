Review focus

  • A raised side-goal target that is not exactly 1.25 × current law's value rounded up to the next 1,000.
  • A side goal left out while another tuning would have met it above its floor, or a ring left with no offered goal (must stop instead).
  • A price edit that breaks a rule: whole above 0, rising within a node, cheapest level shown at rung 0 at or under RUNG_LUMP.
  • A bench line taken while the 1-minute load was 2 or more and not labelled ballpark.
  • A docs result row still naming 2026-11-14-09ca30c8 as the current result of record (dated history rows elsewhere may stay).

Task 2: Tuning on V until tree-balance exits 0

Delivers row T1.

  • Modify: src/lib/game/catalogue/tuning.ts (RUNG_LUMP, SIDE_TUNING, PRICES only)
  • Modify: src/lib/game/catalogue/tuning.spec.ts only if a side goal is left out (held to tree-catalogue §sec-tests-tuning)
  • Modify: docs/dev/game.md § Tuning (a dated result paragraph)
  • Consumes: Task 1's LADDER_YEARS.
  • Produces: tuning.ts under which npx tsx scripts/tree-balance.ts --version 2026-11-25-76c90397 exits 0.
  1. Run the balance on V and save the report (text and --json) in the SDD dir. 
    npx tsx scripts/tree-balance.ts --version 2026-11-25-76c90397
    If it exits 0 with today's tuning.ts, skip to step 4.
  2. Edit tuning.ts by hand, by these rules only (tree-catalogue §sec-design-balance-side and §sec-design-balance-prices):
    • A goal flagged at-or-below-current-law: set its target to the report's raiseTo (1.25 × current law's value, rounded up to the next 1,000).
    • A goal never-met in every gated hand play with its target at or above its floor, under any tuning tried: remove its entry from SIDE_TUNING, then tune every remaining goal again. Never empty a ring (each ring from 0 to the last keeps one offered goal); if the rule would, stop and report.
    • A failing pacing check or a stuck/too-long play: change prices, RUNG_LUMP or side rewards. Prices are whole above 0 and rise within a node; the cheapest level shown at rung 0 stays at or under RUNG_LUMP.
    • Never change a rule, SHARE, CLOCK, TARGETS, a node or the script.
  3. Rerun step 1's command; repeat step 2 until exit 0. If no set of numbers passes, stop and report BLOCKED with the last report and the checks that fail (the hand-back to the owner).
  4. If a goal was left out, hold tuning.spec.ts to §sec-tests-tuning (its ids test lists exactly the ids with an entry, in order; each ring keeps one). Then run: 
    npx vitest run src/lib/game
    Expected: all pass.
  5. In docs/dev/game.md § Tuning, add a short dated result: 2026-11-25, dataset V, cars on, exit 0, each gated play's runs/purchases/clock, each goal left out with the highest value a gated hand play reached, its floor and the deadline read at. Replace any result for 2026-11-14-09ca30c8.
  6. Commit. 
    git add src/lib/game/catalogue/tuning.ts src/lib/game/catalogue/tuning.spec.ts docs/dev/game.md
