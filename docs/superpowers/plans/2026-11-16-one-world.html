One world on /sim plan

Run the policy once and the comparison once, on seed 1, and show that one future: one line on the chart, whole-number totals, and the policy's effect as the plan world minus its twin.

For agentic workers REQUIRED SUB-SKILL: use superpowers:subagent-driven-development to implement this plan task by task. Steps are checklist items; progress is kept in the workspace ledger, not in the plan.

Overview

Goal
/sim runs two worlds on seed 1, the user's policy and the comparison twin, and every number on the page comes from them. The chart shows one homes-completed line plus the state target, with no band, no Average and no "This city". "Because of this policy" is plan rows minus twin rows.
Architecture
Bottom-up would break the build between tasks: the page reads the fields the score removes. So the page goes first. Task 1 stops the page reading the band and the mean; it reads world 1's shown, which already exists. Task 2 collapses the score to one pair: chunkOf(plan, twin), with rows and planEffect and no mean, sd or band. Task 3 collapses the runner: one world per ensemble, and no worlds in the protocol, host, runner or client. Task 4 brings the docs in line. The restore copies (COPY_MONTHS) stay. They serve fast edits, not alternate futures.
Tech Stack
SvelteKit 2, Svelte 5 runes, TypeScript, Vitest (server and client projects), Playwright.
Spec
docs/superpowers/specs/2026-11-16-one-world-design.html

Global Constraints

  • The plan and the comparison each run one world on seed 1. Nothing keeps a worlds: N parameter, a mean/sd path or a band "just in case" (spec anti-goal). The restore copies (COPY_MONTHS, runner/ensemble.ts:23) stay.
  • "Because of this policy" is plan.rows[i] - twin.rows[i] for entitledNew and completedNetNew. It is never smoothed, clamped or rounded, and it can be negative (spec sec-effect-variance).
  • The headline, Results totals, targets and RHNA fraction come from the world's whole-number rows. There is no rounding or apportioning step, because the rows are integers (Int32Array sums in score/series.ts).
  • Copy stays terse, with no disclaimers. RANGE_NOTE and CITY_NOTE are deleted. TWIN_NOTE becomes exactly 'The forecast is run twice, with and without it.'
  • Out of scope, do not touch: /lesscars (src/lib/sim/scenario/band.ts, BAND_RUNS, scenario-host.ts, src/lib/lesscars/** including copy.ts and ExtraChart.svelte) and src/lib/sim/world/funding/tolerance.referee.spec.ts. TimelineScore (src/lib/sim/scenario/types.ts:312-369) keeps band and planEffectBand because scenario-host fills them. /sim passes [] for both.
  • Exact values that move because the headline now reads world 1 are regenerated by running the code. Never hand-write them. A commit that regenerates values says so in its body.
  • Conventional Commits, with messages given as -m flags. No Claude attribution anywhere: no trailers, footers, or notes in code or docs.
  • Vitest runs with expect.requireAssertions, so every test calls expect.
  • Code style: 2-space indent, single quotes, no trailing commas, 100 columns.
  • Signoff (npm run signoff) is the only check. Do not git push first. chreode fails a run on server stderr, timing crutches (sleeps, waitForTimeout) and flakes that pass only on retry. Write none of these.
  • Port 4173 (preview, e2e) is shared between sessions. Never kill whatever holds it. Wait for it to be free.
  • Perf suites (npm run test:perf) run only on an idle machine and are not part of signoff. A busy machine defers them.
  • Work only in /Users/mindlace/Projects/sfhousing/.claude/worktrees/one-world. Run cd on its own, never as cd … && cmd.
