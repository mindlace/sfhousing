Overview

Goal
The map says what is happening, on screen. On /sim: a project that is approved, starts building or completes gets a ring that grows and fades as the playhead passes the day; a project allowed by the person's zoning or funded by a pool they added carries a mark for as long as it stands; a key over the map's bottom right counts the homes in each stage at the playhead's date and names every mark. On / and /p/<id>: the same key names the building types and lists each painted height with its lots, and hovering or focusing a height outlines where it applies. On every map page the layer switches sit beside the key, and "View" leaves the header.
Architecture
Two flag bits travel with each project slot from the engine (TimedPackedCell.slotFlags, set by the map stream from a new runner/flags.ts); no hashed file changes. The map draws halos and marks as one new instanced deck layer, timeline-halos (HaloLayer), built by the TimelineController once per update beside the stage bars and driven by the clock uniform the bars already read, so nothing new runs per frame. A shared map control (MapKeyControl.svelte) holds two disclosures, Layers and Key, at the map's bottom right above the attribution; /sim fills the key from a pure tally over TimelineView, Paint from a new editor-worker request (heightLots, which replaces the unused opLots). The layer rows move out of ViewMenu into LayerSwitches.

  • Zoning bit (SLOT_FLAG.zoning): a simulated row (ORIGIN_SIM) whose lot's limit, in the frame of the model month of its first entered stage, is set by one of the person's zoning policies. Honest meaning: "your zoning sets this lot's height limit". It over-counts: some of these projects would have started under current law. Pipeline and phase rows never carry it (they were filed before today). It must never be worded "because of" or "would not exist without".
  • Money bit (SLOT_FLAG.money): a funded row with at least one programme whose pool is not a baseline pool. Honest meaning: "funded by a pool you added". Exact for what it says. A money policy that scales the baseline funds through baseline pools, so those projects carry no bit.
  • Cost: no new work per world step. The bits are computed only where a cell is packed (itemsOf, the same cadence as scheduleAt), O(1) per project for the zoning bit (a frame lookup and a memoised owner read) and O(programmes) for the money bit. The first owner read of a zoning state resolves that state once (O(lots)); heights and cards already resolve the states they show, so the extra resolves are at most one per zoning state that a project started under. One byte per slot travels with each cell.
  • What the bits are not: they do not sum to "+N from your policy" (the spec's warning in sec-prop-engine). The key says "Under your policy" and never shows a count for it.

Open questions
