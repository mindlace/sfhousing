Quick repairs plan

Slice 1 of the information design review: the Keyboard shortcuts break is fixed, Fewer cars leaves the header, "FZP" reads "current law", transit shading is off by default, and the footer leaves the map pages.

For agentic workers REQUIRED SUB-SKILL: use superpowers:subagent-driven-development to implement this plan task by task. Steps are checklist items; progress is kept in the workspace ledger, not in the plan.

Overview

Goal
Five small changes that each ship on their own: (1) opening Keyboard shortcuts never changes the header's height or moves a header or dock item, and closes with Escape and a second press; (2) the header has two mode links, Paint and Simulate, and /lesscars still works by URL; (3) the main screens of /sim and /s/<id> say "current law", "Current timelines" and "Current funding" where they said FZP, the plan or the formal names; (4) transit capacity shading starts off for a viewer with no stored choice; (5) /, /sim, /lesscars, /p/* and /s/* have no footer, the header carries an About entry, and /about links the data page and the source repository.
Architecture
Task 1 replaces the <details> in HistoryButtons with a button and a native popover="auto" panel placed under the button by a small pure function, so the list lives in the top layer and takes no space in the header row or the dock. Task 2 deletes one link from SiteHeader's modeLinks. Task 3 changes copy in the src/lib/fzp, src/lib/sim-page and src/lib/timeline modules that render Results, the header delta, the fixed rows and the inspector. Task 4 flips one default in src/lib/view/prefs.ts. Task 5 renders SiteFooter only on document routes and adds the About entry to SiteHeader.
Tech Stack
SvelteKit 2, Svelte 5 runes, TypeScript, Tailwind 4, the HTML Popover API, Vitest (server and client projects, vitest-browser-svelte), Playwright, axe through expectNoA11yViolations.
Spec
docs/superpowers/specs/2026-11-17-information-design-review-design.html, slice 1 of tbl-slices, with tbl-words, sec-decisions, sec-defects, tbl-inv-chrome and sec-prop-about. Later slices (one clock, the timeline, the map, the detail column, Paint, shared parts, the About surface) are out of scope.

export interface Placement { left: number; top: number; maxHeight: number }
/** Right-aligned under the anchor, kept `margin` px inside the viewport. */
export function placePopover(
  anchor: { bottom: number; right: number },
  size: { width: number },
  viewport: { width: number; height: number },
  gap?: number,    // default 4
  margin?: number  // default 8
): Placement
// left = clamp(anchor.right - size.width, margin, viewport.width - size.width - margin),
//        and margin when the popover is wider than viewport.width - 2 * margin
// top = anchor.bottom + gap; maxHeight = max(0, viewport.height - top - margin)

Builder's call A native popover="auto" rather than the ViewMenu pattern (an absolute panel, ViewMenu.svelte:67-73). The popover sits in the top layer, so it can never take space in the header grid or be clipped by the dock's scroll box, and the browser gives Escape, light dismiss and toggling by the control for free. Placement is by script because CSS anchor positioning is not in every engine this site supports.
Builder's call The control keeps an explicit aria-expanded, synced from the popover's toggle event. SiteHeader looks for [aria-expanded="true"] inside the Menu panel before it lets Escape close the Menu (SiteHeader.svelte:75) and before a click closes it (:94), so the shortcuts behave like View inside the Menu.
Builder's call On beforetoggle to open, hide the panel (visibility: hidden); on toggle to open, measure it, apply placePopover and show it. This avoids one frame at the browser's default centred position. While open, a window resize, or a scroll (capture) whose target is outside the panel, calls hidePopover(). Coarse pointers still get no control (HistoryButtons.svelte:22-29,71).
