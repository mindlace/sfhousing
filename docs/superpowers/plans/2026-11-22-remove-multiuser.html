Remove multiuser plan

Implements the remove-multiuser spec: shared sims, invitations, roles and the per-sim Durable Object go; accounts stay, with no sims in them.

For agentic workers REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps are checklist items; progress is kept in the workspace ledger, not in the plan.

Overview

Goal
Delete the multi-user stack (sim log, browser store, sync, socket protocol, members UI, server sims, invitations, the Durable Object, operator takedown, capability ledger, authorization) and leave the identity code standing on its own, with one generated migration dropping the five tables.
Architecture
Six tasks, ordered so every deletion follows the removal of its last importer: the identity code first stops calling into sims (Task 1); the request layer and the locals it read go together (Task 2); sign-in and the e2e seams lose sims (Task 3); the remaining multi-user modules, the Durable Object and its config go (Task 4); the schema and the modules only it still imports go, and the migration is generated (Task 5); then the new 404 e2e cases and the auth doc (Task 6). The tree passes npm run check and its Vitest projects after every task.
Tech Stack
SvelteKit 2, Svelte 5, Better-Auth (anonymous, magic link, passkey plugins), Drizzle on D1, Wrangler, Vitest (server and client projects in vite.config.ts:57 and vite.config.client-test.ts:49), Playwright.
Spec
docs/superpowers/specs/2026-11-22-remove-multiuser-design.html (binding). Context: the incremental-game design, rulings R1 and D10 and interface row I1.
Ordering differs from the dispatch in four places, all forced by imports
  • app.d.ts's Locals and Error.resource are read by authz/require-cap.ts:17,60 and require-sim-role.ts:20, whose only callers are the sims and invite routes. So Task 2 deletes the five route trees, require-cap, require-sim-role and enforcement-parity.spec.ts with the locals change. enforceMutationRate's only callers are those routes, so its removal stays in Task 2.
  • reseedHandleFromSim and the simTitle parameter are used by src/lib/server/sims/start-sim.ts:13,154 and the invite page (src/routes/invite/[token]/+page.server.ts:15-16,129,133). Both go in Task 4 (after the invite page in Task 2 and start-sim in Task 4), not Task 1.
  • pending-sim.ts is imported by start-sim.ts:8; the invite template by invites/email.ts:2; the 'invite' mail kind is recorded by invites/email.ts:16. All three move from Task 3 to Task 4.
  • schema/simControlPlane.ts:2 imports $lib/sim-log, sim-log/shapes.ts:1 imports $lib/members/copy, and db/capability-events.ts:4 imports $lib/server/event-log/append. So src/lib/sim-log/, src/lib/members/ and src/lib/server/event-log/ are deleted in Task 5 with the schema files, not in Task 4.
  • e2e files are type-checked (tsconfig.json includes e2e/**/*.ts), so each e2e change lands in the task that removes what it imports: the six route-driving specs and the invite a11y case in Task 2; the account specs, email-link, auth-methods-default, pseudonymous-onboarding and the two helpers in Task 3. Task 6 keeps the new 404 cases and the full e2e run.

The spec's global constraints (verbatim)

  • Work happens in git worktrees under .claude/worktrees/. Commits follow Conventional Commits. No attribution to an AI anywhere.
  • Code style: 2-space indent, single quotes, no trailing commas, 100 columns.
  • Every Vitest test calls expect.
  • Signoff fails on server stderr, on timing crutches and on a retried flake. Each unit runs npm run lint, npm run check and the Vitest projects its files belong to before it hands back.
  • Port 4173 is shared by every session on this machine. A unit never kills a server it did not start; it waits.
  • Every agent runs every command in the foreground and never ends a turn while something it started is running.
  • Schema changes go through npm run db:generate. Nobody edits a migration.
  • No unit runs npm run signoff: its dataset step fails until the dataset is uploaded. closing runs it once, after the upload.
  • The dataset version changes in this build. The dataset is uploaded once, by closing, from the integration branch, after every unit has merged; no other unit uploads a dataset. reach-check builds one earlier to run the check and uploads nothing.
  • A unit that writes a hashed path regenerates the fixture dataset with npm run pipeline -- fixture and commits it.
  • WCAG 2.2 AA: every new control is at least 24 px and passes expectNoA11yViolations in light and dark.
  • Page text is short. No sentence says what something is not.
  • Nothing on the main screen says "RHNA". The goal is read from the Goal value, never from a constant.
  • The game's rules are read from src/lib/game/. No component compares a level to a number.
  • One future: no seed control, no band, no average over runs.
  • Published plans and policies, their ids and their pages keep working, including every policy published before this build.
  • A number that is a claim about the world carries its source and tier, in the existing Sourced, Unsourced and Evidence shapes.
  • A runtime dependency that ships in the bundle gets a credit in SOFTWARE. This build adds none.
  • CSP changes are interface changes. This build makes none.
  • Timing is measured only on a quiet machine. A unit that cannot get one defers the measurement and says so.
