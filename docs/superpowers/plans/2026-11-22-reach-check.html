Reach check implementation plan

Implements the reach check spec: scripts/level2-check.ts, its test, and one run on a dataset built from the integration branch.

For agentic workers REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps are checklist items; progress is kept in the workspace ledger, not in the plan.

Overview

Goal
A command that runs the empty policy document through the real timeline host on a built dataset and exits 1 when current law misses the goal inside the window (G4's build check, ruling D1), then one run of it on the live dataset built from the integration branch.
Architecture
One module with four exports (runEmptyDocument, readLevel2, level2Lines, level2Exit) and a main that runs only when executed directly. runEmptyDocument serves the dataset directory from disk to loadScenario and to createTimelineHost as scripts/ensemble-measure.ts:148-177 and :1279-1347 do, and resolves when a filled reaches the compiled statics' lastIndex. readLevel2 reads defaultGoal over the view with readGoal.
Tech stack
TypeScript run by npx tsx; Vitest server project; the data pipeline (npm run pipeline).

// src/lib/game/standing.ts
export type Standing =
  | { kind: 'playing' }
  | { kind: 'short'; seen: Result; bar: Bar | null }
  | { kind: 'won'; on: Day };

/** `seen` is `goalOutcome(...)` for the months reached; null while no result is seen. */
export function standing(level: Level, bar: Bar | null, seen: Result | null): Standing;
  • standing is playing at level 1 and while seen is null.
  • At level 2 a reached result is won.
  • At levels 3 to 5 a result is won when it beats the bar.
  • Every other seen result is short.
  • goalOutcome is read on the playable document's forecast and never while the numbers are stale, so a standing always belongs to the policy on screen.
  • A build check runs the empty document on a built dataset and fails when the goal is not reached inside the window (D1).
  • reach-check writes the check and runs it once finite-funding and pool-closing have merged, so a miss reaches the owner while the build is still running. closing runs it again on the dataset it uploads.

This unit consumes F2, F3 and L1 only through the merged tree (the host, the pipeline and funding.json); it calls none of their new names directly. standing itself is game-core's; this unit writes only the build check.

Review focus

  • A host that posts error after the window started filling, or never posts compiled: the promise rejects once and the host is disposed and every timer cleared, so the process exits instead of hanging. Pinned by the missing-calibration test (t1-s1) and by the command exiting on its own in Task 2.
  • A deadline month later than view.months' last entry, or absent from it: homesAtDeadline reads at view.lastIndex, never at -1. Pinned by the amount-1 margin assertion, which needs the deadline's index.
  • The goal met exactly in the deadline month: margin 0 and a "Reached" line, never "Missed". Pinned by the homesAtDeadline amount test (reached on or before the deadline, exit 0).
  • Stdout carries exactly three lines on exit 0 and 1 and nothing on exit 2; host warnings go to stderr only from main. Pinned by the level2Lines tests and checked by running the command in Task 2.
  • A file the host asks for that is not in the directory: a 404 answer (ok: false), never a thrown ENOENT escaping as an unhandled rejection. Pinned by the missing-calibration test, which must reject with host error: .

  1. Write the failing test scripts/level2-check.spec.ts. One runEmptyDocument('e2e/fixtures/data/fixture-0') in beforeAll (no warn; give the hook a timeout argument large enough for one fill, as an argument to beforeAll, not a wait). Tests and their assertions, from #sec-tests-check:
    • run covers the window: run.datasetVersion === 'fixture-0'; view.filledThrough === view.lastIndex; view.lastIndex + 1 === WINDOW_MONTHS.
    • the fixture misses the goal's own amount: r = readLevel2(run); r.amount === defaultGoal(run.asOf).amount; r.reachedOn and r.marginMonths null; level2Exit(r) === 1; line 3 starts 'Missed: ' and ends `, ${(r.amount - r.homesAtDeadline).toLocaleString('en-US')} short`.
    • reached at homesAtDeadline: readLevel2(run, h) with h = readLevel2(run).homesAtDeadline; reachedOn not null and reachedOn <= deadline; level2Exit === 0; line 3 starts 'Reached: '.
    • missed by one: amount h + 1; line 3 ends ', 1 short'; exit 1.
    • amount 1 is reached in the first month: reachedOn === view.months[0] (or the first month's day as readGoal reports it); marginMonths equals the calendar-month count from view.months[0] to deadline, computed in the test from year and month.
    • lines: level2Lines(r).length === 3; line 1 'Dataset fixture-0'; line 2 `Goal: ${r.amount.toLocaleString('en-US')} homes by ${formatShortMonthYear(r.deadline)}`.
    • no manifest: runEmptyDocument(emptyTmpDir) rejects with a message containing 'no dataset at' and the path.
    • missing calibration: copy the fixture with fs.cpSync into fs.mkdtempSync(join(os.tmpdir(), 'level2-')), delete the file scenarioUrls(manifest).calibration names, and runEmptyDocument(copy) rejects with a message starting 'host error: '; remove the copy in afterAll.
    No setTimeout, setInterval or fixed wait anywhere in the file.
  2. Run it and see it fail (module not found). 
    npx vitest --run --project server scripts/level2-check.spec.ts
  3. Implement scripts/level2-check.ts to the spec's #sec-design-check, which is authoritative for every step, message and line. Decisions the spec leaves to the plan:
    • Waiting: the host's post callback settles one promise (resolve on the filled condition, reject on error); no polling. The only timers are those the host is given (setTimeout/clearTimeout wrappers that track live handles so they can all be cleared) and one timeoutMs guard; on settle, dispose the host (as host.spec.ts does) and clear every tracked handle and the guard.
    • Rejection order for errors: a missing or unparsable manifest.json, or one parseManifest rejects, gives no dataset at {dir}; a loadScenario failure (no fzp in the result) gives host error: {code}: {message}, like a host error post.
    • The filled condition is at rev 1 and is checked against the last compiled received before it; cells posts are dropped on arrival.
    • marginMonths: (dy.year - ry.year) * 12 + (dy.month - ry.month) on the two days' calendar months, using the date helpers goal.ts already imports.
    • Number formatting: toLocaleString('en-US') (the spec's "82,069").
    • main runs only when import.meta.url is the executed file (pathToFileURL(process.argv[1]).href). Argument errors (no directory, a non-positive or non-integer --amount, an unknown flag) and every rejection give exit 2 with one stderr line level2-check: {reason}; host warnings go to console.error. Set process.exitCode; do not call process.exit while timers could be pending.
