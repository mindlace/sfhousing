# /sim UX, plan 2 of 5: the dock, the header score and the Results face — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace `/sim`'s white policy sheet with a themed dock: tabs (Transit · Paint · Permits · Protect) on its editing face, a Results face that Run and the header score flip to, a desktop rail when collapsed, a bottom sheet with a peek handle on phones, and one header score component that `/` adopts in plan 5.

**Architecture:** A generic `Dock` (`src/lib/dock/`) owns layout, tabs, the two faces and the phone sheet, driven by a small `DockState` store the page holds. `SimPage` renders the existing sections as tab panels (plans 3 and 4 replace Paint and Transit) and passes FzpMode's Results snippet as the Results face. `HeaderScore` (`src/lib/scoreboard/`) replaces `ScoreBar` and its popover: pressing it flips the dock. `FzpScorePanel` becomes `SimResults`, rearranged, with the score's start date. `PolicyPanel`, the read-only fieldset machinery and the phone sub-view go.

**Tech Stack:** SvelteKit 2, Svelte 5 runes, TypeScript, Tailwind 4, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-02-sim-ux-design.md` (Goals 1, 4, 5, 6, 9, 10, 11, 12). Builds on plan 1 (`2026-11-02-sim-ux-1-theme-and-time.md`: tokens, `NoticePills`, `onrewind`).

## Global Constraints

- SvelteKit 2, Svelte 5 runes, Tailwind 4. `md` (768 px) is the desktop/phone breakpoint.
- Header actions go through `useHeaderActions`; the save state stays in the header's status slot.
- CSP unchanged; no new runtime dependencies. Saved and shared policies open unchanged.
- Tabs: `/sim` Set Policy `Transit · Paint · Permits · Protect`; in Run the dock shows **Results** instead of the tabs. The structure has room for locked tabs; nothing is locked.
- The dock has two faces in both modes: editing (tabs) and Results. A button at the top of Results flips back, in the same place in both modes: **"Edit policy"** on `/sim` (it also ends a run), **"Paint"** on `/` (plan 5), **"Policy"** in view mode (`/s/<id>`).
- Header score: one component in `/` and `/sim`: a headline number, a progress bar toward RHNA, and on `/sim` a "vs FZP +N" delta, hidden in Set Policy, shown once a run starts. In Set Policy it shows `at.total` at today. Tapping it flips the dock to Results.
- Results states the baseline date from the score data ("8,805 homes added since Jan 2021", "of which 8,805 built by today"), never a hard-coded date.
- Results contents (today's `FzpScorePanel`, rearranged): homes added and the delta vs FZP; the chart with a playhead; RHNA progress; the pipeline breakdown; sources (collapsible). No by-neighbourhood breakdown on `/sim`.
- Less copy: remove "Each lot takes the tallest rule that covers it, never below FZP.", "Later strokes win where they overlap.", the "New zoning rules" and "Custom zoning" titles, "Read-only during a run". "Add transit rule" becomes "+ Transit layer". Anything still needing explanation goes behind an ⓘ.
- Desktop: the dock is open by default and collapses to a thin rail of tab icons; the header's "Policy" button toggles it. Phones: a bottom sheet with the same tabs and a peek handle naming the active tab or face; also reachable from the Menu. In Run the phone sheet holds Results at a peek height above the time bar.
- Every surface follows `prefers-color-scheme` with plan 1's tokens; both themes WCAG 2.2 AA.
- Vitest `expect.requireAssertions`; colocated tests; Playwright for flows. 2-space indent, single quotes, no trailing commas, 100 columns. Conventional Commits with `-m` flags. Never `cd x && cmd`. No Claude attribution.

1. **Pressing the header score during a run**, when Results already shows. Expected: Results stays, the run continues; nothing toggles back to the tabs. Test in Task 4.
2. **Collapsing the dock (Escape, the Policy button) during a run, then reopening.** Expected: it reopens on Results, still in the run; "Edit policy" is the first control. Test in Task 4.
3. **Scrubbing back to Today (plan 1's `onrewind`) while Results shows.** Expected: Set Policy, the editing face, on the tab that was active before Run. Test in Task 4.
4. **A phone in Run.** Expected: the sheet peeks Results above the time bar; the scrubber, its buttons and the footer links stay unobscured at 375 px. Test in Task 4 (e2e).
5. **Crossing md with the phone sheet open, or with the desktop dock collapsed.** Expected: the same face and tab on the other side; focus is not lost to `<body>`; no modal backdrop is left behind. Test in Task 1.

  ```ts
  // dock-state.svelte.ts
  export type DockFace = 'edit' | 'results';
  /** Phones: 'closed' shows the handle only; 'peek' about 40dvh; 'full' up to 85dvh. */
  export type SheetSize = 'closed' | 'peek' | 'full';
  export class DockState {
    face: DockFace;   // $state, 'edit' first
    tab: string;      // $state, the editing face's tab
    open: boolean;    // $state, desktop: panel (true) or rail (false)
    sheet: SheetSize; // $state, phones
    constructor(opts: { tab: string; open?: boolean });
    /** Results, shown: desktop opens the panel; a phone sheet below 'peek' goes to 'peek'. */
    showResults(): void;
    /** The editing face, at `tab` when given; a phone sheet at 'peek' goes to 'full'. */
    showEdit(tab?: string): void;
    /** The header score in Set Policy: Results ↔ editing face, opening the dock if hidden. */
    toggleResults(wide: boolean): void;
    /** The header's Policy / Paint button and Escape: desktop open ↔ rail; phone closed ↔ full. */
    toggleOpen(wide: boolean): void;
    /** The dock shows its body: desktop `open`, phones `sheet !== 'closed'`. */
    visible(wide: boolean): boolean;
  }
  // icons.ts
  export const DOCK_ICONS: Record<'transit' | 'paint' | 'permits' | 'protect' | 'results' | 'policy', readonly string[]>;
  // Dock.svelte
  export interface DockTab { id: string; label: string; icon: readonly string[] }
  interface Props {
    id: string;                 // the region's id, for the header buttons' aria-controls
    label: string;              // 'Policy' (/sim, /s/<id>) or 'Paint' (/): the region and tablist name
    state: DockState;
    tabs: readonly DockTab[];
    panel: Snippet<[string]>;   // the tab panel's body for a tab id
    top?: Snippet;              // above the tab panel, editing face only (Undo and Redo)
    results?: Snippet;          // the Results face's body
    flipLabel: string;          // 'Edit policy' | 'Paint' | 'Policy'
    onflip(): void;             // the flip button on Results
    /** The user opened it (button, handle, score): move focus in. False for the default open. */
    focusOnOpen?: boolean;
    /** Phones: the sheet's visible height above `bottom` in px (0 from md). */
    onsheetheight?: (px: number) => void;
    onclose?: () => void;       // after Escape collapsed it (the page restores focus)
  }
  ```
  Markup contract (tests and later plans rely on it): the dock root has `data-testid="dock"`, `id={id}`, `aria-label={label}` and class `sfh-dock`. From md, open: a `<section class="sfh-dock-panel …">`, `absolute top-0 left-0 w-80`, `bottom: var(--fzp-scrubber-h, 0px)`, `bg-surface dark:bg-surface-dark`, border right; the editing face shows `role="tablist"` (`aria-label={label}`), one `role="tab"` per tab (`aria-selected`, `aria-controls`, roving tabindex, Left/Right/Home/End), the `top` snippet, then `role="tabpanel"`; the Results face shows the flip button (first in the face, `data-testid="dock-flip"`) then `<div role="region" aria-label="Results" data-testid="score-details">{@render results()}</div>`; a collapse button (`aria-label="Collapse {label}"`) sits right of the tabs. Collapsed: `<nav class="sfh-dock-rail" data-testid="dock-rail" aria-label={label}>`, `w-12`, one icon button per tab plus Results, each named by its label and opening the dock there. Below md: the sheet is a non-modal `<section>` at `bottom: var(--fzp-scrubber-h, 0px)`, full width, with a handle button (`data-testid="dock-handle"`, `aria-expanded`, text the active tab's label or "Results"), and the body when not closed. The sheet joins the header overlays (`headerOverlay`): opening it closes the Menu; the Menu opening closes it to `'closed'`. Escape with focus in the dock collapses it (desktop to the rail, phone to `'closed'`), unless a modal dialog is open.
  `--dock-w`: any ancestor with class `sfh-dock-host` gets `--dock-w: 20rem` while it contains `.sfh-dock-panel` and `3rem` while it contains `.sfh-dock-rail` (from md), and its `.maplibregl-ctrl-bottom-left` moves to `left: var(--dock-w)` (the rule `PolicyPanel.svelte:263-270` had, renamed).
  Builder's call: the phone sheet is non-modal, because a modal cannot peek at 40dvh with the map and the time bar usable (the spec's Run peek).
