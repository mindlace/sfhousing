# Road-like Lots Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Lots that are road (street remnants, medians, slopes, undedicated streets, strips under ramps and beside kept freeways) stop being candidates for building in `/sim`, FZP and both /lesscars arms, by a stated rule over locked sources plus a small curated override file, measured on the live dataset and released through staging and production bump PRs.

**Architecture:** A new locked DataSF source (City Lands, `datasf-city-lands`) feeds a new SQL file, `55_road_lots.sql`, run by `runSql` between `50_clip.sql` and `60_attributes.sql`. It evaluates the public-owner, low-cover, no-homes lots against four geometric and name rules, applies the override file and the freeway-land catalog, and writes `road_lots`; `60_attributes.sql` then makes those lots ineligible exactly as it does underwater lots, and the chunk record carries a reason code in a new sparse `rl` column beside `uw`. Everything downstream (T11 `parcels.bin`, the T13 panel, the Paint editor, both /lesscars arms) sees the lot through `eligible`; the scenario step counts what the rule removed, /lesscars stops taking road-like lots as zoning neighbours, and the live build is reviewed on imagery before release.

**Tech Stack:** TypeScript, DuckDB spatial (`@duckdb/node-api` 1.5.6), Vitest (pipeline and server projects), tsx, Playwright, wrangler (R2 upload), `gh`.

**Spec:** `docs/superpowers/specs/2026-11-07-road-lots-design.md` (approved 2026-11-07). Release flow: `docs/dev/pipeline.md` ("Release run order", "Lock and datasetVersion"), `docs/dev/deploy.md` ("Promoting a datasetVersion"). Model for the release tasks: `docs/superpowers/plans/2026-11-03-lesscars-v1-1-b-content.md` Tasks 3-5.

## Decisions (builder's calls)

- **Rule id `sd.parcels.road-like`, not `road_like`.** The registry's id pattern is kebab-case (`ID_RE`, `pipeline/lib/quality.ts:64`); an underscore fails `validateRules`. Report counts keep the spec's `scenario.road_like.*` keys (counts have no pattern).
- **City Lands joins by geometry, not block-lot.** The portal's columns are `land_id, land_name, dept_id, address, city, zip, category, department_name, shape` (metadata read 2026-11-07): there is no block-lot. A lot takes the City Lands row that covers the largest share of its area, when that share is at least **0.5** (`road_city_share_min`); one name per lot, and a sliver of a neighbouring strip never names a house lot. City Lands rows that name no lot are counted (`road_like.city_lands.unmatched`) and ignored.
- **The word list (decided from the live names, 2026-11-07 recon over the 1,035 rows):** every word is matched whole (`\b…\b`, case-insensitive), because `ROADWAY` otherwise matches `BROADWAY PARCEL (STAIRS)`, `I-480 BROADWAY PARCEL` and `HEALTH CENTER 4 (AIR RIGHTS OVER BROADWAY TUNNEL)`. `PLAZA` is **dropped**: its 18 live matches include parks (Alta Plaza, Justin Herman Plaza, Fairmount Plaza), civic plazas (Mint, Hallidie, UN Plaza), `MISSION-BARTLETT PARKING PLAZA` and `MOHCD - Parcel E of Ridgetop Plaza`, a housing site. `CIRCLE` is **narrowed** to `CHAVEZ ST CIRCLE`, its only live match (spec's own example). `RIGHT OF WAY` (unhyphenated, `DPW Right of Way/Remainder`) is added. Task 7 still reviews every flagged lot whose name contains `PLAZA` or `CIRCLE`.
- **"No homes" is the land-use units** (`parcel_landuse.units = 0`, the chunk's `existingUnits`), available in the SQL stage. A road-like lot whose latest roll shows homes is counted (`scenario.road_like.with_roll_units`) and warned about; `scenarioEligible` never makes it eligible.
- **Roll class** is that of the latest roll year's row that `80_scenario.sql` would pick for the lot (largest `property_area`, then `parcel_number`, `use_code`, `property_class_code`; `80_scenario.sql:303-311`), with roll rows mapped to the lot through `src_parcel_attrs.blklot → mapblklot` (`80_scenario.sql:171-176`). Zoning is picked as `86_freeway_land.sql:30-36` picks it (active rows, `blklot = mapblklot` first). Both are computed in `55_road_lots.sql`, which runs before `80_scenario.sql`.
- **Public street centrelines for R2s** are `src_streets` rows whose `layer` is not `FREEWAYS`, `PRIVATE`, `PRIVATE_PARKING` or `PAPER_WATER` and not `PARKS%` (the investigation's set less `FREEWAYS`; live layers: `STREETS, UPROW, PAPER_FWYS, STREETS_PEDESTRI, STREETS_TI, PAPER, STREETS_YBI, STREETS_HUNTERSP, PSEUDO` remain). The band is the union of 10 m round-capped buffers, aggregated in `cnn` order as `86_freeway_land.sql` does; "at least" has the same 1e-6 tolerance.
- **R3's "within 40 m"** is measured as the investigation measured it: a `FREEWAYS` line intersects the lot, or the centreline nearest the lot's `ST_PointOnSurface` (any layer, within 300 m; ties by smaller `cnn`) is a `FREEWAYS` line and lies under 40 m from that point. Reason: the spec's precision figure is that rule's.
- **Inscribed radius:** `(ST_MaximumInscribedCircle(geom, 0.05)).radius` (DuckDB spatial 1.5.6 has it; checked 2026-11-07), computed only for lots with cover under 0.05.
- **Underwater lots are not evaluated:** they are already ineligible, and the `uw` and `rl` sets stay disjoint.
- **Reason precedence:** `override` for a `road` row, else the first that fires of `r7`, `r1n`, `r2s`, `r3` (the spec's order). The per-rule booleans are kept in `road_lot_eval` so "R3 alone" is visible to the review.
- **The spec's "test on the raw output" is a build check.** The live raw output exists only inside a build, so `roadLotProblems(db)` runs after `runSql` in every build (live and fixture) and a problem is a `BuildError`: a `keep` row naming no parcel or block, a `keep` row the raw rule does not flag (stale), a `road` row naming no parcel, a `road` row the raw rule already flags, a `road` row on a catalog parcel. Vitest covers each failure on the mini fixture.
- **Inputs as tables.** `loadRoadLotInputs(db, catalog, overrides)` writes `rl_catalog`, `rl_keep` and `rl_road` before `runSql`; `runSql` always rewrites `rl_word` from code and creates the three input tables empty if absent, so callers that pass nothing (`lesscars-freeway-land`, the SQL unit tests) still run. `miniDuck()` loads the fixture inputs, so every mini test sees the fixture's overrides.
- **Review list file.** The scenario step writes `pipeline/.cache/derived/<v>/road-lots.csv` (build-internal, never uploaded): every lot the raw rule flags, plus `road` rows, with the rule booleans, reason, kept-by reason, land name, zoning, roll class, cover, radius, street share, area, net homes removed and label point. Task 7 reviews from it.
- **The build note** is a new `docs/dev/road-lots.md` (mechanism summary pointing at `pipeline.md`, the live build, the imagery review with verdicts, the six lots beside freed sites), linked from `CLAUDE.md`'s scoped docs and from `pipeline.md`.
- **Attribution:** City Lands is PDDL (courtesy credit); its mention joins the `hasScenario` line of `src/routes/attribution/+page.svelte:70-76`, since it feeds `parcels.bin` eligibility.
