Sim object plan

Unit 2 of the sim message log: one Durable Object per sim that orders, checks, stores and streams its commits over a websocket, its own SQLite migration track, the worker entry and bindings, and the D1 copy of each sim's log.

For agentic workers REQUIRED SUB-SKILL: use superpowers:subagent-driven-development to implement this plan task by task. Steps are checklist items; progress is kept in the workspace ledger, not in the plan.

Overview

Goal
A sim that exists in sim_index can be opened at GET /api/sims/<simId>/stream as a websocket. Its Durable Object sends hello and access, answers resume with the commits after a position, accepts an append only on the tip and only from a writer, refuses with behind, invalid, not-writer, limit or gone, stores every accepted commit for good, sends it to every resumed socket, and then copies its envelope to D1.
Architecture
The logic lives in plain modules under src/lib/server/sim-object/ that Node tests run against the same SQLite bundle the object applies (better-sqlite3): SimStore (rows), decideAppend (the order of checks), LogHost (one serialized append path: decide, hash, fold-check, insert, broadcast). The class SimObject only wires sockets, attachments, the alarm and D1 to LogHost. The SvelteKit route resolves the session and the role, checks Origin, and forwards the upgrade with the identity and the right to write in a header the browser cannot set. A post-build script wraps the adapter's _worker.js so it also exports the class; wrangler bundles it, resolving $lib through its alias setting.
Tech Stack
TypeScript, Cloudflare Durable Objects (SQLite storage, websocket hibernation API, alarms, RPC), Drizzle (durable-sqlite, d1, better-sqlite3 in tests), @planafoot/drizzle-cf-migrations 1.2.1 (safeMigrate, describeAppendOnlyBundle, freshBundleSqlite), Vitest (project server), fast-check 4, Playwright against wrangler dev. No new dependency.

Invariants of the object

Every task's tests serve these. They are stated once here; the spec names in brackets say where each comes from.

  1. I1 Gapless. Stored positions are exactly 1 to n; each row's seq is its position and its commit's parent is seq - 1 (#tbl-commit, anti-goal "a log with a gap or a second order").
  2. I2 Chain. verifyChain over the stored commits, from GENESIS_HASH, is null (#tbl-commit hash).
  3. I3 State is the fold. Whenever LogHost holds a folded state, rulesetText of it equals rulesetText(fold(stored commits)) (R7, sim-log.md "Rules for callers").
  4. I4 Store, send, index. An accepted commit is inserted before any socket is sent it, and the D1 index is written after the send, never before; an index failure never refuses or delays a commit (R41).
  5. I5 A refusal changes nothing. A refused or duplicate append leaves the rows, the tip, the hash and the folded state as they were. It does take a rate token.
  6. I6 Once per id. No two rows share a commit id; an append whose id is stored is a silent no-op (#tbl-commit id).
  7. I7 One order on every socket. A socket that has sent resume receives every commit after that position exactly once, in seq order: first the resume answer, then each new commit as it is stored (R26 to R28, R40).
  8. I8 The Worker decides who writes. A socket writes only if the Worker said so at open, or a later rereadRoles() did; the browser never states who it is, and the actor stamped is the identity the Worker passed (R46, R53).
  9. I9 Append-only. Rows are never updated or deleted, except all at once by takeDown() (R21); the object's migration track is append-only (R22).

Decisions made in this plan

  1. Worker entry: wrap the adapter's output, let wrangler bundle it. scripts/worker-entry.ts runs after vite build: it moves the adapter's .svelte-kit/cloudflare/_worker.js to .svelte-kit/cloudflare-adapter/_worker.js (same depth, so its relative imports of ../output/server/ still resolve) and writes a two-line _worker.js that re-exports its default and exports SimObject from src/lib/server/sim-object/sim-object.ts. wrangler.jsonc gains "alias": { "$lib": "./src/lib" } so wrangler's esbuild resolves the object's $lib imports. Reason: the adapter writes its worker to main and deletes that path first (node_modules/@sveltejs/adapter-cloudflare/index.js:49-77), so no source file can be main; wrangler already bundles main on deploy and dev, so this needs no new dependency, unlike planafoot's explicit esbuild pass (planafoot/scripts/build/build-worker-impl.ts). Checked at plan time with wrangler deploy --dry-run on a wrapper exporting $lib/sim-log and $lib/server/sims/sim-roles: it bundled (7.3 MB) and exported both. alias is a top-level-only field (absent from RawEnvironment in node_modules/wrangler/config-schema.json), so it applies to staging too.
  2. Binding SIM, class SimObject, migration tag v1-sim-object, in both environments. Addressed by getByName(simId); inside the object ctx.id.name is the sim id (also in alarm()). Reason: Durable Object bindings and migrations are not inherited by an environment (developers.cloudflare.com/durable-objects/reference/environments/); ctx.id.name is set for getByName callers since 2026-03-15 (developers.cloudflare.com/durable-objects/api/id/#name), so nothing stores the sim id.
  3. npm run dev cannot run the object. getPlatformProxy (adapter-cloudflare's dev platform) does not run the Worker's code and needs script_name for a Durable Object (developers.cloudflare.com/workers/wrangler/api/#getplatformproxy); wrangler warns "These will not work in local development" and leaves the binding out. The route answers 503 when platform.env.SIM is missing; the socket, its e2e tests and any manual check use npm run preview (wrangler dev, which runs the class from the bundle). Reason: a second dev Worker with script_name would mean a second config and process for a path only unit 4's page will use, and that page must already work with no connection (R15 to R17).
  4. The object's SQLite schema. commits(seq integer primary key, id text not null unique, hash text not null, bytes integer not null, body text not null) and a one-row sim_state(id integer primary key, indexed_seq integer not null default 0, gone_at integer). body is JSON.stringify of the stored Commit, sent on the socket as it is. Reason: "commits in order, exactly as stored" (#tbl-frames) is then a splice, not a re-serialisation; hash and bytes are columns so the tip and the size cap need no parse; no CHECK (the package's doctrine forbids it in a DO track).
  5. Frames. Exactly #tbl-frames, as JSON text with a type field: {type:'hello', build, protocol: 1}, {type:'access', write}, {type:'commits', commits}, {type:'refused', id, why} from the server; {type:'resume', after} and {type:'append', commit} from the browser. They live in src/lib/sim-stream/protocol.ts, which has only type imports, so unit 4 and the e2e helper import it. Keepalive is the text ping, answered pong by the runtime's auto-response. Close codes: 1003 a binary frame, 1008 a malformed frame, 1011 an internal error, 4410 taken down. Reason: one module both ends read; the auto-response answers without waking the object (R23; developers.cloudflare.com/durable-objects/api/state/#setwebsocketautoresponse).
  6. Resume. The answer is one or more commits frames of at most 1 MiB each (at least one commit per frame), or one empty commits frame when there is nothing after the position. Live commits go only to sockets that have resumed. A resume past the tip, or on a taken-down sim, is answered refused {id: null, why: 'gone'}. Reason: the empty frame tells the browser it is caught up; holding broadcasts until resume gives I7 by construction; a browser holding positions the server lacks has a log the server no longer has, and gone is the only #tbl-frames reason that says so (see Open questions).
  7. The order of the append checks. gone, not-writer, rate (limit), frame size (limit), parse (invalid), duplicate id (silent), sim length and total size (limit), parent (behind), then the fold check (invalid) and the stored size (limit). Reason: cheap refusals first, so a flood costs no parse; a duplicate before behind, because a resent commit's parent is always stale and refusing it behind would make the browser re-apply it on top of itself; sim-log.md "Rules for callers" puts every non-fold check before apply.
  8. A duplicate id gets no frame. Reason: the browser sends resume before its pending commits (R17), so the resume answer already carried the stored copy, which is its confirmation (R26).
  9. Limits (LIMITS in limits.ts): a stored commit at most 1 MiB (1,048,576 bytes of UTF-8 body); an incoming append frame at most 1 MiB + 4 KiB; a sim at most 100,000 commits and 512 MiB of bodies; 120 appends in a burst and 2 a second after (per sim); send frames at most 1 MiB. Reason: a whole painted policy is up to 262 KB (#tbl-approaches), so an import (R20) fits a commit; at plan time a fold of 5,001 commits took 3 ms in Node and a checked apply 0.03 ms (ballpark, busy machine), so 100,000 commits fold well inside the 30 s CPU limit (developers.cloudflare.com/durable-objects/platform/limits/); 512 MiB is far below 10 GB; 2 a second is faster than a person paints. All are builder's calls the owner may move.
  10. Per-sim rate as an in-object token bucket, not a rate-limit binding. Reason: a binding counts per Cloudflare location and approximately (developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/#locality); one object per sim is single-threaded, so its own bucket is exact and needs no new namespace in either environment. PUBLISH_RL is not reused (R25). The bucket starts full whenever the object wakes, which only ever allows more.
  11. One append at a time. LogHost runs append, ensureStarted, resume and takeDown through one promise chain. Reason: chainHash awaits crypto.subtle, and input gates hold only across storage operations (developers.cloudflare.com/durable-objects/best-practices/rules-of-durable-objects/#understand-how-input-and-output-gates-work), so two appends on one parent could otherwise both pass the parent check.
  12. Hash, then apply in place, then insert, then send. The hash is computed first (the only await); apply(commit, {check: true}) runs on the held state (atomic: a throw leaves it as it was); the row insert and the call to the send sink follow with no await between them. If the insert throws, the held state is dropped and refolded on the next append. Reason: sim-log.md allows apply in place when every other check comes first; no await between apply and insert keeps I3; the storage write and the frames then leave together behind the output gate (developers.cloudflare.com/durable-objects/best-practices/rules-of-durable-objects/, "output gates").
  13. The fold is lazy. The object folds its rows (pages of 500) on the first append after it wakes, not on open or resume. Reason: most wakes are a reader resuming, which reads rows only.
  14. R58's first commit. When a writer opens a sim with no commits, the object appends {kind: 'system', label: 'Start', source: 'sim.start', restores: null, changes: [{op: 'set', key: 'sim', field: 'name', value: <index title>}]} with a new id, parent: 0, shapes: SHAPES_REVISION, the route's dataset version and the server's build, and the opener as actor. It goes through the same append path. A title the name check refuses leaves the log empty and is logged. Reason: R58; the opening socket gets it in its own resume answer, so it is not sent to that socket first.
  15. The index write. sim_state.indexed_seq is a watermark. After each send, the object starts one index pass if none is running: up to 50 unindexed commits go to D1 in one batch, then the watermark moves. On failure it logs once and sets an alarm 30 s ahead; alarm() runs the same pass and re-arms on failure. On wake, if the watermark is behind and no alarm is set, it sets one for now. The sim_index update only moves forward (positions below the new count). Reason: R41; alarms are at-least-once and retried (developers.cloudflare.com/durable-objects/api/alarms/), and a fresh alarm per failure avoids the six-retry limit.
  16. D1 columns. sim_index gains remixed_from (text), remixed_from_position (integer), positions (integer, not null, default 0), last_change_at (ms timestamp) and dataset_version (text). sim_commit holds sim_id, seq, kind, source, actor, at, build, dataset_version, bytes, restores_position, restores_as, primary key (sim_id, seq), indexes on actor and dataset_version, no foreign key. The object writes all but the two remixed_from columns. Reason: R24's list; restores_* beyond it because #sec-study asks for "undo and redo runs", which kind alone cannot tell from a jump; no foreign key, as sim_invite (rebuildable copies); the remix source has no field in the commit yet (see Open questions).
  17. Worker to object: one header. The route sets x-sfh-sim-open to JSON {identity, write, title, datasetVersion, build}, deleting any copy the browser sent; the object refuses an open without a valid one (400). identity is locals.user.id or null; write is false whenever identity is null. Reason: a websocket upgrade must go through fetch; planafoot's live route stamps identity the same way (planafoot/src/routes/api/quests/[questId]/live/+server.ts).
  18. Who writes. canWrite(role) is abilityDominates(ROLE_BUNDLE[role], 'sim.write') (src/lib/server/authz/ability.ts:48). Reason: R47 names sim.write; tying to the ability, not to role names, follows any later bundle change.
  19. Origin. A foreign Origin is refused 403; a missing one passes, exactly as refuseUnlessSameOriginJson treats it (src/lib/server/security/same-origin-json.ts:16-19). The comparison moves into a shared refuseForeignOrigin. Reason: #sec-constraints says "as refuseUnlessSameOriginJson does"; a browser always sends Origin on a websocket handshake, and a client without one carries no victim's cookies.
  20. A 101 passes headersHandle untouched. Reason: a 101's headers are immutable, and the re-wrap in src/hooks.server.ts:81-92 would build a new Response without the webSocket, dropping the upgrade (planafoot returns early on 101 for the same reason, planafoot/src/hooks.server.ts:211-216).
  21. rereadRoles() and takeDown() are built here. RPC methods on SimObject: the first re-reads each open socket's role from D1 (foldSimRole) and sends access where it changed; the second deletes every commit, marks the sim gone, and closes every socket with 4410. Unit 3 calls them. Reason: both act on sockets and storage only the object holds; the dispatch asks for the interface now. Their end-to-end tests wait for unit 3's callers.
  22. A commit under a newer shape revision is refused invalid. Reason: apply throws future-shapes and nothing in #tbl-frames fits better; the browser compares hello.build first and reloads when it differs (see Open questions).
  23. Logs. The object logs only what is unexpected (an index failure, an insert failure, a refused start commit, a migrate failure), with the sim id and the error message, never a commit body, an identity or a refusal. Reason: npm run signoff fails on unexpected server stderr; no account identifiers in logs.
  24. Where each behaviour is tested. The decision, the store, the host and its invariants, the index write, the route and the open header run in Vitest (Node, better-sqlite3 with the object's own bundle); the class's wiring runs in Playwright against wrangler dev. No @cloudflare/vitest-pool-workers. Reason: #sec-constraints and docs/dev/testing.md make Playwright the source of truth for Workers behaviour; the pool would be a new dependency for code that is thin by design.
  25. The e2e socket client is the page's own WebSocket. e2e/helpers/sim-socket.ts opens it in page.evaluate on /about, keeps every received frame in window.__sfhSockets, and waits with page.waitForFunction on a frame count. Reason: Playwright's request context cannot open a websocket; a page sends the session cookie and runs under the app's CSP, so the test also proves connect-src 'self' admits the socket in Chromium.

Open questions

  1. Where a remix records its source. R32 says a remix's first commit "records the sim and position it came from", and R24 and R35 put it on the index row, but CommitDraft has no field for it (src/lib/sim-log/types.ts). This plan adds the two remixed_from columns and writes neither. Recommendation: unit 3 takes the source in POST /api/sims (R51 already posts there first) and writes the columns; no envelope change.
  2. Two cases #tbl-frames has no reason for. A resume past the tip is answered gone (decision 6) and a commit from a newer shape revision invalid (decision 22). Recommendation: keep both; unit 4 treats gone on resume as "this log is not the server's" and reloads on a differing hello.build before sending anything, so invalid never drops a newer build's edit.
  3. Renames from /sims. updateSimIndexTitle writes sim_index.title directly. Once a sim has a log, the next index write sets the title back to the log's name (R42 makes the index a copy). Nothing writes commits before unit 4, so nothing regresses in this unit. Recommendation: unit 3 or 5 makes the rename a name commit through the object.
  4. CSP and other engines. connect-src 'self' is proven only in Chromium by this unit's e2e; MDN notes 'self' "does not resolve to websocket schemes in all browsers". Recommendation: unit 4, whose page opens the socket, runs one check in WebKit and Firefox and raises a CSP change with the owner only if one refuses.

Review Focus

Inputs the spec implies and no rule spells out, most likely to bite first. Each line's test is in the named task.

  1. Two appends on one parent at once. Two tabs of one writer send on the same tip within the hash's await. Exactly one is stored; the other is behind; positions stay gapless. Task 4 (two appends on one parent: one stored, one behind).
  2. The index is down. D1 fails while commits arrive. Every commit is still stored and sent; the unindexed ones reach D1 later, in order, and replaying a batch writes nothing twice and never moves the index back. Task 1 (is idempotent and never moves the index backwards) and Task 4 (tracks what the index has not seen).
  3. A browser ahead of the server. A tab resumes from a position the server does not have (local state reset, a takedown). It is told gone, not sent an empty answer it would read as "caught up". Task 4 (resume past the tip or on a gone sim is null) and Task 8 (resume answers from any position).
  4. A commit from a newer build or with an unusable title. A commit under a newer shape revision is refused invalid and stored nowhere; a legacy index title the name check refuses leaves the log empty, and the socket still opens and reads. Task 4 (refuses a commit under a newer shape revision and changes nothing, ensureStarted with a title the name check refuses leaves the log empty).
  5. The insert itself fails. Storage throws after the fold check accepted the commit. Nothing is sent, the held state is dropped, and the next append folds again from the rows, so I3 holds. Task 4 (a failed insert drops the held state).

import type { ClientFrame, ServerFrame } from '../../src/lib/sim-stream/protocol';

type Entry = { ws: WebSocket; frames: ServerFrame[]; closed: number | null };
declare global {
  interface Window {
    __sfhSockets?: Entry[];
  }
}

/** Open a socket on the sim from the page's origin; returns its handle. */
export async function openSimSocket(page: Page, simId: string): Promise<number> {
  return page.evaluate((id) => {
    const list = (window.__sfhSockets ??= []);
    const scheme = location.protocol === 'https:' ? 'wss' : 'ws';
    const ws = new WebSocket(`${scheme}://${location.host}/api/sims/${id}/stream`);
    const entry: Entry = { ws, frames: [], closed: null };
    ws.addEventListener('message', (e) => entry.frames.push(JSON.parse(String(e.data))));
    ws.addEventListener('close', (e) => {
      entry.closed = e.code;
    });
    list.push(entry);
    return list.length - 1;
  }, simId);
}

/** Wait until socket `h` has received at least `n` frames; returns all of them. */
export async function framesAtLeast(page: Page, h: number, n: number): Promise<ServerFrame[]> {
  await page.waitForFunction(
    ([i, k]) => (window.__sfhSockets?.[i]?.frames.length ?? 0) >= k,
    [h, n] as const
  );
  return page.evaluate((i) => window.__sfhSockets![i].frames, h);
}

/** Send a frame once the socket is open. `commit` may be anything, to test refusals. */
export async function sendFrame(
  page: Page,
  h: number,
  frame: ClientFrame | { type: 'append'; commit: unknown }
): Promise<void> {
  await page.waitForFunction((i) => window.__sfhSockets?.[i]?.ws.readyState === 1, h);
  await page.evaluate(([i, text]) => window.__sfhSockets![i].ws.send(text), [h, JSON.stringify(frame)] as const);
}

/** Send `frame` and return the next frame this socket receives. */
export async function sendAndRead(page: Page, h: number, frame: ClientFrame | { type: 'append'; commit: unknown }): Promise<ServerFrame> {
  const before = (await framesAtLeast(page, h, 0)).length;
  await sendFrame(page, h, frame);
  return (await framesAtLeast(page, h, before + 1))[before];
}

/** Resume after `after` and return the answer (one frame: e2e logs are small). */
export const resumeAndRead = (page: Page, h: number, after: number): Promise<ServerFrame> =>
  sendAndRead(page, h, { type: 'resume', after });

/** Wait for socket `h` to close; returns the close code. */
export async function closedCode(page: Page, h: number): Promise<number> {
  await page.waitForFunction((i) => window.__sfhSockets?.[i]?.closed !== null, h);
  return page.evaluate((i) => window.__sfhSockets![i].closed!, h);
}

  expect(frame.type).toBe('commits');
  return frame.type === 'commits' ? frame.commits : [];
}
