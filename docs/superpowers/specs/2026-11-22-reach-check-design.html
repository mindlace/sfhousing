Reach check design

The script that runs current law on a built dataset, and its first run as soon as the money rules are in.

Goal

This unit holds ruling D1 of the design doc ("There shouldn't be a case where it's unachievable") early. Current law reaches the goal with 15 to 31 months to spare, and only once pool closing is in (the margin warning), so the verdict must reach the owner while the build is still running.

  • scripts/level2-check.ts: runs the empty document through the real timeline host on a built dataset and fails when current law misses the goal inside the window (G4's build check).
  • scripts/level2-check.spec.ts: its test on the fixture, with an amount argument.
  • One run: a dataset built from the integration branch on the operator's machine once remove-lesscars, finite-funding and pool-closing have merged, the check run on it, and the month and margin handed back.
  • On a miss, "blocked: current law misses the goal", with the numbers, to the conductor and from there to the owner.

export type Standing =
  | { kind: 'playing' }
  | { kind: 'short'; seen: Result; bar: Bar | null }
  | { kind: 'won'; on: Day };

/** `seen` is `goalOutcome(...)` for the months reached; null while no result is seen. */

Design

The level 2 check

The check is G4's build check: it runs the empty document on a built dataset and fails when the goal is not reached inside the window (D1). It is invoked with npx tsx, like scripts/dataset-version.ts; it gets no npm script, so package.json is not touched.

npx tsx scripts/level2-check.ts <datasetDir> [--amount <homes>]
<datasetDir>
A built dataset directory holding manifest.json: pipeline/out/<v> in this unit's run and in closing's finish, e2e/fixtures/data/fixture-0 in the test. Required.
--amount
Replaces the goal's amount. For the test and for what-ifs; neither this unit's run nor closing passes it.

The module exports its two steps, so the test runs the host once and reads it at several amounts:

// scripts/level2-check.ts
import type { Day } from '../src/lib/timelapse/time';
import type { TimelineView } from '../src/lib/sim/world/score/types';

export interface EmptyRun {
  datasetVersion: string;
  asOf: Day;
  view: TimelineView;
}

export interface Level2Result {
  datasetVersion: string;
  amount: number;
  /** The goal's deadline: the window's last whole calendar month. */
  deadline: Day;
  /** The first month the amount is met; null when it is not met by the deadline. */
  reachedOn: Day | null;
  /** Homes counted by the goal's measure at the deadline month. */
  homesAtDeadline: number;
  /** Calendar months from reachedOn to the deadline; null when missed. */
  marginMonths: number | null;
}

/** Load the dataset from disk and fill the whole window for the empty document. */
export function runEmptyDocument(
  dir: string,
  opts?: { warn?: (msg: string) => void; timeoutMs?: number }
): Promise<EmptyRun>;

/** Read the goal over the run; `amount` defaults to the goal's own. */
export function readLevel2(run: EmptyRun, amount?: number): Level2Result;

/** The lines the command prints. */
export function level2Lines(r: Level2Result): string[];

/** 0 when reached, 1 when missed. */
export function level2Exit(r: Level2Result): 0 | 1;

runEmptyDocument, in order:

  1. Read <dir>/manifest.json with parseManifest.
  2. Serve every URL /data/<datasetVersion>/<path> the host asks for from <dir>/<path>, for fetch and fetchBytes alike, as scripts/ensemble-measure.ts:148-170 does. A file that does not exist answers ok: false, status 404.
  3. Load the scenario with loadScenario(…, scenarioUrls(manifest), …) and take input.calibration and input.asOf.
  4. Reconcile DEFAULT_POLICY4 with reconcilePolicy4(DEFAULT_POLICY4, input.calibration, input.asOf).doc.
  5. Create the host with real timers, retryDelaysMs: [] and warn from the options (default: drop the message).
  6. Send openTimeline at rev 1 with the manifest, the reconciled document, lots: {} and months: WINDOW_MONTHS.
  7. Send prefetch with the bbox that covers every chunk of the manifest, as the host spec's prefetchAll does.
  8. Wait until a filled at rev 1 has through equal to the compiled statics' lastIndex. Keep the filled chunks in arrival order; drop cells payloads.
  9. Build the view with viewOf(chunks, statics), dispose the host, clear its timers.
  • An error post from the host rejects with host error: {code}: {message}.
  • Not filled within timeoutMs (default 600,000) rejects with window not filled in {n} s.
  • A missing or unreadable manifest.json rejects with no dataset at {dir}.
  • The function never writes a file and never touches the network.

readLevel2:

  • The goal is defaultGoal(run.asOf), with amount in place of its own when given.
  • reachedOn is readGoal(goal, view, view.lastIndex).reachedOn.
  • homesAtDeadline is goal.measure.valueAt(view, d), where d is the month index of goal.deadline in view.months, capped at view.lastIndex.
  • marginMonths is the count of calendar months from reachedOn's month to the deadline's month: 0 when the goal is met in the deadline month.

The command prints to stdout, three lines, numbers with thousands separators and months as formatShortMonthYear gives them. Reached:

Dataset 2026-12-01-1a2b3c4d
Goal: 82,069 homes by Oct 2066
Reached: Nov 2064, 23 months before the window's end

Missed:

Dataset 2026-12-01-1a2b3c4d
Goal: 82,069 homes by Oct 2066
Missed: 81,308 homes by Oct 2066, 761 short

Exit codes:

0
The goal is reached inside the window.
1
The goal is missed. The three lines are printed.
2
The check could not run: a missing or bad argument, no dataset, a host error, a timeout. One line on stderr, level2-check: {reason}, and nothing on stdout.
  • The command passes host warnings to stderr; the exported functions never write to the console.
  • It runs only when executed directly, never on import.
  • Its imports are relative (../src/lib/…), as scripts/ensemble-measure.ts's are; tsx resolves the $lib imports inside them.

The one run

The operator's worktree is branched from the integration branch once remove-lesscars, finite-funding and pool-closing have merged into it. In order:

  1. Confirm the three merges are in the branch (git log --oneline shows each unit's merge).
  2. Write the script and its test. Run npm run lint, npm run check and npx vitest --run --project server scripts/level2-check.spec.ts. Commit.
  3. npm run pipeline -- doctor. It must pass.
  4. If pipeline/.cache is missing: npm run pipeline -- fetch --restore.
  5. npm run pipeline -- version; call the answer <v>.
  6. npm run pipeline -- build, without --skip-tiles. Every invariant passes.
  7. npm run pipeline -- check <v>.
  8. npx tsx scripts/level2-check.ts pipeline/out/<v>.
  9. Hand back (The verdict).
  • The build is the one closing repeats, without upload or verify. Nothing is uploaded and nothing is published.
  • The unit merges no origin/main and runs no signoff.
  • When the machine cannot build the live dataset (doctor fails, fetch --restore cannot reach the archive, the build runs out of memory or disk), the operator stops and hands back "blocked: cannot build the live dataset" with the failing command and the exact missing tool, version, credential or resource from its output. It installs nothing that needs the owner's password.
  • A build invariant that fails is reported the same way, with its id and message: it is a defect of the unit that last wrote the pipeline.

The verdict

On exit 0 the unit is done. Its hand-back carries:

  • The dataset version <v> it built.
  • The check's three lines: the month the goal is reached and the margin to the window's end.

On exit 1 the unit hands back "blocked: current law misses the goal". It changes no code, data or window length. Its hand-back carries:

  • The dataset version and the check's three lines: the homes by the window's end and the shortfall.
  • The bound of city-impact-fees and of state as the merged pipeline/enrichment/funding.json holds them: kind, date or dollars, tier and citation.
  • The conductor takes a miss to the owner. The remedy is the owner's (D1: the goal is always reachable; the window's length is the setting the owner picked).
  • The other units carry on meanwhile.
  • closing runs the same check on the dataset it builds and cannot upload while the check fails.
  • The script and its test are finished either way; the conductor merges them on a pass or on a miss, so closing has them.
  • An exit 2 is not a verdict: it is reported with its stderr line, fixed in the script when the fault is the script's, and the run repeated.

Tests

The check's own test

scripts/level2-check.spec.ts, Vitest server project, on e2e/fixtures/data/fixture-0. The fixture city cannot reach 82,069 homes, so the test uses the amount argument of readLevel2; X1's browser seam is not involved. One runEmptyDocument in beforeAll, with no warn, so the test writes nothing to stderr.

  • The run's datasetVersion is fixture-0, and view.filledThrough equals view.lastIndex, with view.lastIndex + 1 equal to WINDOW_MONTHS.
  • At the goal's own amount the fixture misses: reachedOn is null, marginMonths null, level2Exit 1, and the third line starts Missed: and ends with the shortfall amount - homesAtDeadline written with separators and short.
  • At homesAtDeadline the goal is reached on or before the deadline: level2Exit 0 and the third line starts Reached: .
  • At homesAtDeadline + 1 it is missed by exactly 1: the third line ends , 1 short.
  • At amount 1 it is reached in the first month, and marginMonths equals the month count from view.months[0] to the deadline.
  • level2Lines gives three lines; the first is Dataset fixture-0; the second is Goal: {amount} homes by {deadline month}.
  • runEmptyDocument on a directory with no manifest.json rejects with no dataset at and the path.
  • runEmptyDocument on a copy of the fixture missing its calibration file rejects with host error: (the copy is made in a temporary directory and removed after).

The verification list

  1. npm run lint, npm run check and the server Vitest project pass.
  2. npm run pipeline -- doctor, build and check <v> pass.
  3. npx tsx scripts/level2-check.ts pipeline/out/<v> has run, and its lines are in the hand-back.
  4. The branch's diff touches only the two script files.

No existing test is deleted or changed.

Global constraints

  • Work happens in git worktrees under .claude/worktrees/. Commits follow Conventional Commits. No attribution to an AI anywhere.
  • Code style: 2-space indent, single quotes, no trailing commas, 100 columns.
  • Every Vitest test calls expect.
  • Signoff fails on server stderr, on timing crutches and on a retried flake. Each unit runs npm run lint, npm run check and the Vitest projects its files belong to before it hands back.
  • Port 4173 is shared by every session on this machine. A unit never kills a server it did not start; it waits.
  • Every agent runs every command in the foreground and never ends a turn while something it started is running.
  • Schema changes go through npm run db:generate. Nobody edits a migration.
  • No unit runs npm run signoff: its dataset step fails until the dataset is uploaded. closing runs it once, after the upload.
  • The dataset version changes in this build. The dataset is uploaded once, by closing, from the integration branch, after every unit has merged; no other unit uploads a dataset. reach-check builds one earlier to run the check and uploads nothing.
  • A unit that writes a hashed path regenerates the fixture dataset with npm run pipeline -- fixture and commits it.
  • WCAG 2.2 AA: every new control is at least 24 px and passes expectNoA11yViolations in light and dark.
  • Page text is short. No sentence says what something is not.
  • Nothing on the main screen says "RHNA". The goal is read from the Goal value, never from a constant.
  • The game's rules are read from src/lib/game/. No component compares a level to a number.
  • One future: no seed control, no band, no average over runs.
  • Published plans and policies, their ids and their pages keep working, including every policy published before this build.
  • A number that is a claim about the world carries its source and tier, in the existing Sourced, Unsourced and Evidence shapes.
  • A runtime dependency that ships in the bundle gets a credit in SOFTWARE. This build adds none.
  • CSP changes are interface changes. This build makes none.
  • Timing is measured only on a quiet machine. A unit that cannot get one defers the measurement and says so.

Out of scope

  • Uploading a dataset, verifying it, and signoff: closing.
  • Running the check again on the dataset that is uploaded: closing.
  • Documenting the check: closing.
  • An npm script for the check, or a chreode step that runs it: no unit.
  • Changing a funding bound, the window's length or the goal when the check misses: the owner's call.
  • The funding bounds themselves: finite-funding. Pool closing: pool-closing.
