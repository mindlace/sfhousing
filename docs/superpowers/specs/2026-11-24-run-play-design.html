Run play: drops, the collecting ring and sound

A canvas over the map that turns each completing project into a drop, lets the player sweep a ring over drops to collect them, and plays short sounds made in the browser.

Purpose

During a run the player collects units from completing homes (P9). This subsystem is everything the player sees, hears and does inside a run. It knows nothing of the map, the simulation or the store: game-sim mounts it over the map and hands it a RunFeed.

  • It plans the drops from the city markers: one per project completing inside the run, worth its net new homes (call 2).
  • It shows each drop when the run's clock reaches its day, and counts it as dropped.
  • It collects a drop the ring touches, and counts it as collected. A drop not collected fades.
  • It moves the ring by mouse, pen, touch drag and the arrow keys, and collects everything under "Collect for me" (call 17).
  • It reports the run's totals to game-sim through ontake. Nothing it does reaches the worker or the policy document (P1, P9).
  • It makes four sounds with Web Audio and no files (call 18), and stores the two preferences "Collect for me" and mute.

Rulings it carries: P1, P9, P10 (worth is Units), calls 2, 13, 14, 17 and 18, and the accessibility line of the global constraints.

Interfaces

Produces R1. Needs G2 (units: credit and total) and G4 (Hands, BASE_HANDS). RunTake and Units are types that contracts provides; Marker.existing is a field of R1's own Marker, and the layer is built against a fake feed. Copied from the design with no change.

  • Nothing flashes more than three times a second.
  • A screen reader is told the run's totals at its end, never each drop.
  • The layer's root carries data-dropped and data-collected, the totals in homes.
  • onPrefs calls fn after either preference is written in this page, and returns its own removal. A change applies to a run in progress.
  • The layer's words are in src/lib/game/run/words.ts.
  • createSound makes its sounds with the Web Audio API and loads no file. It makes no sound while muted() is true or before a user gesture.

Global constraints

  • One future: the same policy document always gives the same forecast. No game state reaches the worker except through the policy document.
  • No file the dataset version hashes is changed: pipeline, src/lib/config.ts, src/lib/{data,generator,timelapse}, src/lib/plan/{geometry,types}.ts, src/lib/sim/finance (pipeline/lib/version.ts:41). The dataset version stays as it is.
  • A policy node acts on a lever the code already has, at a value the code already sources. No node invents a value.
  • The painted area, own pools, the City funding scale and market terms are never offered in a game.
  • Published plans and policies open and play in full, as today.
  • WCAG 2.2 AA: everything works from the keyboard; targets are at least 24 px; motion follows the reduced-motion setting; nothing flashes more than three times a second.
  • Page text is short. A node is a name, a line and a price.
  • The CSP is not widened. Sound is made in the browser; no audio file, font or script is added.
  • A runtime dependency is not added without a credit in src/lib/attribution.ts. None is expected.
  • Code style: 2-space indent, single quotes, no trailing commas, 100 columns.
  • Vitest runs with expect.requireAssertions. Tests are colocated.
  • A schema change goes through npm run db:generate. Migrations are never edited by hand.
  • Signoff fails on server stderr, on timing crutches and on retried flakes. Timing is measured only on a quiet machine.
  • Port 4173 belongs to whichever session started the preview. Never kill it; wait.
  • Commits use Conventional Commits and carry no Claude attribution.
  • Work happens in git worktrees under .claude/worktrees/.

Planning the drops

// src/lib/game/run/drops.ts
export function planDrops(markers: Iterable<Marker>, asOf: Day, to: Day): Drop[] {
  const byRow = new Map<number, Marker>();
  for (const m of markers) byRow.set(m.row, m);
  const out: Drop[] = [];
  for (const m of byRow.values()) {
    if (!(m.completed > asOf && m.completed <= to)) continue;
    const net = m.homes - m.existing;
    if (!(net > 0)) continue;
    out.push({
      row: m.row,
      lng: m.lng,
      lat: m.lat,
      day: m.completed,
      worth: { home: net },
      policy: m.policy
    });
  }
  return out.sort((a, b) => a.day - b.day || a.row - b.row);
}
  • A marker whose completed is NaN is left out, since no comparison with NaN holds.
  • asOf is exclusive and to inclusive.
  • Two markers with one row: the later in iteration order is the one planned.
  • A marker with homes at most existing gives no drop.
  • The result is a new array of new objects; the markers are not changed.
  • game-sim calls it with today as asOf and the rung's deadline as to, and passes the result as feed.drops.

The run model

The model is a plain object that the functions below change in place, so a frame allocates almost nothing. Every input that varies (wall time, the feed, the projection, the hands, reduced motion) is an argument. Tests step it with no canvas and no clock.

Start

  • createRun returns a model that is not running, with empty lists, a zero take, a 0 by 0 box and the ring at (0, 0).
  • A step whose running is true while the model's is false starts a run.
  • Starting sets take to { dropped: {}, collected: {} }, clears seen, live, counts and sweep, sets cursor to 0 and highDay to -Infinity, takes drops from the input, and puts the ring at the box's centre.
  • The same step then goes on as a running step. Every drop whose day is at or before the input's day appears in it.
  • The step reports started: true.

Appearing

  • When the input's drops is not the array the model holds, the model takes it and sets cursor to the first index whose day is after highDay, by binary search. In the same step, each drop before cursor whose row is not in seen is passed, in array order: its day was reached before its row arrived, so it appears now.
  • highDay becomes the larger of itself and the input's day. A NaN day leaves it as it is.
  • Each drop from cursor on whose day is at or before highDay is passed, and cursor moves past it.
  • A passed drop whose row is in seen is skipped. Otherwise its row is added to seen, its worth is credited to take.dropped, and it is appended to live.
  • A new live drop has bornMs = now, endMs = now + max(hands.lingerMs, RUN_TIMES.minShownMs), takenMs = null and at = project(lng, lat).
  • A drop whose at is null is counted and can be collected only by auto.

Collecting

  • A running step collects, and so does the step that ends a run (Fading, ending and going back).
  • With auto, every live drop whose takenMs is null is collected in the step, the ones that appeared in it included.
  • Without auto, a live drop whose takenMs is null and whose at is set is collected when sweepHits(m.sweep, m.ring, at, hands.radiusPx) is true.
  • sweepHits is true when p is within r of the path made by the points of sweep followed by ring: of any segment between two points with no null between them, or of any single point.
  • A drop that appears under a still ring is collected in the step it appears in.
  • Collecting sets takenMs = now and endMs = now + RUN_TIMES.takenMs, and credits the worth to take.collected. A drop is collected once.
  • Collecting a drop whose at is set appends a FloatCount at at. When counts then holds more than RUN_CAPS.maxCounts, the oldest is removed.
  • After the collect pass, sweep is emptied and ringMoved set false.
  • A drop that is fading can still be collected until its endMs.

Fading, ending and going back

  • Each step removes from live every drop with now >= endMs, and from counts every count with now >= bornMs + RUN_TIMES.countMs. The number removed is removed.
  • A step whose running is false while the model's is true ends the run. It first appears and collects exactly as a running step does, at the input's day: every drop whose day is at or before that day is counted in dropped, and one that the ring touches, or every one under auto, is collected. Then it reports ended: true, and the model's running becomes false.
  • The clock reaches the deadline and turns running false in one frame (game-sim's RunClock), so this step is the one that counts the drops due in the run's last frame. Every drop planDrops plans through the deadline is therefore counted in a run that reaches it.
  • After the ending step nothing is dropped or collected. The take is final at that step.
  • Ending sets each uncollected drop's endMs to the smaller of its own and now + RUN_TIMES.fadeMs, or to now under reduced. It empties sweep.
  • A run stopped before its deadline ends the same way. Drops whose day it never reached are never counted.
  • A feed day earlier than highDay changes nothing: no drop appears again, no count goes down, and live drops keep their times.
  • A new drops array in mid-run is matched to what is shown by row. A row in seen is never counted again, whatever its day or worth in the new array.
  • A drop already shown, live or collected, stays as it is: same point, worth, times and state, and its counts stay in the take.
  • A shown drop whose row is missing from the new array also stays as it is, collectable until its endMs. Nothing is taken out of the take.
  • A row not yet shown takes its day and worth from the new array. A row not yet shown that the new array lacks never appears. A row not yet shown whose day is at or before highDay appears in the step that takes the new array and is counted in dropped then: the city feed can trail the run's clock, and every completion the run passes is dropped.
  • A step while not running only removes what has ended.

When a frame is drawn

  • dirty is true when the step started or ended the run, a drop appeared, was collected or was removed, a count was removed, or the ring moved.
  • Without reduced, dirty is also true while anything animates: a drop younger than appearMs, an uncollected drop within fadeMs of its endMs, a collected drop, or any count.
  • Under reduced nothing animates, so only the discrete changes make a frame dirty.
  • idle(m) is !m.running && m.live.length === 0 && m.counts.length === 0.

The ring

// src/lib/game/run/run-model.ts
export const RING_KEYS = {
  stepPx: 16,
  shiftStepPx: 64
} as const;

export const RING_KEY_DIR: Record<string, [number, number]> = {
  ArrowLeft: [-1, 0],
  ArrowRight: [1, 0],
  ArrowUp: [0, -1],
  ArrowDown: [0, 1]
};
  • The ring's centre starts each run at the centre of the canvas box.
  • The ring's centre is clamped to the box: x to [0, w] and y to [0, h]. setBox clamps it again when the box changes.
  • setBox from an empty box (a width or height of 0) to one with both sides above 0 puts the ring at the new box's centre, whether or not a run is in progress. So a run that starts before the canvas has a size gets its ring at the centre once the first size arrives. While the box is empty no pointer point is inside it and every key step clamps to (0, 0), so nothing the player did is lost.
  • setBox is not a ring move. When it centres or clamps the ring it empties sweep and leaves ringMoved as it is, so no path joins the ring's place before the box changed to its place after.
  • pointRing(m, p, fresh) moves the ring to p, clamped. When fresh is false it first appends the old centre to sweep; when true it appends null. It sets ringMoved.
  • When sweep would hold more than RUN_CAPS.maxSweep entries, its oldest entry is removed first.
  • nudgeRing(m, dx, dy) is pointRing(m, { x: ring.x + dx, y: ring.y + dy }, false), so a key step sweeps the ground it crosses.
  • The layer listens for pointermove and pointerdown on the window, passive, for every pointer type: mouse, pen and touch.
  • A pointer event counts only while the run is running. Its point is its client position less the canvas box's cached top left.
  • A point inside the box (both coordinates within [0, size]) moves the ring. A point outside leaves the ring where it is and marks the pointer as out.
  • A pointerdown inside the box moves the ring with fresh true. So does the first pointermove inside after the pointer was out. Lifting a finger and touching elsewhere does not sweep the ground between.
  • Every other pointermove inside moves it with fresh false, whatever buttons are down.
  • A touch drag reaches the window only because the map's run view sets touch-action: none (M1).
  • The layer listens for keydown on the window. An arrow key moves the ring one stepPx in its direction; with Shift, one shiftStepPx. A held key moves it once per key repeat.
  • A key is ignored, and not prevented, when the run is not running, when auto is on, when the event is already prevented, when Alt, Control or Meta is down, or when its target is an input, textarea, select or editable element, or sits inside an element whose role is slider, menu, menubar, listbox, radiogroup, tablist, tree or grid.
  • A key that moves the ring calls preventDefault, so the page does not scroll.
  • The ring is drawn only while running and while auto is off.
  • It is drawn as a circle of radius hands.radiusPx: a fill of the accent at alpha 0.08, a 4 px stroke of the surface colour at alpha 0.9, and over it a 2 px stroke of the ink colour.

Look
The colours and the font family the layer reads from the page.
  • drawRun clears the whole canvas, then draws drops, then counts, then the ring.
  • It draws the newest RUN_CAPS.maxDrawn entries of live that have a point, oldest of those first, so newer drops sit on top.
  • A live drop is a filled shape with a outlinePx stroke of the surface colour. A drop whose drop.policy is true is a diamond, a square turned 45°, whose half-diagonal is diamondScale * dropRadius(worth), filled with look.policy. Every other drop is a circle of radius dropRadius(worth), filled with the accent. The scale gives the diamond about the circle's area.
  • With motion, a live drop grows from size 0 to full over appearMs, eased out as 1 - (1 - t)^3, and its alpha falls linearly from 1 to 0 over the last fadeMs before its endMs.
  • A collected drop is its shape's outline only, takenLinePx wide, in its fill colour: a diamond in look.policy for a policy drop, else a circle in the accent.
  • With motion, a collected drop's size goes from its full size s to s * (1 + takenGrow) and its alpha from takenAlpha to 0, linearly over takenMs.
  • A count is the text dropCountText(worth) from run/words.ts, centred, in countWeight countFontPx px of the page font, with a countHaloPx stroke of the surface colour under a fill of the ink colour.
  • A count's baseline starts countGapPx above the drop's top edge. With motion it rises countRisePx linearly over countMs, holds full alpha for the first countHoldShare of it, then falls linearly to 0.
  • Under reduced motion every shape and count is drawn at full size and full alpha in its place, and vanishes at its end time.
  • The layer reads the colours at mount from the root's computed style: --color-accent, --color-ink and --color-surface, or --color-accent-dark, --color-ink-dark and --color-surface-dark while (prefers-color-scheme: dark) matches. It reads them again when that query changes.
  • look.policy is TOKENS.light['tl-halo-policy'], or TOKENS.dark['tl-halo-policy'] while (prefers-color-scheme: dark) matches, chosen with the other colours. It is the colour the map draws its policy diamond in, so a policy drop matches the map's diamond in shape and colour. The token is read from $lib/map/palette because the map sets its --map-* properties on its own root, which the layer, a sibling, does not inherit.
  • The font is the canvas element's computed font-family.

Pixel ratio, size and redraw

  • The backing store is Math.round(w * dpr) by Math.round(h * dpr), with dpr = Math.min(devicePixelRatio || 1, DRAW.maxDpr), the map's own cap. The context's transform is setTransform(dpr, 0, 0, dpr, 0, 0), so everything is drawn in CSS pixels.
  • A ResizeObserver on the canvas sets the size: it resizes the backing store, calls setBox and reproject, re-reads the box's top left, and draws one frame.
  • A change of matchMedia('(resolution: ' + dpr + 'dppx)') does the same.
  • The box's top left is also re-read on a window scroll (capture, passive) and at each run start.
  • The camera is locked during a run (M1), so a drop's point is projected once when it appears and again only on a resize.
  • The frame loop runs only while the model is running or not idle. It steps every frame and draws only a dirty one.
  • When the model turns idle the loop clears the canvas once, stops, and the canvas gets visibility: hidden so the browser does not composite it. It is shown again when a run starts.
  • Pointer and key events never start the loop.

Many drops at once

  • Every drop is counted in dropped and can be collected, however many appear in one step.
  • At most RUN_CAPS.maxDrawn (240) live drops are drawn: the newest. An older live drop beyond the cap is still hit by the ring and still counts.
  • At most RUN_CAPS.maxCounts (40) counts exist; a new one pushes out the oldest.
  • A step calls sound.collect() once if it collected any drop, and otherwise sound.pop() once if any drop appeared. The sounds' own gaps then thin a stream of frames.
  • ontake is called at most once per step.
  • A frame's work is bounded: one pass over the drops passed, one hit test per live drop against at most maxSweep segments, and at most 240 drops, 40 texts and one ring drawn.

Reduced motion, flashing and the screen reader

  • The layer reads reduced motion from reducedMotion() in clock.ts, a live matchMedia('(prefers-reduced-motion: reduce)'), once per frame, and passes it to step and drawRun.
  • Under reduced motion drops and counts appear and disappear without growing, rising or fading (R1).
  • Every drawn shape stays at least RUN_TIMES.minShownMs (400 ms) from appearing to vanishing: an uncollected drop by its linger floor, and a collected drop by takenMs after collection. So no one spot changes more than about 2.5 times a second.
  • Nothing blinks or pulses, the canvas never fills or clears its whole area in a colour, and the ring never flashes.
  • The drawn drops cover at most 240 shapes with their outline: a circle of radius 10.5 px is about 346 square CSS pixels and a diamond of half-diagonal 12.75 px about 325, so at most about 83,000 square CSS pixels, below the WCAG general-flash area of 341 by 256 px.
  • The canvas has aria-hidden="true". No drop, count or sound is announced.
  • The layer holds one visually hidden paragraph with aria-live="polite" and test id run-live.
  • It is empty while a run is running. When the run ends it is set to runOverText(take) from run/words.ts. It is emptied when the next run starts.

Decisions

  • The state machine lives in its own file, run-model.ts, and changes its model in place. Reason: a frame with hundreds of drops must not allocate, and tests still step it without a canvas.
  • A drop is projected when it appears and again only on a resize. Reason: the camera is locked in the run view (M1), so a point cannot move otherwise.
  • The ring collects along its path since the last frame, not only at its centre. Reason: a fast sweep crosses a drop between two frames.
  • A new touch, or re-entry after the pointer left the map, breaks the path. Reason: lifting a finger is not a sweep.
  • An uncollected drop lasts at least 400 ms, and a collected one 400 ms more. Reason: the flash limit needs every shape to stay a while.
  • The step that ends a run first passes and collects the drops due through its day, then cuts live drops to a 400 ms fade and stops collecting. Reason: the clock turns running false in the frame it reaches the deadline, so the last frame's drops are counted there, and ontake at the end must carry final totals.
  • A feed day going back changes nothing. Reason: counts that go down would undo what the player saw.
  • A row that arrives in a new drops array after the run's day has passed its day appears at once. Reason: the city feed may trail the clock by a flush or more, and R1 drops every completion the run reaches.
  • A shown drop whose row leaves a new drops array stays until its own end. Reason: taking away a drop the player saw, or units they collected, would read as a fault.
  • onPrefs notifies after every write, failed ones included, and only in this page. Reason: the switch the player pressed must take effect even when storage is full.
  • Only the newest 240 drops are drawn; older live drops beyond the cap still count and can be collected. Reason: the draw stays inside the frame budget and the flash area, and no drop is lost.
  • A collected drop rings out in place and its "+N" rises from it; nothing flies to the unit count (call 28). Reason: the canvas covers only the map's box, the count is in the Menu below lg, and a flight for each drop would break the flash limit and the frame budget. The header's count rolls when the run is settled.
  • Drop radius grows with the square root of worth, 4.5 to 9 px. Reason: area tracks homes while a large project does not hide its neighbours.
  • At most one sound per frame, collect before pop, with gaps of 50 and 70 ms. Reason: a burst must not become a roar.
  • The audio context is made at the first gesture even when muted. Reason: unmuting then plays at once.
  • The ring is hidden and the arrow keys are left alone under auto. Reason: the ring does nothing then.
  • The colours are the page's accent, ink and surface tokens, and the map's policy-mark token for a policy drop. Reason: no new colour is added, dark mode follows, and a drop from a project the policy marks pops in the same colour as the map's diamond, as the source model asks.
  • A policy drop is a diamond and every other drop a circle. Reason: the map's policy-mark token and the accent are one colour in both themes (src/lib/map/palette.ts:91, :138; src/routes/layout.css:4, :8), so colour alone cannot tell them apart; the diamond is the map's own policy mark, and a shape carries the difference for every reader, colour vision or not.
  • The canvas is hidden when idle. Reason: a hidden canvas is not composited over the map.
  • The clock is a mocked module, not a prop. Reason: the R1 props stay as the design gives them.
  • Preferences are stored as '1' and '0'. Reason: the shortest value that a stray string cannot be read as.
  • The layer's frame budget is 2 ms p95, to be confirmed by closing's bench case. Reason: the map's p95 is about 9 to 10 ms today, so 2 ms keeps it well under 16.7 ms.
