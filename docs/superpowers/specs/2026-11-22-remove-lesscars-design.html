Remove less cars design

Delete /fzp, /lesscars and everything only they use, and keep the freeway-land catalog, the scenario engine and src/lib/fzp.

Goal

This unit is the remove-lesscars subsystem of the incremental game design. It carries rulings R4 ("delete less cars now") and D11 ("what stays from less cars") and owns interface row L1. A later unlock rebuilds less cars on the step engine; nothing here is kept for it except what D11 names.

  • The routes /fzp and /lesscars are gone and answer 404.
  • The app modules built for /lesscars are gone: src/lib/lesscars, src/lib/sim/lesscars, src/lib/data/lesscars, and the two src/lib/fzp files only /lesscars used.
  • The sim worker has three modes: editor, scenario and timeline.
  • The map style draws an older dataset's roads_lc layer as ordinary roads, and names that layer only for a dataset that has it. The palette has no lc-* tokens, and filter-expr.ts is gone.
  • The pipeline has no less-cars step, command, SQL, enrichment or test. A build copies the basemap byte for byte and writes no scenarios/lesscars/*.
  • The freeway-land catalog moves to pipeline/enrichment/freeway-land.json and decides lot eligibility exactly as before.
  • PATHS in pipeline/lib/version.ts lists exactly what the pipeline imports, and a test holds it there.
  • The fixture dataset is regenerated and committed; no dataset is uploaded.

Design

What the two URLs answer

  • /fzp and /lesscars, with or without a query, answer 404 with the root error page: title and heading "Page not found", and the link "Go to the home page".
  • No redirect is kept. R4 says delete it all; the redirect's own comment calls it temporary; no product page and no published link has pointed at /fzp since /sim replaced it.
  • The reserved handle words lesscars and fzp (src/lib/server/user-store/handle-normalize.ts:20-21) stay reserved. This unit does not edit that file.

The sim worker

The router keeps its behaviour for the three remaining modes, request for request.

// src/lib/sim/router.ts
type WorkerMode = 'editor' | 'scenario' | 'timeline';

export interface RouterDeps {
  editor: { handle(r: SimRequest): void; dispose(): void };
  createScenario: () => { handle(r: ScenarioRequest): void; dispose(): void };
  createTimeline: () => { handle(r: TimelineHostRequest): void; dispose(): void };
  post(msg: ScenarioResponse | SimResponse | TimelineHostResponse): void;
}

// src/lib/sim/scenario/types.ts
export type WorkerRequest = SimRequest | ScenarioRequest;
export type WorkerResponse = SimResponse | ScenarioResponse;
  • init disposes the scenario and timeline hosts; initScenario disposes the editor and the timeline host; openTimeline disposes the editor and the scenario host. None of them calls a playback host.
  • reroll and setLevers in timeline mode answer error with code: 'bad-request' and the message `${type} needs a /sim scenario session`, as today.
  • prefetch and retryChunks go to the scenario host, the timeline host or the editor by mode.
  • parcelSummary goes to the timeline host, the scenario host or the editor by mode.
  • A message whose type the router does not know, such as an old initPlayback or playbackCard, is ignored: nothing is posted and no host changes.
  • worker.ts builds no playback host.

  • manifestFiles lists no scenarios.lesscars.* entry, so upload, verify and data:local neither send, check nor copy those files, even for an older manifest that names them.

Datasets built before this unit

A published plan or policy keeps loading its own dataset. What such a dataset holds, rule by rule:

  • Its manifest has scenarios.lesscars. It parses, with splitRoads: true (the manifest). The worker hosts' checkManifestShape does not look at scenarios (src/lib/sim/scenario/load.ts:113), so they take it as they do today.
  • Its scenarios/lesscars/* are never fetched: no code reads them and manifestFiles does not list them, so data:local, upload and verify skip them.
  • Its basemap.pmtiles holds the moved freeway stretches in roads_lc. The map draws them through the clones (the style).
  • Its report.json has V35 and lesscars.* counts. Nothing in the app reads it; pipeline check <v> on such an out dir reports what the current checks measure and ignores the rest.
  • Its scenarios/fzp/*, chunks, buildings, fonts, neighbourhoods and transit.json use codecs this unit does not change.

The map style and palette

  • manifest.splitRoads is the one input that switches the clones on. protomapsLayers takes it from buildStyle(manifest, theme) and puts each clone right after its roads layer.
  • For a manifest without splitRoads, no style layer names roads_lc and no layer id ends in __lc.
  • themePaintDiff(manifest) builds from the same manifest, so its clone entries exist exactly when the style has clones.
  • The comment above the constants says: datasets built before this unit move some freeway stretches into roads_lc; their manifests have scenarios.lesscars, and the clones draw that layer as roads.
  • TokenName, both TOKENS themes and every CSS the palette emits have no lc-* token.

  • The comments that name /lesscars in palette.ts go with the tokens.

Global constraints

  • Work happens in git worktrees under .claude/worktrees/. Commits follow Conventional Commits. No attribution to an AI anywhere.
  • Code style: 2-space indent, single quotes, no trailing commas, 100 columns.
  • Every Vitest test calls expect.
  • Signoff fails on server stderr, on timing crutches and on a retried flake. Each unit runs npm run lint, npm run check and the Vitest projects its files belong to before it hands back.
  • Port 4173 is shared by every session on this machine. A unit never kills a server it did not start; it waits.
  • Every agent runs every command in the foreground and never ends a turn while something it started is running.
  • Schema changes go through npm run db:generate. Nobody edits a migration.
  • No unit runs npm run signoff: its dataset step fails until the dataset is uploaded. closing runs it once, after the upload.
  • The dataset version changes in this build. The dataset is built and uploaded once, from the integration branch, after the last unit that writes a hashed path has merged; no unit uploads a dataset.
  • A unit that writes a hashed path regenerates the fixture dataset with npm run pipeline -- fixture and commits it.
  • WCAG 2.2 AA: every new control is at least 24 px and passes expectNoA11yViolations in light and dark.
  • Page text is short. No sentence says what something is not.
  • Nothing on the main screen says "RHNA". The goal is read from the Goal value, never from a constant.
  • The game's rules are read from src/lib/game/. No component compares a level to a number.
  • One future: no seed control, no band, no average over runs.
  • Published plans and policies, their ids and their pages keep working, including every policy published before this build.
  • A number that is a claim about the world carries its source and tier, in the existing Sourced, Unsourced and Evidence shapes.
  • A runtime dependency that ships in the bundle gets a credit in SOFTWARE. This build adds none.
  • CSP changes are interface changes. This build makes none.
  • Timing is measured only on a quiet machine. A unit that cannot get one defers the measurement and says so.
