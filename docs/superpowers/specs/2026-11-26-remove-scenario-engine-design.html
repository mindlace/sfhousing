Remove the scenario engine

Delete the old Monte Carlo engine and the tests that held the step engine to it; move what the step engine still uses into src/lib/sim/world/.

Why

  • The owner does not keep unused code. The step engine (src/lib/sim/world/) replaced the scenario engine (src/lib/sim/scenario/); the old run loop, its host and its worker mode serve no page.
  • The parity tests that made the new engine equal the old one were right while the step engine was being built. Now they limit the model to what the old engine could represent. Every one of them goes.

Goals, non-goals, anti-goals

  • Goal: src/lib/sim/scenario/ no longer exists. Nothing named "scenario" survives as an engine, mode, client or host.
  • Goal: no test compares the step engine with the old engine (referee, golden, equality or replay).
  • Goal: what the step engine still calls lives under src/lib/sim/world/, and what nothing calls is deleted.
  • Non-goal: rewriting the borrowed rules in the world's own style, or changing any model behaviour. That is later work.
  • Anti-goal: a change in what the game shows. Every simulation number, map frame and card stays as it is today.
  • Anti-goal: a change in the dataset version. Moving code must not change codeTreeHash or treeDatasetVersion, which would force a new dataset upload.

What is there today

  • Dead: scenario/simulate.ts (the run loop), scenario/scenario-host.ts, the 'scenario' mode in src/lib/sim/router.ts and src/lib/sim/worker.ts, src/lib/sim/scenario-client.ts, and the golden suites scenario/simulate.golden.* and simulate.finance.golden.*.
  • Parity tests outside scenario/: world/referee.spec.ts, referee.variants.spec.ts, pipeline.referee.spec.ts, frames.referee.spec.ts, score/series.referee.spec.ts, map-stream.equality.spec.ts and pipeline/test/simulate-replay.test.ts, together with the helpers that only serve them (for example oldInputOf in world/test/timeline.ts).
  • Live, borrowed by the step engine: engine.ts (stage.ts, world.ts, pipeline.ts, holds.ts and funding/serve.ts call into it), card.ts, lot-at.ts, preview.ts's PREVIEW_MAX_LOTS, the host's createToken, MEMO_CAP and SLICE_PLAN_MS, the Master type from simulate.ts, and the shared modules types, input, money, funding, dates, rng, score, load, finance-score, funded, market, policy, massing, geometry, line, band and fixtures/. These are imported from about 230 files across src, scripts and pipeline.

Approaches

  • A. Cut only the dead parts. This is the smallest diff, but the live rules would stay in a folder named after the old engine, mixed with leftovers.
  • B. Cut, then move what is live into world/. Chosen by the owner, with world/ as the destination. Both reasons are fully addressed: no unused code, and nothing that reads as the old model setting the shape of the new one.
  • C. B, plus rewriting the borrowed rules natively. This would change the model, which is out of scope here.

Design

  1. Delete the parity tests first, along with the test helpers and fixtures that only they use. The suite then no longer needs the old run loop.
  2. Delete the old engine's entry points: simulate.ts (after moving Master), scenario-host.ts (after moving the constants and createToken the world host uses), scenario-client.ts, the router's 'scenario' mode and the worker's scenario host. ScenarioWorkerInput and ScenarioWorkerLike, which the timeline client and session use, move to timeline-client.ts under names that drop "Scenario". The same goes for the "Scenario" names in lookup-requests.ts and scenario/types.ts's worker request union.
  3. Prune engine.ts down to what the world calls, and move it into world/. Functions only the run loop used are deleted. The remaining modules move too, each one deleted if nothing outside the old engine uses it.
  4. Rewrite imports everywhere (src, scripts, pipeline, e2e), then delete src/lib/sim/scenario/.
  5. Keep the dataset version. codeTreeHash ignores scenario/engine.ts today (see pipeline/test/version.test.ts). Its path rules are updated so the moved files hash exactly as before, and the test's paths follow the move.
  6. Docs: remove every docs/dev/ mention of the scenario engine, the referees and the golden suites, and fix moved paths. That covers world-core.md, world-funding.md, ensemble-runner.md, finance-*.md, testing.md, pipeline.md, policy-timeline.md and the others grep finds. Specs and plans under docs/superpowers/ are history and stay as they are.
Builder's call The layout inside world/ (for example world/rules/ for the pruned engine and world/input/ for the loaders and types) and the new names for symbols that carry "Scenario" or "scenario" (loadScenario, scenarioUrls, ScenarioParcels, manifest.scenarios in code) are left to the builder. Dataset keys and the manifest's on-disk field names do not change.

Done when

  • src/lib/sim/scenario/ and src/lib/sim/scenario-client.ts are gone, and a grep for sim/scenario, simulateDetailed, referee or golden in src, scripts, pipeline, e2e and docs/dev finds nothing.
  • npm run check, npm run lint, npm run test:unit and npm run test:e2e pass, and npm run signoff posts.
  • The build's dataset version equals main's.
  • npx tsx scripts/reach-check.ts on the fixture gives the same result as on main.
