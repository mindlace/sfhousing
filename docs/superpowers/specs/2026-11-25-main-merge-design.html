Main merge: the car ownership model in the incremental loop

Brings main into the integration branch, with the car ownership model and the commits beside it, says what the merged code is where the two sides meet, and takes the results of record again on main's dataset.

Purpose

This unit runs after loose-ends, on the integration branch with every other unit of the design merged. main carries four commits the package was not built on: freeway land is unpaintable (#149), permit-side pooled baselines fitted from 2015-01-01 (#150), the Pipeline workflow removed (#151), and the car ownership model with parking into start odds (#153, docs/dev/cars.md). It produces no interface row and needs none. It is built in two parts, in order:

  • The merge: origin/main merged into the unit's branch, every conflict resolved by the rules below, the application whole on the merged tree, and the reach check of record run.
  • The retake: the measured ladder, the tuned numbers, the run bench, the purchase-to-ready wait and the budgets held to main, taken again on main's dataset with cars in the world.

It carries P1 (the game never changes what the simulation forecasts), P3 (new parts of the model join the tree as branches of nodes), D1 (current law reaches the first goal inside the window), R7 (one future; evidence ranks), call 10 (the measured ladder) and call 25 (every tuned number in tuning.ts).

Interfaces

Produced: none. Needed: none. Row E2 holds the chunk's fields as they are after the merge: cars is the car system's, waiting is E2's.

  • The painted area, own pools, the City funding scale and market terms are never offered in a game.

  • WCAG 2.2 AA: everything works from the keyboard; targets are at least 24 px; motion follows the reduced-motion setting; nothing flashes more than three times a second.
  • Page text is short. A node is a name, a line and a price.
  • The CSP is not widened. Sound is made in the browser; no audio file, font or script is added.
  • A runtime dependency is not added without a credit in src/lib/attribution.ts. None is expected.

  • Vitest runs with expect.requireAssertions. Tests are colocated.
  • A schema change goes through npm run db:generate. Migrations are never edited by hand.
  • Signoff fails on server stderr, on timing crutches and on retried flakes. Timing is measured only on a quiet machine.

Design

Cars and the game

  • Cars are part of the forecast, not a lever. The game reads them nowhere: no node, grant, limit, side goal, tally row or headline reads cars. A run's drops, the goal's homes and every rung's reading take the forecast as it is, cars included (P1, one future).
  • The car model joins the tree as a branch of nodes only once the document holds a car or parking policy for a node to act on (P3). None exists, so this round adds no node.
  • Details' cars row shows in the workshop and in the open game as main shows it on the simulation.
  • The cars-per-household layer is a Layers-panel preference like transit access: it is set in the workshop or the open game, and while on it draws in the run view as transit access does (call 19). The run neither turns it on nor off.
  • About keeps main's Cars section in its assumptions beside the package's game sections.

The score series

  • SeriesChunk is { from, rows, planEffect, money, tiers, cars, waiting? }. cars is the plan series' car rows (main's rule); waiting is the plan world's homes waiting for money (E2). Neither reads the other.
  • chunkOf sets both keys; the chunk keys test lists the six.
  • TimelineView carries cars (main's, null for a world without a car system) and waitingMoney (E2). viewOf joins both, each by its own null rule; chunksBefore trims both.
  • WorldSeries keeps main's created(cars) and stepped(month, cars?), and the extras keep both cars(from, through) and waiting(world, from, through).
  • The before helpers of host.edit.spec.ts and timeline-client.host.spec.ts copy cars and waiting, each trimmed to the same months.
  • The waiting count is recorded at the end of the funding system's shadow hook. The car step runs between systems 3 and 4 and never writes the funding line, so the count's rule is unchanged with cars on.
  • docs/dev/world-score.md documents both: main's cars section and the package's "Homes waiting for money".

The reach check and the car switch

  • scripts/level2-check.ts and its spec stay deleted. The reach check is scripts/reach-check.ts, and it carries main's switch.
  • Usage: npx tsx scripts/reach-check.ts <datasetDir> | --version <v> [--from <origin>] [--amount <homes>] [--cars on|off]. --cars defaults to on; any other value is refused with exit 2 and the line reach-check: --cars must be on or off, got <value>.
  • openEngine(src, { warn?, timeoutMs?, cars? }) passes cars to createTimelineHost, default 'on'. Engine gains fillMs: wall-clock milliseconds from openTimeline to the last month of the opening fill (current law).
  • The reach check prints a fifth line after its four: Filled in <s> s (cars on|off), the seconds to one decimal. Its exit codes are unchanged.
  • reach-measure and tree-balance run with cars on and take no switch: they measure the game a player plays.
  • Documents that name level2-check as a command name reach-check: docs/dev/cars.md (the off path is reach-check --cars off; the section "Level 2 with and without cars" is titled "Current law with and without cars"), docs/dev/testing.md, docs/dev/pipeline.md and CLAUDE.md (the cars entry reads "current law with and without cars"). A dated measurement keeps its figures and dataset.

The dataset

  • The package writes no file main's PATHS hashes, src/lib/sim/cars, src/lib/sim/scenario/rng.ts and src/lib/transit included. So the merged tree's dataset version is origin/main's, and npx tsx scripts/dataset-version.ts --check passes on it. A difference stops the unit and goes to the conductor.
  • That version is main's to build and upload. The unit confirms <origin>/data/<v>/manifest.json answers 200 on production; when it does not, the unit stops and hands back "blocked: main's dataset <v> is not uploaded". It uploads nothing.

Decisions

  • One unit in two parts. The merge has to be whole before signoff can merge origin/main itself; the retake needs a quiet machine and may hand back to the owner, so it follows the merge.
  • Cars stay out of the game's rules. The model has no lever in the document, so a node would invent one; the game sees cars only as the forecast's homes.
  • The reach check takes main's switch, not its name. Level 2 does not exist in the game; the check's question is the package's, and --cars off keeps main's way of measuring the car system's cost.
  • The scripts that set numbers run with cars on. The ladder and the prices are for the forecast the player plays.

Out of scope

  • Building or uploading a dataset: main's.
  • Car or parking policies, and nodes that act on them: a later round (P3).
  • Changing the car model, its costs or its layer.
  • Running npm run signoff: the conductor, after the hand-back.
