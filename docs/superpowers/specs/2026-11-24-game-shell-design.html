Game shell: one address, the opening, the header and the name

The game lives at /: the brush editor in the opening, the simulation after it, a header without steps, and the site named SF Housing.

Purpose

This subsystem is the shell around the game of the incremental loop. It makes Paint and the simulation one page at one address, turns Paint into the opening of a new game, takes the two steps out of the header, renames the site and removes Remix from the shared plan page.

It carries these rulings and calls:

  • P5 one game on one page: the steps "1 Paint" and "2 Simulate" go.
  • P8 the name is "SF Housing".
  • P11 paint is the opening only: the brush shows until the first run starts and never again.
  • P13 no Remix: the Remix button on /p/<id> goes, and the shared banner loses it for both kinds.
  • P14 Publish sends what is true: the plan during the opening.
  • D7 the account is made at the first win, which is the room goal: the opening calls won().
  • Call 6 one address: /sim redirects to /; the map remounts once and keeps the camera.
  • Call 7 the header's unit count (GameCell) takes the level cell's place.
  • Call 9 the open game is the whole tool, and call 21: at / it shows the simulation; a test that needs the opening seeds a new visitor.
  • Call 15 the name changes in the user-facing places, SES_FROM and the tests; rpID and the infrastructure names stay.

This is the last part of one lane: one unit, merged once. Its parts, in dependency order, are game-save, part B of tally-tree, game-sim and game-shell; the unit's plan orders its tasks across the parts as its tests need, inside the lane's write set, and each file ends as the spec that owns it says. When the lane lands, the application builds again and type-checks outside e2e/**; the e2e specs that still use the earlier helper API, and the e2e run, are whole again when closing lands (design, sec-write-sets).

// src/lib/game/state.ts
import type { Day } from '$lib/timelapse/time';
import type { RunResult } from './run-result';

export type UnitKind = 'home';
export const UNIT_KINDS: readonly UnitKind[] = ['home'];
export type Units = Partial<Record<UnitKind, number>>;
export type NodeId = string;

export interface MetRung {
  rung: number;
  reachedOn: Day;
  datasetVersion: string;
  at: string;
}

export interface GameState {
  v: 2;
  phase: 'opening' | 'runs';
  firstWinAt: string | null;
  bought: Record<NodeId, number>;
  units: Units;
  rung: number;
  met: MetRung[];
  side: Record<string, string>;
  runs: number;
  last: RunResult | null;
}

export const NEW_GAME: GameState;

// src/lib/game/save-shape.ts
export interface GameSave {
  v: 2;
  id: string;
  name: string;
  nameIsDefault: boolean;
  state: GameState;
  plan: string | null;
  policy: string | null;
  savedAt: string;
}

export type SaveEntry = Pick<GameSave, 'id' | 'name' | 'nameIsDefault' | 'savedAt'> &
  Pick<GameState, 'phase' | 'rung'>;

export function parseGameSave(json: unknown): GameSave | null;
phase
'opening' until the first run starts.
firstWinAt
ISO time the room goal was first met. The server makes the account on the first save that has it (D7).
bought
The level bought of each node, 1 or more. A node not bought has no entry.
units
The balance to spend.
rung
The index in the ladder of the deadline in play.
met
One entry per rung met, ascending by rung, each recorded once.
side
Side goal id to the ISO time it was first met.
last
The latest run's result, which the header shows between runs.
  • NEW_GAME is the opening with nothing bought, no units, rung 0 and no runs.
  • parseGameSave returns null unless v is 2 at both levels (P15).
  • The result is rebuilt from the known fields. An unknown field is dropped.
  • parseGameSave checks the shape only. It keeps a node, a level, a side goal or a rung the catalogue does not have; fitGame (G6) drops those in the browser.
  • The server stores what parseGameSave returns.
  • Unit amounts and runs are whole numbers of 0 or more.
  • plan and policy stay opaque text, as they are today.

Removed: Level, Progress, Banked, Bar, barOf, roundComplete, levelUp, standing, beats.

  • state and limits are reactive. limits is OPEN_LIMITS for the open game, else limitsOf(state).
  • Every save the store reads, from storage or from the server, passes through parseGameSave and then its state through fitGame (G6).
  • won sets firstWinAt once and writes.
  • startRuns sets phase to 'runs'. It does nothing while firstWinAt is null.
  • buy writes the new state when the purchase is good and returns what buy of G3 returns. A refused write returns { ok: false, reason: 'short' } and changes nothing.

  • The open game is in phase 'runs' with the last rung met, every node bought and no units; its methods that write do nothing.
  • settle does nothing for a result already settled.

Global constraints

  • One future: the same policy document always gives the same forecast. No game state reaches the worker except through the policy document.
  • No file the dataset version hashes is changed: pipeline, src/lib/config.ts, src/lib/{data,generator,timelapse}, src/lib/plan/{geometry,types}.ts, src/lib/sim/finance (pipeline/lib/version.ts:41). The dataset version stays as it is.
  • A policy node acts on a lever the code already has, at a value the code already sources. No node invents a value.
  • The painted area, own pools, the City funding scale and market terms are never offered in a game.
  • Published plans and policies open and play in full, as today.
  • WCAG 2.2 AA: everything works from the keyboard; targets are at least 24 px; motion follows the reduced-motion setting; nothing flashes more than three times a second.
  • Page text is short. A node is a name, a line and a price.
  • The CSP is not widened. Sound is made in the browser; no audio file, font or script is added.
  • A runtime dependency is not added without a credit in src/lib/attribution.ts. None is expected.
  • Code style: 2-space indent, single quotes, no trailing commas, 100 columns.
  • Vitest runs with expect.requireAssertions. Tests are colocated.
  • A schema change goes through npm run db:generate. Migrations are never edited by hand.
  • Signoff fails on server stderr, on timing crutches and on retried flakes. Timing is measured only on a quiet machine.
  • Port 4173 belongs to whichever session started the preview. Never kill it; wait.

Design

One address

/ loads what both the opening and the simulation need. +page.svelte chooses its body after mount from the game.

// src/routes/+page.ts
import { error } from '@sveltejs/kit';
import { emptyPlan, type Plan } from '$lib/plan';
import { loadSimScenario, type SimPageData } from '$lib/sim-page/load';
import type { PageLoad } from './$types';

/** The opening's plan and the simulation's scenario: one manifest, then the calibration. */
export type HomeData = SimPageData & { plan: Plan };

export const load: PageLoad = async ({ fetch, parent }): Promise<HomeData> => {
  const { datasetVersion } = await parent();
  let plan: Plan;
  try {
    plan = emptyPlan(datasetVersion);
  } catch {
    error(500, 'Invalid dataset version');
  }
  const { fellBack: _current, ...scenario } = await loadSimScenario(
    datasetVersion,
    datasetVersion,
    fetch
  );
  return { plan, ...scenario };
};
  • The load fetches the manifest once and the calibration once. The opening uses plan, manifest and manifestError; the simulation uses the five SimPageData fields.
  • A manifest failure returns manifest: null, manifestError: true, calibration: null and never throws. A calibration failure returns calibrationError: true; the opening runs, and the simulation shows its own Retry when it mounts.
  • fellBack is no longer returned: nothing read it.
  • Cost: the calibration (at most 256 KB, 59,823 bytes in fixture-0) is fetched on every load of /, the opening included, and on a server render its body is inlined in the HTML, as /sim's is today.
Decision Load both in +page.ts. The phase lives in the browser's storage, so the server cannot tell which body is needed. Loading the calibration only when the simulation mounts would add a round trip before the simulation on every later visit, which is every visit after the first win. The opening is played once per game.

Decisions

  • The name lives in src/lib/shell/name.ts. config.ts is an input of the dataset version (pipeline/lib/version.ts:41-50), so it is left alone and APP_NAME stays unused.
  • schema.ts writes the name as a literal. src/lib/plan/purity.spec.ts lets plan/ code import only its siblings and a named list, which keeps the plan model free of app modules; schema.spec.ts pins the whole sentence, so the literal cannot drift from SITE_NAME unseen.
  • Both data loads in +page.ts. The server cannot know the phase, and the simulation is every visit after the first win.
  • The body is chosen after mount. The server holds the open game; any earlier choice mismatches at hydration.
  • /sim is a 308 from a universal load, the query dropped. The only query it read is retired; 308 matches /attribution; the universal load keeps the redirect inside the two files this subsystem holds.
  • The opening is its own component. Its header registration must exist only while it is mounted, or the simulation's header would be preceded by Paint's.
  • The card stays while the goal is met. OpeningCard has no dismiss, and the map stays usable under the non-modal card.
  • No remount on a change of the current id. The sync's rekey keeps the same game; a real switch loads the page.
  • No dot on the Menu button. Nothing in the Menu acts on an offered rung or an affordable node.
  • The Remix-free N5: "Made with map data X, older than the current data (Y)." It states the fact the old line hung Remix on.
  • The About section keeps its id about-levels. Ids are link targets, and two specs name it.
  • The run's keys are a third table, "Run". The two existing tables list Paint's and the timeline's keys; a run is neither.
  • "Five or more years" in The deadline's body: the first step runs from the window's end to a 31 December, and when more than four five-year steps fit, the ladder keeps four years with wider steps between them (G6), so no step is shorter than five years and some can be longer.
  • remix.ts is deleted. No page imports it, and Remix is gone.
  • SharedBanner keeps its unused id prop. Dropping it would change /s/[id] for no gain.
