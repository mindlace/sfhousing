Finite funding design

Every one of today's funding sources carries a bound from evidence, federal tax credits get a yearly ceiling, and no pool can always pay.

Goal

Today's public money in the simulation never ends: every baseline pool is paid each year with no end, and the federal pool can always pay. This unit makes it finite, as the incremental game design rules (R2, D3, Finite public money). It delivers:

  • pipeline/enrichment/funding.json at schema 2: a bound on every source, read from evidence, and the federal yearly ceiling.
  • The calibration step emits pools whose inflows follow their source's bound, with provenance text that states each end and its citation.
  • Pool.uncapped gone from the types, both engines, the score, the pipeline and the page.
  • Stored and published documents that carry uncapped still load.
  • The fixture dataset's calibration.json regenerated.

Pools that end leave a known limit in the step engine: an affordable application waits on a spent pool. The pool-closing unit, built after this one, removes it (D13).

ends
on is an ISO date. The source's last yearly arrival is the last one on or before it.
remaining
The dollars the source has left in total, as of the citation: an authorisation not yet issued, a balance being spent down.
none
Law sets no end. reason says what was read that shows it.
  • Every City source, the state source and the federal source has a bound. A file without one is refused.
  • No bound has tier 4. An end nobody has read in a source is not written.
  • A source with ends emits one yearly inflow from the dataset date to on.
  • A source with remaining emits one-time inflows of dollarsPerYear on the dataset date and each anniversary until dollars is used, the last one being what is left.
  • A source with none emits one yearly inflow with no end.
  • A source whose ends.on is before the dataset date, or whose remaining.dollars is 0, emits a pool with no inflow, and its programme is not in the baseline.
  • The calibration's provenance text for each pool states its end, or that it has none, with the citation.
  • The "check" that compares implied homes a year with observed awards is kept and reads the first year.

Design

The funding file, schema 2

The file's shape follows F1; perHome, city's other fields, awards and retiredIds keep today's meaning. This unit adds the Bound type and makes it required on every source in one step.

  | { kind: 'none'; reason: string; tier: 1 | 2 | 3; cite: Cite };

  id: string;
  label: string;

  tier: number;
  method: string;
  cite: Cite;

export interface FederalSource {

export interface FundingFile {
  schema: 2;
  perHome: { /* as today */ };
  city: { fiscalYear: string; total: number; tier: 1; cite: Cite; sources: CitySource[] };
  state: StateSource;
  federal: FederalSource;
  awards: { /* as today */ };
  retiredIds: string[];
}

Validation rules, each a BuildError naming the path, in the form today's parseFundingFile gives:

  • schema is 2. A file at schema 1 is refused with "funding.json is schema 1: every source needs a bound (schema 2)".
  • Every City source, state and federal has a bound. A missing one is refused.
  • bound.kind is ends, remaining or none; each kind holds exactly its own keys (a strict object).
  • bound.tier is 1, 2 or 3. A tier 4 is refused with "a bound's tier is 1, 2 or 3: an end nobody has read in a source is not written".
  • ends.on is a real calendar date, YYYY-MM-DD.
  • remaining.dollars is a whole number of 0 or more.
  • A source with remaining.dollars above 0 has dollarsPerYear above 0, else "a source with money remaining needs a yearly amount".
  • bound.method and bound.reason are non-empty text; bound.cite is a Cite as today (https URL, page, retrieval date).
  • federal.dollarsPerYear equals the largest, over awards.years, of that year's new-construction award homes, times perHome.federal. Else "federal.dollarsPerYear must be the most new-construction homes awarded in one year times perHome.federal".
  • federal holds no uncapped key: the strict object refuses it.
  • state.tier and federal.tier are 1, 2 or 3.
  • Unchanged: ids, retired ids, debt exactly on goBond and cop, City sources summing to city.total, the fiscal year, the award rows, and perHome against AFFORDABLE.

A source whose money has ended stays in the file with its bound, so stored policies that name its pool keep loading. retiredIds keeps its meaning: the ids of sources removed from the file.

Federal tax credits and the ceiling

The ceiling is the most San Francisco won in one year of the award rows: 1,274 new-construction homes in 2024, times $443,108, which is $564,519,592 a year.

Decision: the ceiling is the best year, not the average The award rows give two readings, the average year (980 homes, $434,245,840) and the best year (1,274 homes, $564,519,592). A ceiling below a year the records show was reached would contradict per-record data, so the best year is the ceiling. Neither binds in the measured runs.

The ceiling is what the federal pool receives each year. Like every pool, it pays from all it has received less what is committed, so credits not awarded in their year stay in the pool and can be awarded later, as California carries unused private-activity bond ceiling forward. No yearly limit on awards is added.

From a bound to pools and programmes

baselineFunding builds one pool per source, in today's order: the City sources in file order, then state, then federal-tax-credits. A source's inflows follow its bound.

asOf
The dataset date, the build's asOf.
anniversary k
The day inflowArrivals (src/lib/sim/scenario/funding.ts) gives as the k-th arrival of a yearly inflow from asOf, k from 0: the same month and day k years later, 29 February becoming 28 February in a common year.
the first year
The days from asOf to the day before anniversary 1.
  • none: one inflow { kind: 'yearly', from: asOf, to: null, dollarsPerYear }.
  • ends with on on or after asOf: one inflow { kind: 'yearly', from: asOf, to: day(on), dollarsPerYear }. day(on) is the Day of that date.
  • remaining with dollars above 0: one once inflow on each anniversary k = 0, 1, 2, … of min(dollarsPerYear, left), where left is dollars less the inflows before it, until left is 0.
  • ends with on before asOf, or remaining with dollars 0: the pool has inflows: [].
  • A pool with no inflow has no programme in the baseline. Every other pool has today's one grant programme, from: asOf, to: null.
  • Shares are computed as today, with roundShares over every source, those without a programme included. A dropped programme's share leaves every bundle, so projects go ahead on what is left at lower odds, as when a source is switched off today.
  • No pool has uncapped; the federal pool is built like any other, kind: 'federal', debt: null, leverage: 1.
  • The build check V25 (fundingOutcomes, pipeline/lib/fzp-cal/invariants.ts) holds the rule below.
  • A source's dollarsPerYear of 0 under none or ends still gives its yearly inflow of 0; no arrival is made of it, as today.

A programme keeps to: null under every bound. Ending a programme on its pool's last inflow would strand the last year's money; the pool ends when it is spent, which the step engine handles once pool-closing lands (F3 in the design).

V25's funding rule

fundingOutcomes(cal, live) reports a problem when any of these fails:

  • The programmes are exactly one baseline-<pool id> per pool that has at least one inflow, in pool order, each with pool that pool's id. A pool with no inflow has none.
  • At least one programme exists.
  • Every programme's grant share is above 0.
  • The programmes' shares, in millionths, sum to at most 1,000,000.
  • When every pool has an inflow, they sum to exactly 1,000,000.
  • The messages: "baselineFunding programmes [..] are not one baseline-<pool id> per pool with an inflow, in pool order [..]"; "baselineFunding has no programme"; "baselineFunding programme {id} has a share of 0"; "baselineFunding shares sum to {n} millionths, over 1000000"; "baselineFunding shares sum to {n} millionths, not 1000000".
  • The detail reads "baselineFunding {p} pools, {g} programmes; shares {n} millionths", followed by "; no programme for {ids}" when a pool has none, the ids in pool order joined with ", ".
  • The affordableRoutes part is unchanged.

Provenance, the check and the report

Each pool's provenance entry states its end, or that it has none, with the bound's citation. The pieces:

end(b)
The short form for a label: "ends {on}" (on on or after asOf), "ended {on}" (before), "{$X.X million} left" (remaining above 0), "spent" (remaining 0), "no end".
cited(b)
"(tier {b.tier}; {b.cite.label}, {b.cite.page})".
boundSentence(b)
The bound's sentence in the method, below.
ends, on on or after asOf:
  Ends: the amount is held level from the first inflow to {on}; the last inflow is on {last arrival, YYYY-MM-DD}. {method} {cited}.
ends, on before asOf:
  Ended on {on}: the pool receives nothing and its programme is not in the baseline. {method} {cited}.
remaining, above 0:
  Remaining: {$dollars}, paid at the yearly amount from the first inflow until used, {n} inflows, the last {$last} on {YYYY-MM-DD}. {method} {cited}.
remaining, 0:
  Remaining: nothing; the pool receives nothing and its programme is not in the baseline. {method} {cited}.
none:
  No end: {reason} {cited}. The amount is held level from the first inflow (an assumption, not a forecast).
  • A City entry's label is "{label}: {$X.X million} a year, {fiscal year} ({end})". Example: "City: general-obligation bonds and other debt: $80.5 million a year, FY2024-25 ($260.3 million left)".
  • A City entry's method replaces today's "The amount is held level from the first inflow, with no end (an assumption, not a forecast)." with boundSentence. The inflow sentence ("First inflow on asOf ..., then each anniversary.") stays for a pool with an inflow and is left out for one without.
  • The state entry's label is "{label}: {$X.X million} a year (a lower bound; {end})"; its method is today's, then boundSentence.
  • The federal entry's label is "{label}: at most {$X.X million} a year ({end})"; its method is the file's federal.method, the award sentence, the share sentence, boundSentence, then "FY2024-25 dollars, not adjusted."
  • The federal entry's n is the number of new-construction award rows and its window is the award window, from 1 January of the first award year to 31 December of the last.
  • Each entry's sources are today's, then the bound's cite as "{label}, {page}" with its URL, unless an existing source has the same label and URL.
  • Each entry's tier is the larger of 2 and the bound's tier.
  • A fixture build marks every entry tier 4 with the "Fixture (tier 4): " prefix, as today.

The check is kept and reads the first year:

  • For each pool with a programme and a share above 0, its implied homes a year is its first year's dollars divided by (share times the uncovered cost).
  • impliedHomesPerYear is the least of those, rounded half up. The federal pool counts like any other.
  • The check's method begins "Implied: over the pools with a programme and a share above 0, the least of their first year's dollars ÷ (share × {uncovered}), rounded half up: {n}." and continues as today.
  • fundingWarning's text says "the baseline pools fully fund" in place of "the capped pools fully fund".
  • On the live file the check stays 780 implied against 980 observed, with no warning: the impact-fee balance is above one year's amount, so that pool's first year is its full $34.8 million.

Global constraints

  • Work happens in git worktrees under .claude/worktrees/. Commits follow Conventional Commits. No attribution to an AI anywhere.
  • Code style: 2-space indent, single quotes, no trailing commas, 100 columns.
  • Every Vitest test calls expect.
  • Signoff fails on server stderr, on timing crutches and on a retried flake. Each unit runs npm run lint, npm run check and the Vitest projects its files belong to before it hands back.
  • Port 4173 is shared by every session on this machine. A unit never kills a server it did not start; it waits.
  • Every agent runs every command in the foreground and never ends a turn while something it started is running.
  • Schema changes go through npm run db:generate. Nobody edits a migration.
  • No unit runs npm run signoff: its dataset step fails until the dataset is uploaded. closing runs it once, after the upload.
  • The dataset version changes in this build. The dataset is uploaded once, by closing, from the integration branch, after every unit has merged; no other unit uploads a dataset. reach-check builds one earlier to run the check and uploads nothing.
  • A unit that writes a hashed path regenerates the fixture dataset with npm run pipeline -- fixture and commits it.
  • WCAG 2.2 AA: every new control is at least 24 px and passes expectNoA11yViolations in light and dark.
  • Page text is short. No sentence says what something is not.
  • Nothing on the main screen says "RHNA". The goal is read from the Goal value, never from a constant.
  • The game's rules are read from src/lib/game/. No component compares a level to a number.
  • One future: no seed control, no band, no average over runs.
  • Published plans and policies, their ids and their pages keep working, including every policy published before this build.
  • A number that is a claim about the world carries its source and tier, in the existing Sourced, Unsourced and Evidence shapes.
  • A runtime dependency that ships in the bundle gets a credit in SOFTWARE. This build adds none.
  • CSP changes are interface changes. This build makes none.
  • Timing is measured only on a quiet machine. A unit that cannot get one defers the measurement and says so.
