City net design

The city feed carries, per project row, the homes the project replaces, from the worker through the map's validation and store to the page's index.

Purpose

A drop in a run is worth the project's net new homes (call 2). The page gets one record per project today, the CityDelta marker, and it has gross homes only. This unit adds the homes each project replaces, so that the run-play and game-sim units can price a drop at homes - existing with no new message.

  • It carries call 2: a drop is worth net new homes, the same kind of number the goal counts.
  • It carries call 3 by what it leaves out: no income tiers per project.
  • It carries the global constraint "one future": the field is read from the world the series reads, and nothing about it flows back to the worker.
  • It produces row E1 and needs no row.

existing
Per changed row: the homes the project takes off the goal's count, capped at 65,535. That is the homes on its lot once it has entered construction after the dataset date, and 0 otherwise.
  • homes - existing of a completed row is that row's effect on the series' completedNet.
  • A row whose marker has not begun carries 0, as homes does.
  • A marker that differs only in existing is a changed marker and is sent.
  • validateCityDelta checks the new array's length.
  • The map's store and the page's index keep it per row.

Unchanged: every other field and rule of the feed.

What the series subtracts

  • On a row's enter into construction on a day after asOf, the series files -p.existing[row] into FRESH (simulated rows) or PIPELINE (every other non-master row) (src/lib/sim/world/score/series.ts:502-509).
  • A row that entered construction on or before asOf has nothing subtracted.
  • On a complete end the series files +units, the row's current units, into the same field (src/lib/sim/world/score/series.ts:541-542).
  • completedNet is PIPELINE + FRESH (src/lib/sim/world/score/series.ts:587).
  • The series' asOf is ScoreStatics.asOf (src/lib/sim/world/score/series.ts:240), the same dataset date as the world's.
  • The goal's measure is view.baseline.completedNet + view.rows[i].completedNet (src/lib/goal/goal.ts:42-46).
  • A row's whole effect on completedNet is therefore its units when it completes, less p.existing[row] when it entered construction after asOf.

Design

The value of existing

A marker's existing is exactly what the series takes off completedNet for that row by the marker's day.

// in markerOf, after homes, with s = scheduleAt(world, statics, row, day) not null
const built = s.entered.construction;
if (built !== undefined && built > statics.asOf) {
  m[EXISTING] = Math.min(MAX_HOMES, Math.max(0, s.existingUnits));
}
  • The source is Schedule.existingUnits from scheduleAt, which is the world's column existing. The feed reads no other column.
  • A row that entered construction after statics.asOf, on or before the marker's day, carries its existing homes.
  • A row that entered construction on or before statics.asOf carries 0. Its homes were replaced before today, and the goal counts its full units.
  • A row that has not entered construction by the marker's day carries 0.
  • A row that has not begun (scheduleAt is null) carries 0, as homes does.
  • The value is capped at 65,535 and a value below 0 is sent as 0, as homes is.
  • An exited row that entered construction after asOf keeps its existing: the series took those homes off too.
  • With no cap reached, for the rows that have a marker, at any day D the feed reads: the sum of homes over markers completed on or before D, less the sum of existing over every marker, equals those rows' share of completedNet at D.
  • For a completed marker, homes - existing is the row's whole effect on the goal's measure, which is R1's worth.

markers()
The method the game-sim unit reads to build R1's Marker objects.
  • It lists every row below the store's length whose has is set, in ascending row order, completed or not.
  • completed is days[3 × row + CITY_DAY.completed], NaN as stored.
  • lngLat is a new two-element array per item.
  • It reflects every update applied so far, including a from that forgot rows.
  • It does not change sorts and does not mark the order stale.
  • Its cost is one pass over the store's rows: about 30,000 objects on the live city. A caller reads it once per run, not per frame.
  • ActivityEvent, recent and apply are unchanged. Activity's list keeps showing gross homes.

The game-sim unit maps one item to R1's Marker as follows. The mapping is that unit's code, shown here so both sides agree.

Decisions

  • Read through scheduleAt. Schedule.existingUnits is the column the series reads, and reading it from the schedule keeps the marker on the one read the cells are packed from.
  • Layout: EXISTING at 6, FLAGS moves to 7. The values stay in the wire's field order.
  • Cap and clamp as homes. Same type, same rule, so the two subtract cleanly.
  • An absent existing throws RangeError. A delta built to the contracts unit's optional shape then fails with the feed's own error, not a TypeError.
  • The debug snapshot is unchanged. Its counts do not depend on the new field, and the controller is outside this unit's write set.
  • The accessor is ActivityIndex.markers(): CityMarkerRow[]. An array of every held marker is the simplest thing planDrops can iterate, and filtering by completed day belongs to R1.
  • The accessor's item is not R1's Marker. src/lib/timeline does not import the game; game-sim maps it in one line.
  • ActivityEvent is unchanged. Activity's text shows gross homes today, and changing it is not asked for.
  • The synthetic timeline carries 0. It has no dataset date to compare construction with.
