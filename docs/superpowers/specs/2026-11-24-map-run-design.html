Map run view

One handle method fits the map to the whole city, flat and north up, locks it for a run, and puts the camera back afterwards.

Purpose

During a run every drop must be on screen and reachable by the collecting ring. The map therefore shows the whole city, flat and north up, and nothing the player does with the pointer, wheel, fingers or keys moves it.

  • It carries composer call 14: the run view is flat and north up, fitted to the city, so every drop is reachable and nothing hides behind a tower.
  • It carries composer call 19 on the map's side: during a run the map is the flat basemap and the drops; at the fitted zoom existing buildings do not draw and bars are faint or absent (What shows at the fitted zoom).
  • It carries composer call 13 on the map's side: the map gains only a run view. Drops are drawn by run-play on its own canvas.
  • It produces row M1. It needs no row.
  • It is the second part of one lane with city-net, which writes other lines of src/lib/map/types.ts and docs/dev/map-interfaces.md: city-net, then map-run (design, sec-write-sets).
  • Its only consumer is game-sim, which calls setRunView(true) as a run starts and setRunView(false) when it ends.

  • true: the map remembers its camera, jumps to the whole city, flat and north up, and locks.
  • Locked: no drag, wheel, pinch, double click, key or control moves the camera, and the canvas container has touch-action: none.
  • Locked: hover picks, taps and clicks are not made or delivered, and no tooltip or card shows.
  • Locked: the map's bounds and zoom floor are lifted so the city fits a small box. They return at unlock.
  • Locked: a resize or a change of the bottom inset fits again.
  • false: the map unlocks and jumps back to the remembered camera.
  • The jump is not animated.
  • A call with the value already in force does nothing.
  • The state survives a remount of the map, as the pan state does.
  • The fit keeps the city inside the map box less the bottom inset.

Design

The fitted camera

// src/lib/map/camera.ts (added)
import { SF_GRID_BBOX } from '$lib/transit/grid';

/** The run view fits this: mainland San Francisco, the transit grid's extent. */
export const RUN_BOUNDS: BBox = SF_GRID_BBOX;
/** CSS px kept clear between the city and each side of the box less the bottom inset. */
export const RUN_PAD_PX = 24;
/** The lowest zoom the run view jumps to. */
export const RUN_MIN_ZOOM = 8;

/** The run view's frame for a map box of this size and bottom inset, in CSS px. */
export function runFrame(widthPx: number, heightPx: number, bottomInset: number): CameraFrame;
RUN_BOUNDS
The box the fit keeps on screen.
runFrame
A pure function. It needs no map.
  • The free width is widthPx - 2 * RUN_PAD_PX. The free height is heightPx - bottomInset - 2 * RUN_PAD_PX.
  • The bounds' size in world px at zoom 0 is their Web Mercator span times 512, MapLibre's tile size.
  • The zoom is log2 of the smaller of free width over the bounds' zoom-0 width and free height over their zoom-0 height.
  • The zoom is never below RUN_MIN_ZOOM. When the free width or height is 0 or less, the zoom is RUN_MIN_ZOOM.
  • The centre is the bounds' centre in Web Mercator, unprojected: [-122.4352, 37.77023] to 5 decimals.
  • The pitch is 0 and the bearing is 0.
  • The map's bottom padding is the inset, so a jumpTo with this centre puts it in the middle of the box less the inset, and the fit is 24 px clear of each of its sides.

  • Every box above except the desktop full-height ones needs a zoom below CONSTRAINTS.minZoom (11). A phone always does.

Zoom floor and bounds while locked

  • While locked the map's minimum zoom is RUN_MIN_ZOOM and it has no maxBounds.
  • Lifting maxBounds is required, not only lowering the minimum zoom. MapLibre raises the zoom until maxBounds covers the whole box. On a 375 by 600 box that is zoom 11.12, where the city is 508 px wide and does not fit.
  • On unlock the minimum zoom is CONSTRAINTS.minZoom again and maxBounds is CONSTRAINTS.maxBounds again.
  • When the fit wants a zoom below RUN_MIN_ZOOM, the map jumps to RUN_MIN_ZOOM at the centre. The city is then wider or taller than the box and its edges are cut. This happens only for a box whose free width is under about 59 px or free height under about 57 px.
  • The maximum zoom and maximum pitch are not changed.

Handle state

// SimMap.svelte: handle state that outlives a remount, beside panEnabled
let runView = $state(false);
let remembered: CameraFrame | null = null;
runView
The value of the last setRunView call; false at mount. Reactive because the markup reads it.
remembered
The camera to go back to on unlock: centre, zoom, pitch and bearing. Null while unlocked.
  • remembered is taken when the lock first meets a map: at setRunView(true) when a map exists, otherwise when the next map is created.
  • It is read as map.getCenter(), getZoom(), getPitch() and getBearing(). The centre is the centre of the box less the inset, as MapLibre reports it.
  • Once taken it is not replaced until unlock. A remount while locked keeps it.
  • Unlock clears it.

setRunView(true)

  1. If runView is already true, return.
  2. Set runView to true.
  3. Close any tooltip or card (clearShown) and send one hover miss if a hover hit was last reported (unreportHover).
  4. Forget the resting pointer and any press in progress: live.pointer, live.tap and live.click become null.
  5. If there is no map, stop here. The next map locks itself (see Remount).
  6. Take remembered if it is null.
  7. Apply the handlers (Handlers).
  8. map.setMaxBounds(null), then map.setMinZoom(RUN_MIN_ZOOM).
  9. map.jumpTo(runFrame(container.clientWidth, container.clientHeight, bottomInset)).
  10. Add the class sim-map-run-locked to map.getCanvasContainer().
  11. If the overlay exists, overlay.setProps({ _pickable: false }).

setRunView(false)

  1. If runView is already false, return.
  2. Set runView to false.
  3. If there is no map, set remembered to null and stop. The next map starts at its initial camera, as today.
  4. Remove the class sim-map-run-locked from the canvas container.
  5. If the overlay exists, overlay.setProps({ _pickable: true }).
  6. Apply the handlers.
  7. map.jumpTo(remembered).
  8. map.setMinZoom(CONSTRAINTS.minZoom), then map.setMaxBounds(CONSTRAINTS.maxBounds).
  9. Set remembered to null.
  • The jump comes before the constraints, so a camera that is still lawful lands exactly where it was and the constraints change nothing.
  • If the box was resized or the inset changed while locked, the remembered centre and zoom are kept as they are: the remembered centre sits in the middle of the new box less the new inset, at the remembered zoom, pitch and bearing. The constraints set after the jump then clamp the camera as MapLibre clamps any camera, so a box grown past maxBounds at that zoom gets a higher zoom.
  • No camera is computed from the old box size.

Handlers

applyPan becomes applyInteraction, the one function that sets MapLibre's handlers from both switches. setPanEnabled, setRunView and start call it; nothing else touches a handler.

function applyInteraction(): void {
  const m = live?.map;
  if (!m) return;
  if (runView) {
    m.dragPan.disable();
    m.dragRotate.disable();
    m.scrollZoom.disable();
    m.boxZoom.disable();
    m.doubleClickZoom.disable();
    m.keyboard.disable();
    m.touchZoomRotate.disable();
    m.touchPitch.disable();
    return;
  }
  m.scrollZoom.enable();
  m.boxZoom.enable();
  m.doubleClickZoom.enable();
  m.keyboard.enable();
  m.touchZoomRotate.enable();
  m.touchPitch.enable();
  if (panEnabled) {
    m.dragPan.enable();
    m.dragRotate.enable();
    m.touchZoomRotate.enableRotation();
  } else {
    m.dragPan.disable();
    m.dragRotate.disable();
    m.touchZoomRotate.disableRotation();
  }
}
  • Locked, all eight handlers are off, whatever panEnabled is.
  • Unlocked, the five that setPanEnabled never touched are on, which is MapLibre's default and today's state, and the three it owns follow panEnabled as today.
  • setPanEnabled while locked stores panEnabled and, when false, closes a tooltip or card, as today. The handlers stay off. The value takes effect at unlock.
  • setRunView(false) never turns the pan handlers on while panEnabled is false.
  • touchZoomRotate.disable() also stops MapLibre's one-finger tap-and-drag zoom; doubleClickZoom.disable() stops double click and double tap.

Controls, touch and cursor while locked

  • The root carries data-run-view="on" while runView is true and no such attribute otherwise. It is set from mount, with or without a map.
  • The bottom-left control container is hidden while locked, so the zoom buttons and the compass can be neither seen, pressed nor reached by Tab. Its rule is below.
  • The "Reset view" button is not rendered while locked: its condition becomes coarse && mapState === 'ready' && !runView. resetView returns at once while runView is true.
  • The credit stays shown and works as today. It moves no camera.
  • The canvas container gets touch-action: none and cursor: default from the class sim-map-run-locked. A class, not an inline style, so the brush's inline '' on the same element cannot undo it.
  • The jumps fire zoomstart with no originalEvent, so they do not collapse the credit.

Hover, taps, tooltips and cards while locked

  • No hover pick runs. onPointerMove sets live.pointer to null, closes a tooltip, calls unreportHover and returns when runView is true.
  • hoverSoon's frame callback returns without picking when runView is true, so the moveend of the lock's own jump picks nothing.
  • onPointerDown records no tap and no click while locked. Touch pointers are still counted.
  • onPointerUp delivers nothing while locked. A press that began while locked is never delivered, even if it ends after unlock.
  • timelinePick receives nothing while locked except the one hover miss sent at the lock.
  • deck.gl's own picking is off while locked: the overlay has _pickable: false. So no part takes deck's hover highlight, and a pointer moving over the map costs no picking pass.
  • A part highlighted at the moment of the lock keeps deck's highlight until the next pick after unlock. A run starts from a card or button, so the pointer has left the canvas and deck has cleared it before the lock.
  • pickAt itself is unchanged. The e2e debug's timelinePartAt finds no part while locked, because deck picks nothing.
  • After unlock, hover picks start at the next pointer move over the canvas.

A resize or a new inset while locked

  • SimMap listens to the map's resize event from start. While runView is true it jumps to runFrame for the new box.
  • setBottomInset while locked sets the padding as today, then jumps to runFrame with the new inset.
  • remembered is not changed by either.

Remount and calls before the map exists

  • setRunView before the map exists stores the value and returns. It never throws, in any mapState.
  • In start, where applyPan() is called today, the new map calls applyInteraction(). Then, when runView is true, it takes remembered if it is null, lifts the bounds and floor, jumps to runFrame and adds the container class, as steps 6 to 10 of setRunView(true).
  • When the map was created locked before any setRunView(true) met a map, remembered is the map's initial camera (the initialFrame prop, the plan fit or the default frame). Unlock goes there.
  • The overlay is made with _pickable: !runView.
  • A remount while locked keeps remembered from the first map, so unlock goes to the camera the player had before the run.
  • An unsupported or failed map stays so. setRunView changes only the stored value and the root's attribute.
  • A new SimMap component starts unlocked, with no remembered camera. The page that mounts it decides whether to lock it.

Camera events a consumer sees

  • Each jump fires MapLibre's movestart, move and moveend once, with no originalEvent.
  • A consumer that follows moveend (SimPage's readView, src/lib/sim-page/SimPage.svelte:847-852) sees the whole city's bounds at the lock and the remembered view at the unlock.
  • map.project during a run gives positions in the fitted camera, so run-play's project may call it once per frame and cache nothing across a resize.

The timeline in one pair of layers while locked

While the run view is on, the timeline controller draws every cell's parts in one solid layer and one ghost layer, in place of one pair per cell. The run view shows the whole city, so the per-cell pairs (about 124 cells on the live city, four draws each with the extruded sides and tops) would cost about 500 draws a frame, and every frame redraws because the run's clock moves the day.

// src/lib/map/timeline-controller.ts (added)
/** One merged solid and ghost layer over every cell while on; per-cell layers while off. */
setMerged(on: boolean): void;
  • SimMap's setRunView(true) calls setMerged(true) on the timeline controller once the map and controller exist, and setRunView(false) calls setMerged(false). A controller made while locked starts merged. A call with the value already in force does nothing.
  • Merged, the controller emits timeline-solid-run and timeline-ghost-run: the same SolidPolygonLayer props, TimelapseExtension, uniforms and clock as the per-cell layers, over the cells' binary attributes joined in cell-id order. Bars, marks and the overlay layers follow as they do unmerged, in the same order.
  • The picture is the per-cell layers' picture: same geometry, same parts, same extrusion, and the same two passes in the same order, every solid, then every ghost. The solid pass is the same pixel for pixel, since solids are opaque and write depth. Within the ghost pass the merged layer draws every cell's sides, then every cell's tops, where the per-cell layers draw each cell's sides and tops in turn; ghosts are translucent and write no depth, so where the ghosts of two cells overlap on screen they blend in that other order. At the run view's pitch 0 a side face projects to about one pixel or less, so the difference is confined to slivers of about one pixel where neighbouring cells' ghosts meet. No other pixel differs.
  • Merged layers are not culled per cell; the fitted view holds the whole city, so culling would keep every cell anyway.
  • The joined attributes are built once when merging starts and again after each applyTimeline that changes a cell while merged. A setTime joins nothing.
  • Unmerged, the controller emits per-cell layers exactly as it does with no run view, so per-cell picking and culling work as before. A cell update while merged is held in the per-cell state too, so unmerging needs no rebuild of a cell.
  • Picking is off while locked (Hover, taps, tooltips and cards), so a merged layer never answers a pick, and TIMELINE_PART_LAYER still names only per-cell layer ids.

Performance

  • No existing bench case calls setRunView, and the unlocked map runs the same per-frame code as today.
  • The implementer runs npm run bench:map once after the change, on a quiet machine, with the preview on port 4173 started by that session or already running. Every case must keep p95 at or under 16.7 ms.

Decisions

  • The fit uses SF_GRID_BBOX, not CONSTRAINTS.maxBounds. It is the mainland city's extent, where lots and so drops are; maxBounds is a pan limit with water around it, about 1.4 times as wide, which would shrink the city on a phone for nothing.
  • Padding 24 px on each side. It keeps a drop at the city's edge clear of the box's edge and the ring's reach, and is the project's target size.
  • The lifted floor is 8. Every box a page shows fits above it; it only guards a box squeezed to near nothing.
  • The fit is computed by a pure runFrame, not by map.cameraForBounds. It can be unit tested without a map, and cameraForBounds returns nothing for a box smaller than its padding.
  • Unlock jumps first and restores the constraints after. A lawful camera then lands exactly, and a stale one is clamped by MapLibre's own rule.
  • The zoom buttons and compass are hidden, not removed. A style rule keyed on the root's attribute needs no control instance kept across a remount.
  • The root carries data-run-view="on". The style rule needs a hook, and e2e specs in closing can read it.
  • touch-action comes from a class. The brush writes the same element's inline style; a class cannot be undone by it.
  • The cursor is default while locked. MapLibre's grab cursor would say the map can be dragged.
  • The timeline draws as one solid and one ghost layer while locked. A per-cell pair costs four draws and per-draw uniform setup on every frame of a run; the whole city's cells would put the run's frame over the map's bar. Joining the cells keeps the picture, apart from the blend order of overlapping ghost slivers of about one pixel, and drops the draws to a handful; no small number of draws can keep each cell's sides and tops together. Per-cell layers return at unlock because picking and culling need them.
  • deck's picking is off while locked. Otherwise deck highlights parts under the ring and runs a picking pass on every pointer move, which no bench case measures.
  • A press begun while locked is never delivered. A tap is a whole gesture; half of it was made on a locked map.
  • "Survives a remount" means a remount by a new manifest inside one SimMap, as the pan state does; a new SimMap component starts unlocked.
