## 2. Interfaces

Rows owned or consumed, verbatim:

| # | interface | owner → consumers | mark |
|---|---|---|---|
| I12 | Data manifest: `/data/<datasetVersion>/manifest.json` → `{ datasetVersion, builtAt, sources: { id, url, retrievedAt, license }[], chunks: { cellId, bbox, url, parcelCount }[], buildingsTiles: url, basemapTiles: url, glyphs: url /* MapLibre `{fontstack}/{range}.pbf` template */, sprite?: url, neighborhoods: url }`. All `url`s are root-relative (`/data/<v>/…`). Every eligible-or-not parcel appears in **exactly one** chunk. `buildingsTiles` has one source-layer `buildings` with properties `parcelId`, `heightM`, `baseM`, at minzoom ≤ 12, with buildings clipped to parcels. Published versions are immutable and retained indefinitely. `datasetVersion` matches `^(\d{4}-\d{2}-\d{2}-[0-9a-f]{8}\|fixture-\d+)$` (build date + 8-hex input hash) everywhere it is validated. R2 key = `data/<datasetVersion>/<path>`, served at `/data/<datasetVersion>/<path>` | data-pipeline → platform, plan-model, brush-tool (worker host), typology-generator, map-view | DC |
| I13 | Share API: `POST /api/plans` (body: `Plan`, ≤ 256 KB) → `{ id }`; `GET /api/plans/:id` → `Plan`; page `/p/:id`. Ids are 8-char base58. Status codes and error bodies are as defined in the plan-sharing spec | plan-sharing ↔ platform | DC |
| I16 | Dataset version discovery: the worker var `PUBLIC_DATASET_VERSION` names the current version for new plans. A **published** plan (`/p/:id`) renders on **its own** `plan.datasetVersion`, with an "Open with current data" action that remixes onto current. A **locally autosaved** plan is rebased to current on load: strokes are version-independent, so `datasetVersion` is rewritten and the plan re-resolved, with a one-line notice if the version changed (`manifestUrl = /data/${v}/manifest.json`). map-view and the worker host take the manifest as a parameter, never a global. If that version's manifest 404s, fall back to current and show the plan-sharing "older data" notice | platform → plan-sharing, brush-tool, map-view | DC |

Platform consumes I12 (serves it; reads `sources` for `/attribution`). For I13 platform
supplies the D1 binding, the rate-limit binding, the Drizzle schema location and migration
pipeline; `plan-sharing` owns the routes. Platform owns I16: it defines
`PUBLIC_DATASET_VERSION` (§4.3); the per-plan pinning and 404 fallback are carried out by
its consumers (plan-sharing, the brush-tool worker host, map-view).

## 3. Global constraints (verbatim)

- **Free and open source.** No paid APIs and no vendor keys are needed to run
  or build it. Licence: MIT for code (OD-3). Data attribution is shown in-app
  (ODbL for the OSM/Protomaps basemap and Overture, PDDL/public domain for
  DataSF).
- **Determinism.** The same `Plan` + `datasetVersion` gives the same buildings
  and the same score, on every machine.
- **Overshoot is meaningful.** No readout caps at 100% of a target.
- **Honesty of numbers.** Every unit count is labelled with what it is (M1:
  *theoretical max buildout*). Net counts are shown, not gross. Sources and
  vintages are visible.
- **Performance targets.** Existing-city view pans at 60 fps on a 2022-era
  laptop. Generated buildings appear within 150 ms of pointer-up for strokes
  covering ≤ 500 parcels. A whole-city repaint (≈150k parcels) finishes within
  5 s, off the main thread. The first meaningful paint transfers ≤ 5 MB (parcel
  chunks load lazily under the brush).
- **Mobile works.** Touch painting uses an explicit mode switch. Layout works
  at 375 px.
- **Data is static and versioned.** The worker does no geo computation at
  runtime.
- **Cross-project conventions apply:** Conventional Commits, worktrees for all
  work, bare-name Cloudflare resources (`sfhousing`), and the migration
  workflow via Drizzle.

### 4.3 Current dataset version

The current dataset is `env.PUBLIC_DATASET_VERSION`, exposed to the client by the root
`+layout.server.ts` as `data.datasetVersion` (and to non-page code via
`$env/dynamic/public`). Changing it is a one-line `wrangler.jsonc` PR; the data-pipeline's
upload command prints that line. No mutable R2 pointer exists. In local dev, `.dev.vars`
may override it; e2e builds set it to `fixture-0`.

Per I16, this var names the version for **new** plans only. A loaded plan uses its own
`plan.datasetVersion` (`manifestUrl = /data/${v}/manifest.json`); if that manifest 404s,
the consumer falls back to the current version and plan-sharing shows its "older data"
notice. Because published versions are immutable and retained indefinitely (I12), that
404 should only occur for a version that was never uploaded. Platform passes the version
as data, never as a client global the map or worker reads implicitly.

### 4.4 `/data/<datasetVersion>/*` route

File: `src/routes/data/[version]/[...path]/+server.ts`, exporting `GET`, `HEAD`, `OPTIONS`.
R2 key = `data/<version>/<path>` (URL and key mirror each other; the data-pipeline must
upload to exactly these keys).

**Path validation** (before any R2 call): `version` matches `DATASET_VERSION_RE`; `path`
is 1–256 chars, each `/`-segment matches `^[A-Za-z0-9._-]+$` and is neither `.` nor `..`.
Failure → **404** (not 400; nothing to reveal), body `Not found`, `Cache-Control: no-store`.

**GET:**
1. If the request has a `Range` header with a comma (multi-range) → ignore Range (serve 200 full body; RFC 9110 permits).
2. `obj = await BUCKET.get(key, { range: request.headers, onlyIf: request.headers })`
   (V — `R2GetOptions.range`/`onlyIf` accept `Headers`, developers.cloudflare.com/r2/api/workers/workers-api-reference/).
3. `obj === null` → **404**, `Cache-Control: public, max-age=60` (a version uploaded later
   becomes visible within a minute; versions are never partially uploaded on purpose — the
   pipeline uploads `manifest.json` last).
4. Object without `body` (precondition failed) → **304** if the request carried
   `If-None-Match`, else **412**. ETag + cache headers still set.
5. Object with body and `obj.range` set and the request had a satisfiable single Range →
   **206**, `Content-Range: bytes <start>-<end>/<size>`, `Content-Length: <end-start+1>`.
   Otherwise **200**, `Content-Length: <size>`.
6. Unsatisfiable range (R2 throws on a range starting at/after `size`, I) → **416**,
   `Content-Range: bytes */<size>` (size via `BUCKET.head`).

**Headers on every 200/206/304/412:**
- `ETag: obj.httpEtag`; `Accept-Ranges: bytes`; `Last-Modified: obj.uploaded`.
- `Cache-Control: public, max-age=31536000, immutable` (interplanetary
  `src/routes/api/maps/[bodyId]/+server.ts:19`, V).
- `Content-Type` by extension, overriding stored metadata: `.json`→`application/json`,
  `.geojson`→`application/geo+json`, `.pmtiles`→`application/vnd.pmtiles`,
  `.pbf`/`.bin`→`application/octet-stream`; unknown → stored `httpMetadata.contentType`, else
  `application/octet-stream`. No `Content-Encoding` is invented; if the pipeline stored a
  pre-compressed object it sets `contentEncoding` and `writeHttpMetadata` passes it through.
- `Access-Control-Allow-Origin: *`, `Access-Control-Expose-Headers: Content-Range, Content-Length, ETag, Accept-Ranges`
  — the data is open (R5/R6); third parties may range-read it.
- `X-Content-Type-Options: nosniff`.

**HEAD:** `BUCKET.head(key)`; same status/headers as a 200 GET, no body.
**OPTIONS:** 204, `Access-Control-Allow-Methods: GET, HEAD, OPTIONS`,
`Access-Control-Allow-Headers: Range, If-None-Match, If-Match`, `Access-Control-Max-Age: 86400`.
**Other methods:** 405 with `Allow: GET, HEAD, OPTIONS` (SvelteKit default, I).

No Worker Cache API use in M1 (internal choice; the Cache API does not store 206s, I). Browser
caching is driven by `immutable`. The route does no parsing or geo work on object bodies.

`BUCKET` missing (misconfig) → **503** `Data storage unavailable` (interplanetary :6–9 pattern).

**Local data.** `npm run data:local -- <datasetVersion> [--from <origin>]` fetches
`<origin>/data/<v>/manifest.json` (default origin `https://sfhousing.mindlace.net`), then every
URL it names, and `wrangler r2 object put sfhousing/data/<v>/<path> --local --file …`. Keyless.
For tests, a fixture dataset with `datasetVersion` **`fixture-0`** lives in
`e2e/fixtures/data/fixture-0/` (manifest, chunks, a tiny buildings PMTiles, basemap PMTiles,
glyphs, neighborhoods; produced by data-pipeline's `pipeline fixture`) and
`npm run data:fixture` loads it into local R2. It is the single e2e dataset that every
subsystem's Playwright tests run against.

## 7. Acceptance criteria

1. `npm ci && npm run check && npm run lint && npm test` pass on a fresh clone with no
   Cloudflare credentials and no network beyond npm.
2. `package.json` ranges equal §4.1; `.nvmrc` is `24`.
3. `wrangler.jsonc` declares exactly bindings `DB`, `BUCKET`, `PUBLISH_RL`, `ASSETS` (plus vars)
   in both envs; no DO, KV, queue, AI, or analytics bindings.
4. `GET /data/<v>/<file>` with a single satisfiable Range returns 206 with a correct
   `Content-Range`; without Range returns 200; both carry
   `Cache-Control: public, max-age=31536000, immutable` and an ETag.
5. A path containing `..` or an invalid version returns 404 without touching R2 (asserted via fake call log).
6. Push to main deploys to `https://sfhousing-staging.mindlace.net` after applying staging
   D1 migrations; merging a release PR deploys the tag to `https://sfhousing.mindlace.net`.
7. `/attribution` lists every `manifest.sources` entry and all fixed notices; `/about`
   states "theoretical maximum buildout" and both RHNA numbers; `LICENSE` is MIT.
8. axe gate passes on `/`, `/about`, `/attribution`, 404, at desktop and 375 px.
9. `CLAUDE.md` indexes every `docs/dev/*.md` file that exists.

   for new plans; loaded plans pin their own.
