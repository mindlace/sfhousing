Design

The journey

e2e/game-journey.spec.ts is the one e2e spec that crosses units: Paint and the shell (game-shell), the store and the win card (game-core), /sim under the game (game-sim) and the account save (game-save). It binds to the design doc's rules and texts. Its selectors are the test ids and roles that the game-core, game-shell, game-sim and game-save specs under docs/superpowers/specs/ fix; the operator reads those four specs and the merged code for them. At the time of writing they include win-card, paint-win, header-level, header-level-panel, header-level-up, level-panel, sim-locked, tl-win and tl-to-beat.

Two goal amounts, both constants at the top of the spec with a comment that says how each was found:

PAINT_AMOUNT
1: any stroke that adds a home wins Paint.
SIM_AMOUNT
The homes current law reaches on fixture-0 at month 60, read once as goal.measure.valueAt(run.view, 60) on the run that runEmptyDocument of scripts/level2-check.ts returns for e2e/fixtures/data/fixture-0, with the goal of defaultGoal(run.asOf), so level 2 is won after some play and inside the window.

The one test, in order, on every Playwright project (paintOnce handles the phone layout):

  1. newVisitor(page) and seedGoalAmount(page, PAINT_AMOUNT); open /.
  2. The header's level cell reads "Level 1"; the Simulate step is not a link.
  3. Paint one stroke with paintOnce. The header says "Goal reached" and the win card shows, naming the simulation as the unlock, with "Level up" and "Keep playing".
  4. Write SIM_AMOUNT under E2E_GOAL_KEY with page.evaluate (X1), then press the win card's "Level up". Paint opens /sim with a client-side navigation, and /sim reads the amount when it mounts. The level cell reads "Level 2"; no "+" is offered on any kind.
  5. Play to the goal with the existing run helpers (e2e/helpers/run.ts), waiting on the debug hook, never on time. The win card shows "Goal reached in {month}" and names Permitting as the unlock.
  6. Press the win card's "Level up". The level cell reads "Level 3"; the playhead is at today; Permitting offers "+"; Zoning's lane says "Unlocks when you level up"; Public money's says "Unlocks at level 5".
  7. The bar shows: the level panel says "Beat {month}" with the month level 2 was won in, and the ruler carries the "To beat" flag.
  8. The account exists: the header's account entry shows an @handle, which comes from game.sync.account after the save that made the account (S2); no page data is reloaded and /sim keeps its playhead.
  9. page.request.get('/api/game') answers 200, and its saves hold one game at level 3 (polled with expect.poll until the level-up's save has landed).
  10. Reload /sim: the level cell still reads "Level 3" and the "To beat" flag is still there.
  11. expectNoA11yViolations on /sim at level 3 with the win card closed.
  • Nothing in the spec waits a fixed time or raises a timeout; every wait is a readiness signal.
  • It needs nothing new from any helper: newVisitor, seedGoalAmount, paintOnce, gotoHydrated and the run helpers exist by then.
  • A step the merged code cannot pass is a defect of the unit that owns that behaviour; the operator reports it with the step and the owner unit.

The dated measure

A second test in e2e/game-journey.spec.ts runs the real dateMeasure (M1, funding-measures) through addPolicy and the page (game-sim), which no unit's own tests join. On every Playwright project:

  1. seedGame(page, 5); open /sim with gotoHydrated and wait for the first fill on the debug hook (window.__sfhFzp).
  2. Move the playhead three years on: focus the ruler and press Page Down three times. Read the playhead's day from __sfhFzp.day.
  3. Press Public money's "+" and choose "A housing bond", the label of the housing-bond preset in src/lib/sim-page/funding-presets.ts.
  4. Read the document from __sfhFzp.policy once the page is no longer stale (__sfhFzp.stale false).

What it asserts on the new policy, found as the money policy whose preset is housing-bond:

  • Its first span starts in the model month that holds the playhead's day, at most one month before it and no later than it (a new policy starts on the playhead's model month). Call that first day start; it is more than two years after __sfhFzp.asOf.
  • Its pool's first money-in, read from the first span's effect, is dated start: the bond's one-time principal arrives in the month the policy starts (M1: "A given measure's first payment falls on the first day of its first span").
  • Its label is "A housing bond" and its preset is the preset's id (G3).
  • The bar of the policy on the Public money row is named with "A housing bond" and the span's start date (barLabel).
  • The forecast's use of a dated money-in is proved by the engine's own tests; this test proves the dates the page sends.
  • The field names inside the effect are those of src/lib/timeline/policy4.ts on the merged tree; the operator reads them there and in the funding-measures and game-sim specs.
  • A failure is reported against game-sim (the call from addPolicy) or funding-measures (the dates dateMeasure writes), as the asserted field shows.

The finish: checks, build, check, upload

The operator's worktree is branched from the integration branch after every other unit has merged into it. A comment rewritten under a path in PATHS (for example under pipeline/) changes the dataset version; so after the leftovers are committed the operator runs npm run pipeline -- fixture and commits any change it makes, as the global constraint for hashed paths requires.

  1. Merge the main line: git fetch origin, then git merge origin/main. A conflict stops the unit and is reported.
  2. Write the journey, the leftovers and the docs. Commit. Regenerate the fixture with npm run pipeline -- fixture and commit it when it changed.
  3. Run the full-tree checks (below). Every one passes before going on.
  4. Print the version: npm run pipeline -- version. Call it <v>.
  5. Note whether <v> is already published: npx tsx scripts/dataset-version.ts --check exits 0 when it is. Steps 6 to 9 run either way, so the level 2 check always runs.
  6. If pipeline/.cache is missing: npm run pipeline -- fetch --restore.
  7. Build: npm run pipeline -- build, without --skip-tiles. Every invariant passes.
  8. Check: npm run pipeline -- check <v>.
  9. The level 2 check: npx tsx scripts/level2-check.ts pipeline/out/<v>. Exit 0 goes on. Exit 1 or 2 stops the unit with nothing uploaded (When it fails).
  10. Upload, only when step 5 found <v> unpublished: npm run pipeline -- upload <v>. Then, always, verify: npm run pipeline -- verify <v> --origin https://sfhousing-staging.mindlace.net.
  11. Published is proved by npx tsx scripts/dataset-version.ts --check exiting 0, after verify has found every file the manifest names.
  12. Signoff: npm run signoff, the build's only run of it (no other unit runs it, because its dataset step fails until the upload). Nothing is pushed by hand first. If signoff's merge of origin/main changes <v>, the dataset step fails; go back to step 4, and the level 2 check runs again on the new build.
  13. Hand back with <v>, the check's three lines and the signoff result. Merging the integration branch to main is the conductor's.
  • Only this unit uploads a dataset in this build, and only at step 10.
  • A published version is immutable, so the order is fixed: the level 2 check always runs on the exact directory that is then uploaded.

When the level 2 check fails

The failure rule is reach-check's, applied to this unit's dataset:

  • Nothing is uploaded and signoff is not run. The built pipeline/out/<v> stays on disk.
  • The unit hands back "blocked: current law misses the goal" with the check's three lines, the homes at the window's end beside the amount, and the bounds funding.json holds for city-impact-fees and state. The conductor takes it to the owner: the remedy is the owner's (D1).
  • The unit changes no code, data or window length to make the check pass.
  • An exit 2 is reported with its stderr line and is not an answer about D1.

Global constraints

  • Work happens in git worktrees under .claude/worktrees/. Commits follow Conventional Commits. No attribution to an AI anywhere.
  • Code style: 2-space indent, single quotes, no trailing commas, 100 columns.
  • Every Vitest test calls expect.
  • Signoff fails on server stderr, on timing crutches and on a retried flake. Each unit runs npm run lint, npm run check and the Vitest projects its files belong to before it hands back.
  • Port 4173 is shared by every session on this machine. A unit never kills a server it did not start; it waits.
  • Every agent runs every command in the foreground and never ends a turn while something it started is running.
  • Schema changes go through npm run db:generate. Nobody edits a migration.
  • No unit runs npm run signoff: its dataset step fails until the dataset is uploaded. closing runs it once, after the upload.
  • The dataset version changes in this build. The dataset is uploaded once, by closing, from the integration branch, after every unit has merged; no other unit uploads a dataset. reach-check builds one earlier to run the check and uploads nothing.
  • A unit that writes a hashed path regenerates the fixture dataset with npm run pipeline -- fixture and commits it.
  • WCAG 2.2 AA: every new control is at least 24 px and passes expectNoA11yViolations in light and dark.
  • Page text is short. No sentence says what something is not.
  • Nothing on the main screen says "RHNA". The goal is read from the Goal value, never from a constant.
  • The game's rules are read from src/lib/game/. No component compares a level to a number.
  • One future: no seed control, no band, no average over runs.
  • Published plans and policies, their ids and their pages keep working, including every policy published before this build.
  • A number that is a claim about the world carries its source and tier, in the existing Sourced, Unsourced and Evidence shapes.
  • A runtime dependency that ships in the bundle gets a credit in SOFTWARE. This build adds none.
  • CSP changes are interface changes. This build makes none.
  • Timing is measured only on a quiet machine. A unit that cannot get one defers the measurement and says so.
