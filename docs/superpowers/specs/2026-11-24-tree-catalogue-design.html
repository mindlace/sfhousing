Tree catalogue: nodes, buying, grants, the balance script and the reach measure

The tree's nodes with their prices and sources, what is shown and bought, how a purchase changes the policy document, the script that plays the tree against the engine, and the measurement that fixes the ladder.

Purpose

This subsystem is the tree of the incremental loop: the catalogue that P3 says new levers add to, and the step that turns a purchase into policy.

  • It holds the node data: every node's branch, label, line, adjacency, ring, levels, prices and source (G3).
  • It decides what the tree shows and buys the next level of a node (G3, treeView and buy).
  • It applies a purchase's grant to the policy document, dated from month 1 (G5, applyGrant).
  • It plays the tree against the real engine in several purchase orders and reports pacing (scripts/tree-balance.ts).
  • It measures the earliest year the full tree reaches the goal and derives LADDER_YEARS from it (scripts/reach-measure.ts).
  • It holds every number the balance script tunes in catalogue/tuning.ts: RUNG_LUMP, SIDE_TUNING and the prices (G6, call 25).

Rulings it carries:

  • P1: a node acts on a lever the code already has; the game never changes what a policy forecasts.
  • P3: the tree is data; a new lever is a new entry.
  • P11 and D4: no node offers the painted area, an own pool, the City funding scale or market terms.
  • P12: a grant puts its policy in force from today; switching it off is the document's own switch.
  • Call 4: custom timing and custom route shares are not nodes.
  • Call 5: every measure starts the month it is bought.
  • Call 10 and call 22: deadlines step in by five years toward the measured year, with at most five rungs, so each rung opens a ring.
  • Call 25: every number the balance script tunes is in tuning.ts.
  • Call 16: protections, state-off and federal-credits-off are free and are not nodes.
  • Global constraints: no node invents a value; every preset and measure node names its source.

Interfaces

This subsystem is two parts, built and merged in order. The rows and their sections are copied from the design without change.

  • The code needs G1, G2, G4 and G6, and produces G3 and G5.
  • The measurement needs G1 to G6, and produces T1. Only closing waits on it.

  • A painted area is within the limits only when open (P11).
  • A money policy is within the limits when it is given and its preset is in measures, or its preset is in FREE_MEASURES and measures is not empty. Any other money policy only when open (D4).

  • With OPEN_LIMITS, within is always true.

export function applyGrant(doc: SimPolicy4, grant: Grant, ctx: GrantCtx): SimPolicy4;
limits
The limits after the purchase.
GAME_TRANSIT_ID
The id of the one transit rule the game makes.
  • Every policy the function adds is on, with one span from month 1 and no end.
  • preset and measure: when no policy has that preset, one is added as "+" adds it today. When one exists it is switched on.
  • stop: the game's rule gains the stop type. When there is no such rule, one is added with that stop type and one band at limits.reachM and limits.stories.

  • reach: the outermost band of the game's rule takes the new distance.
  • bands: the game's rule gains a band. Where there is room inside limits.reachM it goes beyond the outermost, as the editor adds one today. Where there is none the outermost band is split in two.
  • A grant whose policy the player removed or changed past recognition adds it again and leaves the player's own policies alone.
  • hands: the document is returned unchanged.
  • The result is within ctx.limits and passes parsePolicy4.
  • The function never removes a policy and never changes one it did not make.

  • settle pays a lump or a side reward only when it also records it, so a result settled twice pays its lump and its side rewards once. The store refuses a second settle of one result (G7).

  • fitGame returns the same object when nothing is dropped or lowered.
  • sideShown returns the first SIDE_SHOWN goals whose ring is open and which are not met.
  • A side goal's read returns null when the view lacks what it reads.

Global constraints

  • One future: the same policy document always gives the same forecast. No game state reaches the worker except through the policy document.
  • No file the dataset version hashes is changed: pipeline, src/lib/config.ts, src/lib/{data,generator,timelapse}, src/lib/plan/{geometry,types}.ts, src/lib/sim/finance (pipeline/lib/version.ts:41). The dataset version stays as it is.

  • The painted area, own pools, the City funding scale and market terms are never offered in a game.
  • Published plans and policies open and play in full, as today.
  • WCAG 2.2 AA: everything works from the keyboard; targets are at least 24 px; motion follows the reduced-motion setting; nothing flashes more than three times a second.
  • Page text is short. A node is a name, a line and a price.
  • The CSP is not widened. Sound is made in the browser; no audio file, font or script is added.
  • A runtime dependency is not added without a credit in src/lib/attribution.ts. None is expected.
  • Code style: 2-space indent, single quotes, no trailing commas, 100 columns.
  • Vitest runs with expect.requireAssertions. Tests are colocated.
  • A schema change goes through npm run db:generate. Migrations are never edited by hand.

Design

The two parts

  • The code: tree.ts, grant.ts, catalogue/nodes.ts, catalogue/play.ts, catalogue/ladder-years.ts and catalogue/tuning.ts with their starting values, and their specs. It produces G3 and G5 and merges first.

  • A node's ring is ringOf(stage): Math.round(stage × (RUNGS − 1) / 4), where RUNGS is LADDER_YEARS.length + 1.

treeView and buy

// src/lib/game/tree.ts (beside the types of G3)
import { affords, shortBy, spend } from './units';
import { NODES } from './catalogue/nodes';

/** The level bought of `node`, 0 for none, never above its last. */
export function levelOf(s: GameState, node: TreeNode): number {
  return Math.min(s.bought[node.id] ?? 0, node.levels.length);
}

/** Its ring is open and it comes after nothing, or after a node that is bought. */
export function isShown(s: GameState, node: TreeNode): boolean {
  if (s.rung < node.ring) return false;
  return node.after.length === 0 || node.after.some((id) => (s.bought[id] ?? 0) >= 1);
}

export function treeView(s: GameState, nodes: readonly TreeNode[] = NODES): NodeView[] {
  return nodes
    .filter((node) => isShown(s, node))
    .map((node): NodeView => {
      const level = levelOf(s, node);
      const next = node.levels[level];
      if (next === undefined) return { node, level, state: 'done', short: null };
      return affords(s.units, next.price)
        ? { node, level, state: 'ready', short: null }
        : { node, level, state: 'short', short: shortBy(s.units, next.price) };
    });
}

export function buy(s: GameState, id: NodeId, nodes: readonly TreeNode[] = NODES): Bought {
  const node = nodes.find((n) => n.id === id);
  if (node === undefined) return { ok: false, reason: 'unknown' };
  if (!isShown(s, node)) return { ok: false, reason: 'hidden' };
  const level = levelOf(s, node);
  const next = node.levels[level];
  if (next === undefined) return { ok: false, reason: 'done' };
  if (!affords(s.units, next.price)) return { ok: false, reason: 'short' };
  return {
    ok: true,
    state: { ...s, units: spend(s.units, next.price), bought: { ...s.bought, [id]: level + 1 } },
    grant: next.grant
  };
}
  • The reasons are checked in this order: unknown, hidden, done, short.
  • buy returns a new state object and changes only units and bought. It never changes its argument.
  • A node bought stays shown: rungs only move forward and nothing is ever unbought.
  • levelOf and isShown are exported for the tree screen and the scripts. They are not part of G3.

export function applyGrant(doc: SimPolicy4, grant: Grant, ctx: GrantCtx): SimPolicy4 {
  switch (grant.tag) {
    case 'preset':
      return givePreset(doc, 'permitting', grant.preset, ctx);
    case 'measure':
      return givePreset(doc, 'money', grant.preset, ctx);

        oneMoreBand(r, ctx.limits.bands, ctx.limits.reachM)
      );
    case 'hands':
      return doc;

function offered(kind: 'permitting' | 'money', preset: string, ctx: GrantCtx): boolean {
  if (kind === 'permitting')
    return PRESETS.some((p) => p.id === preset && p.id !== 'observed' && p.available);
  return fundingPresets(ctx.cal).some((p) => p.id === preset && p.available);
}

function givePreset(
  doc: SimPolicy4,
  kind: 'permitting' | 'money',
  preset: string,
  ctx: GrantCtx
): SimPolicy4 {
  const named = doc.kinds[kind].filter((p) => p.preset === preset);
  if (named.some((p) => p.on)) return doc;
  if (named.length > 0) return setOn(doc, kind, named[0].id, true);
  if (!offered(kind, preset, ctx)) return doc;
  const choice: AddChoice =
    kind === 'permitting'
      ? { kind, what: 'preset', preset: preset as PresetId }
      : { kind, what: 'preset', preset };
  try {
    const w = { asOf: ctx.cal.asOf, months: WINDOW_MONTHS };
    return addPolicy(doc, choice, { w, month: 1, cal: ctx.cal }).doc;
  } catch (e) {
    if (e instanceof AddLimitError) return doc;
    throw e;
  }
}

const isGameRule = (p: Policy): boolean =>
  p.id === GAME_TRANSIT_ID && p.where.tag === 'transit';

const allPolicies = (doc: SimPolicy4): Policy[] => [
  ...doc.kinds.zoning,
  ...doc.kinds.permitting,
  ...doc.kinds.money
];

function putGameRule(doc: SimPolicy4, next: Policy): SimPolicy4 {
  const zoning = doc.kinds.zoning.map((p) => (isGameRule(p) ? next : p));
  return { ...doc, kinds: { ...doc.kinds, zoning } };
}

/**
 * The game rule as the game would make it now, when the document has none: every stop type
 * bought, one band at the limits, from month 1. The document as it is when it has one, or when
 * no stop type is bought.
 */
function withGameRule(doc: SimPolicy4, ctx: GrantCtx): SimPolicy4 {
  if (doc.kinds.zoning.some(isGameRule)) return doc;
  if (allPolicies(doc).some((p) => p.id === GAME_TRANSIT_ID)) return doc;
  const { stops, reachM, stories } = ctx.limits;
  const stopTypes = STOP_TYPES.filter((t) => stops.has(t));
  if (stopTypes.length === 0 || reachM < 1 || stories < 1) return doc;
  const made: Policy = {
    id: GAME_TRANSIT_ID,
    label: GAME_TRANSIT_LABEL,
    preset: null,
    on: true,
    where: { tag: 'transit', stopTypes },
    spans: [
      {
        from: monthFirstDay(ctx.cal.asOf, 1),
        to: null,
        what: { tag: 'bands', bands: [{ maxM: reachM, stories }] }
      }
    ]
  };
  return { ...doc, kinds: { ...doc.kinds, zoning: [...doc.kinds.zoning, made] } };
}

/** The stop type joins the game rule, which is switched on. */
function giveStop(doc: SimPolicy4, stop: StopType): SimPolicy4 {
  const rule = doc.kinds.zoning.find(isGameRule);
  if (rule === undefined || rule.where.tag !== 'transit') return doc;
  const has = rule.where.stopTypes.includes(stop);
  if (has && rule.on) return doc;
  const stopTypes = has
    ? rule.where.stopTypes
    : toggleStop(
        { id: rule.id, kind: 'transit', stopTypes: rule.where.stopTypes, bands: [] },
        stop
      )!.stopTypes;
  return putGameRule(doc, { ...rule, on: true, where: { tag: 'transit', stopTypes } });
}

/** `edit` on every span of the game's rule; null from `edit` leaves that span as it is. */
function editGameRule(
  doc: SimPolicy4,
  edit: (r: ZoningRule) => ZoningRule | null
): SimPolicy4 {
  const rule = doc.kinds.zoning.find(isGameRule);
  if (rule === undefined || rule.where.tag !== 'transit') return doc;
  const stopTypes = rule.where.stopTypes;
  let changed = false;
  const spans = rule.spans.map((s) => {
    if (s.what.tag !== 'bands') return s;
    const next = edit({ id: rule.id, kind: 'transit', stopTypes, bands: s.what.bands });
    if (next === null) return s;
    changed = true;
    return { ...s, what: { tag: 'bands' as const, bands: next.bands } };
  });
  return changed ? putGameRule(doc, { ...rule, on: true, spans }) : doc;
}

/** The innermost band, and each band out from it at the same stories, to `cap`. */
function raiseInnermost(r: ZoningRule, cap: number): ZoningRule | null {
  const bands = bandsInnermostFirst(r.bands);
  const was = bands[0]?.stories;
  if (was === undefined || cap <= was) return null;
  let out: ZoningRule = { ...r, bands };
  for (let i = 0; i < bands.length && bands[i].stories === was; i++) {
    out = setBandStories(out, i, cap);
  }
  return out;
}

/** The outermost band out to `maxM`; null when it is already there or further. */
function reachOut(r: ZoningRule, maxM: number): ZoningRule | null {
  const bands = bandsInnermostFirst(r.bands);
  const last = bands.length - 1;
  if (last < 0 || bands[last].maxM >= maxM) return null;
  return setBandDistance({ ...r, bands }, last, maxM);
}

/** One more band: beyond the outermost as the editor adds one, else inside it. */
function oneMoreBand(r: ZoningRule, most: number, maxM: number): ZoningRule | null {
  const bands = bandsInnermostFirst(r.bands);
  if (bands.length === 0 || bands.length >= most) return null;
  const added = addBand({ ...r, bands });
  if (added !== null && added.bands[added.bands.length - 1].maxM <= maxM) return added;
  const outer = bands[bands.length - 1];
  const inner = bands.length > 1 ? bands[bands.length - 2].maxM : 0;
  const mid = Math.round((inner + outer.maxM) / 2);
  if (mid <= inner || mid >= outer.maxM) return null;
  return { ...r, bands: [...bands.slice(0, -1), { maxM: mid, stories: outer.stories }, outer] };
}

Rules for each grant

  • preset and measure: when a policy of that kind already names the preset and is on, the document is returned unchanged.
  • preset and measure: when policies name it and all are off, the first in list order is switched on with setOn. Its spans stay as the player left them.
  • preset and measure: when none names it, one is added with addPolicy at month 1, as "+" adds it.
  • A preset or measure the calibration does not offer leaves the document unchanged. The node stays bought.
  • A measure past the document's pool, programme or scale-entry limit (AddLimitError) leaves the document unchanged.
  • stop, stories, reach and bands with no game rule: the rule game-transit is added at the end of the zoning list, on, labelled "Transit rule", with every stop type in limits.stops and one band at limits.reachM and limits.stories, its one span from month 1 with no end. On the first stop purchase that is the one stop type bought.
  • stop with a game rule: the stop type joins it in STOP_TYPES order through toggleStop, and the rule is switched on.
  • stories: in every span, the innermost band takes limits.stories through setBandStories, and so does each band out from it that had the same stories. Nothing changes when the cap is not above the innermost band's stories.
  • reach: in every span, the outermost band moves out to limits.reachM through setBandDistance. A band already at or beyond it is left.
  • bands: in every span with fewer bands than limits.bands, addBand adds one 402 m beyond the outermost with its stories, when that is no further than limits.reachM.
  • bands, when there is no room beyond: the outermost band is split in two at the midpoint between it and the band inside it (or 0 m), rounded to a whole metre; both parts keep the outermost's stories.
  • stories, reach and bands switch the game rule on when they change it.
  • hands: the document is returned unchanged.
  • Every edit returns the same document object when nothing changes.
  • The function never removes a policy, never lowers a value, and never touches a policy other than the one it adds, the game rule, or a policy that names the bought preset.

import { NODES } from './nodes';

export interface Played {
  state: GameState;
  doc: SimPolicy4;
}

/** `buy`, then the grant applied with the limits after the purchase; null when refused. */
export function buyAndApply(
  p: Played,
  id: NodeId,
  cal: Calibration,
  nodes: readonly TreeNode[] = NODES
): Played | null {
  const r = buy(p.state, id, nodes);
  if (!r.ok) return null;
  const limits = limitsOf(r.state, nodes);
  return { state: r.state, doc: applyGrant(p.doc, r.grant, { cal, limits }) };
}

/** Every level of every node, bought in catalogue order from current law at no cost. */
export function fullTree(cal: Calibration, nodes: readonly TreeNode[] = NODES): Played {
  let p: Played = {
    state: {
      ...NEW_GAME,
      phase: 'runs',
      rung: LADDER_YEARS.length,
      units: { home: Number.MAX_SAFE_INTEGER }
    },
    doc: DEFAULT_POLICY4
  };
  for (const n of nodes) {
    for (let k = 0; k < n.levels.length; k++) {
      const next = buyAndApply(p, n.id, cal, nodes);
      if (next === null) throw new Error(`full tree: ${n.id} level ${k + 1} was refused`);
      p = next;
    }
  }
  return { state: p.state, doc: runnable(p.doc, limitsOf(p.state, nodes)) };
}
  • fullTree sets the rung to the last, so every ring is open, and leaves the last rung unmet, so the limits are those of the purchases.
  • On today's catalogue, fullTree's document holds the three permitting presets, the six measures and the game rule with all four stop types and three bands at 80 stories, the outermost at 3,219 m.

/**
 * The ladder's years (G6): from the largest multiple of five at least five years before the
 * window's end year down to the first multiple of five at or after the measured year; when more
 * than four fit, the first, the last and two evenly between.
 */
export function ladderYears(endYear: number, reachedYear: number): number[] {
  const first = 5 * Math.floor((endYear - 5) / 5);
  const last = 5 * Math.ceil(reachedYear / 5);
  const all: number[] = [];
  for (let y = first; y >= last; y -= 5) all.push(y);
  if (all.length <= 4) return all;
  const n = all.length - 1;
  return [0, Math.round(n / 3), Math.round((2 * n) / 3), n].map((i) => all[i]);
}

A play

  1. The state starts as NEW_GAME with phase 'runs' and firstWinAt set, and the document as DEFAULT_POLICY4.
  2. A run reads the view of runnable(doc, limitsOf(state)) at the rung's goal, goalAt(asOf, state.rung, amount), with readRun.
  3. The run's dropped units are max(0, view.rows[d].completedNet) at the deadline's month d. Collected units are floor(share × dropped).
  4. The run is settled with resultOf (side goals read from the same view) and settle.
  5. When the rung in play is met and a next one exists, the play takes it with takeNext.
  6. The play then buys by its order (below), applying each grant with buyAndApply, and runs again.
  7. The play ends when finished(state), or as stuck when nothing is left to buy and the rung is not met in 3 runs in a row, or after 300 runs.

Dropped units from the series understate the drops slightly: completedNet takes off the existing homes of projects still building, and a project worth nothing leaves no drop.

Share of drops collected

export const SHARE = { base: 0.25, perRadius: 0.1, perLinger: 0.05 } as const;

/** The share of dropped units a player collects: an assumption, not a measurement. */
export function shareOf(s: GameState, mode: 'hand' | 'collect-for-me'): number {
  if (mode === 'collect-for-me' || (s.bought['hands-auto'] ?? 0) >= 1) return 1;
  const r = s.bought['hands-radius'] ?? 0;
  const l = s.bought['hands-linger'] ?? 0;
  return Math.min(1, SHARE.base + SHARE.perRadius * r + SHARE.perLinger * l);
}

Decisions

  • 23 nodes in stages 0 to 4. One stage per rung of a five-rung ladder keeps each rung opening something new.
  • Rings follow from stages and the measured ladder (ringOf). The number of rungs is measured, so a fixed ring would hide nodes on a short ladder.
  • One start node per branch. The player sees each kind of lever at once.
  • Heights, reach and stories are split into nodes by stage. A single node with every level would open 80 stories in ring 0.
  • state-double comes after federal-support. Alone it buys no homes.
  • A preset node's source is a named provenance from PRESETS (the first for sb423Clock and noDiscretionary, the last for benchmarkPermits). Each names the rule's own basis, not an invented parameter.
  • A preset or measure step reads "From today". A one-level node has no value to name, and it is in force from today.
  • A grant switches the game rule on when it changes it. A purchase takes effect at once (P12).
  • A grant the data cannot honour changes nothing and keeps the purchase. Refunding would need a second state change outside buy.
  • A game rule made again carries every stop type bought. It is the rule as the game would have it, and on a first stop purchase it is that one stop type.
  • Hands steps: 64, 80, 96, 120 px and 5, 6.5, 8 s, then auto. Four and three steps above BASE_HANDS with rising prices give the hands branch a purchase in every early round.
  • Prices are in tuning.ts as PRICES, by node id. The balance script tunes them, and call 25 puts every such number in that file.
  • The scripts read a directory or fetch a version. npm run data:local leaves no directory.
  • The engine runner lives in scripts/reach-measure.ts and fullTree in catalogue/play.ts, so closing's reach check can import both.
  • "Two evenly between" takes the entries at a third and two thirds of the full list, rounded. It keeps every year a multiple of five.
  • A side-goal target at or below current law is raised to 1.25 times current law's value, rounded up to the next 1,000. It keeps the goal a step beyond what the player gets for nothing.
  • The balance script assumes the player takes the next rung at once and estimates drops from completedNet. Both keep it a pure function of the engine's series.
