# Citywide roof processing with a 50 GB working set

Date: 2026-10-12

Status: Follow-up design and implementation plan requested by the user. This document does not claim that streaming, citywide acquisition or citywide validation has been implemented. It supplements the [approved roof design](2026-10-11-existing-building-rooflines-design.md); its product and quality constraints continue to apply.

## Goal and recommendation

Process all existing SF building footprints with full-density LiDAR and optional aerial vegetation evidence, while keeping the entire run-owned local working set below **50,000,000,000 bytes (50 decimal GB, approximately 46.57 GiB)**. The user has 5 Gbps connectivity and prefers remote sources to serve as the backing store. Use streaming acquisition, a small evictable source cache, one image decoded at a time, one roof-fitting process, and resumable spatial batches. A batch is a bounded unit of work, not a 50 GB download followed by additional unbudgeted scratch space.

Original source services are the acquisition backing store; verified content-addressed remote archives become the replay backing store. Do not depend on an upstream URL continuing to return identical bytes. Full acquisition precedes versioned fitting, but never requires full local acquisition: stream each object through hashing and archival, verify it remotely, and discard its local copy. Re-fetch only the objects needed for the current processing neighborhood from the frozen archive. This trades bandwidth for disk and preserves the current requirement that the dataset version identify all frozen inputs.

No citywide run, remote upload, paid storage commitment or dataset promotion occurs as part of writing this plan or opening the implementation PR. Future execution starts with a bounded capacity and imagery pilot, followed by a measured cost/runtime decision.

## Why the current local implementation needs another step

The current fetch/job path materializes the complete selected source set. Python processes four neighborhood clouds at once and retains every building result until the end; point identities occupy expanded Unicode arrays. Restoration downloads the whole report's processing closure. Remote Wrangler transport starts a process per object and probes existence by downloading an object. Large source descriptors and `report.json.roofArchives` also grow with the run. Merely splitting downloads or lowering imagery resolution does not bound these paths.

The retained inventory contains 162,733 parents and 337,455 footprint pieces. A rectangular EPT selection enumerated 311,107 objects; that is not a measured exact-footprint citywide selection. Historical multi-terabyte forecasts used expanded point archives and are not forecasts for the current reference/subset format. One ordinary 940,778-point replay reduced owned captured-candidate evidence from 22,944,441 to 1,962,515 bytes; it did not establish large-building memory use, live beta reconstruction throughput or citywide storage cost. The largest prior vegetated/waterfront probes required approximately 6.02/8.53 GiB RSS with the old expanded representation. The proposed compact RAM representation has not been implemented or measured. See the [current checkpoint](../../dev/rooflines.md#current-checkpoint-and-coverage) for what actually ran.

## Working-set and execution contract

| Local allocation | Default budget, decimal GB | Contents |
| --- | ---: | --- |
| Evictable source cache | 12 | Original compressed LAZ, imagery and hierarchy objects; active leases prevent eviction |
| Active processing | 18 | Point/mask evidence, fitter inputs/outputs and all child-process temporary files |
| Transfer and verification | 6 | Partial downloads, upload staging and one streamed readback at a time |
| Metadata and finalization | 9 | Run database/WAL, source inventories, output spools, audit, indexes and base-dataset work |
| Emergency headroom | 5 | Stops admission before the 50 GB ceiling; never scheduled as ordinary capacity |
| **Total** | **50** | Every run-owned copy, including verification and resume work |

The category budgets are defaults, transferable only through one global reservation manager. The admission ceiling is 45,000,000,000 bytes; the absolute ceiling remains 50,000,000,000. Count allocated disk bytes and committed reservations, including shared-cache leases and SQLite WAL. Route `TMPDIR`, Python temporary files, DuckDB spills, fit work, cache, output and restore paths under the accounted workspace. Never create a full local R2 mirror. Existing installed tools are prerequisites; any run-created copies and base-dataset intermediates count. Unrelated files are outside the run budget, but maintain at least 10,000,000,000 bytes free on the host filesystem in addition to emergency headroom.

Reserve upper bounds before controlled writes. Unknown-length HTTP responses require a configured per-object bound, incremental admission and abort before exceeding it; do not trust Content-Length alone. Native writers require a measured conservative job bound and an enforced workspace/quota limit or equivalent bounded writer supervision demonstrated by fault-injection. A disk polling loop alone is not proof of a strict ceiling. If the host cannot enforce the bound for a native stage, stop the capacity gate instead of advertising a hard guarantee. Charge multipart buffers, sparse allocated blocks and simultaneous readback copies correctly. Keep partially written files resumable or delete them after an interruption; neither an incomplete upload nor an unverified object permits deleting the only good local copy.

RAM is a separate admission condition. Start with one building fitter and one active neighborhood cloud; admit only a measured peak-RSS estimate plus 2 GiB host headroom. Retain the existing conservative large-case process budget until new large-case measurements justify a change. The 50 GB disk budget does not establish that a particular building fits in memory. Split neighboring groups when necessary, but never split a single building's fitting support or reduce LiDAR density. A building exceeding the demonstrated resource envelope pauses the run with a resumable capacity error; it is not silently assigned a geometry fallback.

Start acquisition with four HTTP streams, a shared maximum of two remote archive operations, and one decoded image. Apply backpressure, bounded retries with jitter and Retry-After, and transfer/CPU/RSS/disk telemetry. Concurrency is configurable within the global reservation manager. At 5 Gbps, 50 GB takes 80 seconds at the theoretical link rate; source throttling, latency, TLS, uploads, verification and reconstruction prevent treating that as a runtime estimate. Measure actual effective throughput in the pilot.

## Streaming units, boundaries and identity

1. **Inventory and freeze:** enumerate only EPT nodes intersecting full building footprints plus the existing physical 50 m support. Traverse all relevant depths; never use a coarse EPT level as a substitute for full-density data. Stream original metadata, hierarchy, LAZ and eligible imagery objects through SHA-256 and immutable archival. Store inventories in a disk-backed SQLite run database and bounded canonical parts, rather than one giant JSON object. Freeze configuration, tool/code receipts, permissions, acquisition metadata, retrievedAt and the base footprint/parcel inputs. Null capture dates and vertical CRS remain null unless supported by source metadata.
2. **Version:** once every required object has a verified archive receipt, compute one immutable dataset version. Canonically stream the same logical lock bytes used by `computeDatasetVersion` and `lockSha256`; a sharded physical lock must not change that logical hash. Do not include scheduling, local paths, resume timestamps or cache state. Store a versioned private lock-part root; retain legacy flat-lock readers. A new frozen imagery choice or algorithm revision produces a different version.
3. **Process:** assign each full building exactly one owner using its existing stable building ID and deterministic spatial order. Start with 1 km EPSG:7131 work cells and split building groups by reserved cost. Cells are scheduling aids; fetch every intersecting node needed by the complete owned building plus support, including cross-cell nodes. Reuse leased nodes in a bounded LRU. Decode each source with its original ordinal and unchanged whole-node coordinate transform. Release clouds and results after each building or bounded group; write results incrementally to a disk-backed spool.
4. **Images:** fetch/decode one image tile at a time with the neighbor halo needed for morphology. Accumulate only bounded mask/support windows needed by the active group. A building may need several image tiles; image boundaries must never become roof boundaries. Missing neighbor pixels are unknown, not non-vegetation or duplicated edge pixels. Release decoded imagery after the relevant mask window has been archived and consumed.
5. **Commit and evict:** archive original sources, exact masks, candidate evidence, point references/subsets, portable inputs, diagnostics, outcomes and output-spool parts. Stream a readback through SHA-256 and compare length and digest before recording a durable verified receipt. Then transactionally checkpoint the batch and release unleased local files. Replay a shared source from its verified remote archive after eviction; never refetch a mutable service and silently relabel it with the old digest.
6. **Finalize:** external-sort the committed result spool into the existing building/piece ordering and 1 km public chunks. Shard/flush final artifacts independently of processing batch boundaries. Stream complete parent and piece audits, including zero-piece parents and fallback outcomes. Archive each finished artifact and evict its local copy after verification. Verify the complete remote inventory and dataset invariants in bounded passes. Publish the dataset root manifest last, only after every required artifact is verified; promotion remains the separate existing staging/production workflow.

Use a private schema-2 archive catalog: bounded root (at most 1 MiB), typed content-addressed leaf parts (target at most 16 MiB, absolute 32 MiB), and a building-ID lookup index. The processing report references this root instead of a citywide flat `roofArchives` array. Parts contain only their own dependencies; do not repeat the entire city coverage list per object or building. Reject cycles, duplicate identities, unknown roles, hash/length mismatches and missing closure members. Bound lookup pages and traverse lazily. Public roof mesh/index/audit schemas stay unchanged; update all private readers, restore/upload/check paths and legacy compatibility together. A one-building rebuild restores only its transitive closure, with the same budget manager.

The journal states are `planned → sources_verified → processed → archives_verified → committed → evicted`. Each transition is transactional and idempotent. A private run ID exists before a dataset version; only frozen runs can fit versioned buildings. Root commit is separate from batch commit. On restart, validate configuration/version and receipts, clean incomplete work, and resume unfinished batches. A complete remote object without a journal receipt can be reverified and adopted; a journal receipt without matching bytes is corruption and stops the run. Resume performs no live imagery request once inputs are frozen.

Preserve source-SHA/original-ordinal identities, the held-out split (first four big-endian bytes of SHA-256 of ASCII `<sha>:<ordinal>`, modulo 5), float64 coordinates, signed zero, and original whole-node CRS transforms. Replace repeated Unicode SHA arrays with a sorted immutable SHA dictionary and uint32 indices in RAM: 24 coordinate bytes + 1 class byte + 4 source-index bytes + 8 ordinal bytes = 37 bytes per row, versus the current 289-byte expanded row. Preserve the existing 97-byte logical record/digest and reference/subset archive format. This is an internal representation change, not point thinning or a new quality policy. Require equivalence across scheduling orders for decoded candidates, selected meshes and normalized audit records; raw native fitter ordering is not a determinism claim.

## Lower-resolution imagery decision

The [official SF viewer](https://sfplanninggis.org/1938/) uses the [SF WMTS capabilities](https://tile.sf.gov/api/WMTSCapabilities.xml). Metadata inspected on 2026-10-12 advertises `p2023_rgb8cm`, EPSG:3857, 512-pixel PNG tiles and matrices 6–21. Using its advertised scale denominators, the approximate ground sampling at latitude 37.75° is:

| Matrix | Ground sampling | Use in pilot |
| --- | ---: | --- |
| 19 | 0.118 m/pixel | Current service-level baseline; the source's “8 cm” name is not this matrix's sampling |
| 18 | 0.236 m/pixel | First lower-resolution candidate |
| 17 | 0.472 m/pixel | Second lower-resolution candidate |
| 16 | 0.944 m/pixel | Optional diagnostic only, not the initial target |

One matrix step coarser uses one quarter as many pixels over the same extent, not necessarily one quarter the compressed bytes. Availability here means advertised service matrices; imagery adequacy, actual requests and redistribution permission still need validation. SF imagery remains disabled until derivation/archive permission is recorded. Access through a public viewer is not permission evidence.

A separate candidate is [CDFW's 2022 60 cm RGB NAIP imagery](https://data.ca.gov/@california-department-of-fish-and-wildlife/naip-2022-60cm-california), whose catalog lists unrestricted public use and Creative Commons Attribution. Its [year-specific ImageServer](https://gis.wildlife.ca.gov/images/rest/services/Base_Remote_Sensing/NAIP_2022/ImageServer) offers RGB exports, EPSG:3857 and a 0.6-unit pixel grid. Respect and record the advertised attribution, item IDs, exact request extent/size/bands/resampling, transform, year and returned bytes. Ground sampling must be computed from the actual transform; the product's nominal 60 cm label and Web Mercator grid units are different quantities. Export small bounded RGB windows, not the statewide raster or a changing “latest” mosaic. Reject CIR/NIR band order passed as RGB. [USGS describes NAIP](https://www.usgs.gov/centers/eros/science/usgs-eros-archive-aerial-photography-national-agriculture-imagery-program-naip) as leaf-on aerial imagery, with a 0.6 m standard since 2018 and optional 0.3 m acquisitions. Neither that specification nor a green canopy visible in a picture proves our RGB/PCA heuristic is adequate.

Pilot the existing 12-case quality set plus at least eight additional cases chosen before scoring: overhanging trees, tree/roof borders, shaded canopy, green roofs, pitched roofs, courtyard roofs, tile seams and changed buildings. Compare no imagery, permitted SF matrix 19/18/17 and NAIP RGB where available, keeping full-density LiDAR and unchanged roof QA. Record registration overlays on stable roof corners, canopy/roof labels, masks, removed point counts, selected candidate, fallback reason, height/sections, bytes, throughput, RSS and disk high-water. Separate resolution comparisons within the same capture from the NAIP year/source comparison.

Coarse pixels cannot faithfully represent the current 0.24 m closing and 0.60 m dilation by blindly applying `max(1, round(metres/pixel))`. For the new optional imagery algorithm, use a 0.12 m ground-coordinate mask grid, nearest-neighbor sampling of the original RGB classification with validity support, and the existing physical morphology on that grid. Keep the current algorithm for legacy replay. Coarse canopy/roof boundary cells and unregistered pixels are unknown and cannot alone reject a return; emit an uncertainty flag. Stitch image halos before morphology. Pin this algorithm/config change and archive masks; upsampling is a coordinate/morphology convention, not recovered detail.

Select the coarsest candidate that (a) passes existing roof QA without weakening any threshold, (b) introduces no new roof spikes or loss of the two protected pitched-roof details, (c) has no more than two percentage points additional roof-labelled return rejection versus the permitted matrix-19 baseline, and (d) is within five percentage points of baseline canopy-labelled return rejection on the fixed evaluation set. Report counts per case as well as aggregate rates. Predeclare labels and score evaluation cases without retuning on them. If the SF baseline cannot be used, require at most 2% rejection of roof-labelled returns and at least 80% rejection of canopy-labelled eligible returns, plus visual roof review; label this a different comparison, not baseline equivalence. If no candidate passes, keep a rights-cleared finer source or LiDAR-only/fallback. Resolution choice must not be justified by higher acceptance counts alone. NIR classifiers, ML and photogrammetry are outside this work.

## Gates before a citywide run and release

- Demonstrate cold source freeze, bounded fitting, interruption/resume, selective cold rebuild and finalization using three adjacent cells, a boundary-crossing building and the largest retained vegetated/waterfront cases. Run under the 50 GB cap with one fitter and memory admission; refuse unsupported large cases rather than silently skipping them.
- Compare partition/order/resume variants with the same frozen logical lock and code/tool/config hashes. Require equal normalized selections, meshes, identities and audit records; compare deterministic public encodings with fixed volatile fields. If native variability appears, stop and investigate rather than change tolerances.
- Measure total source/processing archive bytes, object count, requests, repeat-fetch amplification, throughput and fitting time. Project the exact-footprint city inventory using density/building-size strata and report uncertainty/tail cases. Obtain a remote storage/request budget before citywide execution: the 50 GB local cap is not a remote cost cap. The pilot may show that further archive compaction is needed; do not drop diagnostic evidence to meet a cost target.
- Complete global validation with every parent/piece accounted for and explicit method/reason/source-age metadata. Publish aggregate and per-neighborhood outcomes without inventing an acceptance quota. Unsupported or post-capture structures use the existing footprint fallback and remain addressable in the audit.
- Keep original runtime/release gates: actual M2-class headed measurement remains open; the successful M5 run is not that measurement. Verify asynchronous roof activation, 50 ms task limit, p95 16.7 ms frame budget, bounded caches, parcel editing/Undo and staging restoration before promotion.
