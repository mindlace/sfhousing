Homes waiting for money

A per-month count of the homes waiting in the plan's funding line, taken in the worker's step, carried by SeriesChunk.waiting to TimelineView.waitingMoney.

Purpose

The tally after a run shows where the homes not yet built stand: homes in each permitting stage and homes waiting for money. The stage counts are in the series today. The count of homes waiting for money is not: the funding line is worker state, and no count of it is recorded or sent. This unit adds that count, month by month, so the tally (U1) and a run's reading (G6, RunReading.waitingMoney) can read it at the deadline's month.

  • It produces row E2. It needs no row.
  • It carries call 12: the tally's "waiting for money" row is its own build unit. The tally ships without it and gains it when this unit lands.
  • It carries call 23: the count is read at the end of the model month that holds the calendar month's last day, because the line is served once a model month.
  • It carries the source model's rule that the tally shows only what the engine measures: the count is read from the line the engine serves, and nothing is estimated.
  • It carries the global constraint of one future: the count is read from the world and never feeds back into it, so the forecast is unchanged.

The series, the chunk and the view

  • A series files 18 fields per calendar month: pipeline, new, entitled new, exited, six stages, funded, displaced, displaced of completed, five tiers (src/lib/sim/world/score/series.ts:35-51). Its data layout is version: 5 (series.ts:53, score/types.ts:97).
  • Every field is a dated delta filed by an event, summed to a level on demand (series.ts:260-276, :569-578). None is a level read from the world.
  • stepped(month) takes the model month only and has no world (series.ts:607-622, score/types.ts:139). add(e, world, statics) gets the world as it stands when the event is fed (series.ts:396-401).
  • Calendar month i is final once the model month holding its last day is stepped: finalTable(s)[i] = monthOfDay(asOf, last day of month i) (score/statics.ts:220-225, series.ts:561-566).
  • A model month is 30.436875 days (src/lib/timelapse/time.ts:10). Model month m runs from asOf + floor((m - 1) * MONTH_DAYS) + 1 to asOf + floor(m * MONTH_DAYS); day asOf and earlier are model month 0 (src/lib/sim/world/months.ts:9-28).
  • chunkOf reads the plan's money and tiers through extrasOf(plan) only when a money feed is given, and the twin's rows only to subtract two fields (score/chunk.ts:21-33).
  • MoneyFeed carries the plan's world (score/types.ts:146-151). moneyRowsOf already reads history from that world at chunk time: each pool's shut rows (score/money.ts:37-48). A world without funding columns gives null and false there.
  • viewOf joins chunks; its tiers are null when any chunk has none, its money null when any chunk has none or there are no rows (score/view.ts:102-128). chunksBefore trims each per-month array of a straddling chunk (score/view.ts:138-156).
  • SeriesChunk has from, rows, planEffect, money, tiers (score/types.ts:78-86). TimelineView has no waiting field (score/types.ts:171-186).

The funding line

  • FundLine holds one row per waiting application: lot, kind, units, gone, seq and others (src/lib/sim/world/funding/columns.ts:13-60). gone is "1 = removed this step, dropped by compactLine" (columns.ts:30-31).
  • units is the application's size, the homes it would build, set at joining (funding/apply.ts:334) or on a re-make (apply.ts:472). It is gross: the same size an award passes as FundedStart.units (funding/serve.ts:228, :285).
  • A lot holds at most two applications, one per kind (apply.ts:376-378, funding/line-index.ts:59-65).
  • Rows of a lot that started another way can stay on the line. An ordinary start with a 'start' takes the lot's rows off (funding/system.ts:84-85). A start that gained no home sends no 'start', and its lot's rows stay until they would be awarded; the lazy guard then drops them (serve.ts:60-66). The guard's test is: the lot has a lot row and its state is not LOT_FREE (serve.ts:202-206).
  • A lapse marks a row gone directly (apply.ts:465-468).
  • Gone rows may survive a step on a long line; "every reader of the line skips them" (funding/shadow.ts:81-83). Compaction keeps the line index current (line-index.ts:123-131).
  • The line index keeps each lot's waiting rows in byLot, rebuilt from the rows not gone when stale (line-index.ts:36-51). rowOfSeq finds a row by seq by binary search (line-index.ts:68-77).
  • fundOf(world) throws on a world without funding columns (columns.ts:220-224).
  • No count of waiting applications or homes is recorded or sent anywhere (engine-outputs.md section d, checked: the only reader of the funding columns outside funding/ is score/money.ts:42).

When the line is served in a step

  • A step runs seven systems: (1) policy, (2) money in, (3) the stages due, (4) applications join (f.apply), (5) the line is served (f.serve), (6) ordinary starts set aside, (7) shadow starts (f.shadow), then world.month is set (src/lib/sim/world/world.ts:569-675).
  • The line is served once per model month, in system 5 (world.ts:651-652). Awards in the scan carry days inside the month (serve.ts:257-269), and joins carry their applied day (apply.ts:328). Within one step nothing orders them by day.
  • System 7 runs last in every funded month, and compacts the line (shadow.ts:81-83, world.ts:671-674).
  • No funding hook runs in a month whose frame has finance null (world.ts:79-81). The funding columns can be made after month 1 by the first hook that runs (system.ts:20-33).

How the runner feeds, restores and refills

  • The world's events and a stepped mark go to a log at step time (runner/ensemble.ts:132-143, :241-251). A feed unit drains the log into the series later (ensemble.ts:222-239).
  • Feeding happens only while the series gate is open (ensemble.ts:166, :285-290). The gate closes on an accepted edit and reopens when that side's compile finishes (runner/runner.ts:643, :776-784). While it is closed the world can step on. So when a stepped mark is fed, the world may be months past it.
  • Copies are taken after model month 0 only (ensemble.ts:23). A copy holds a structuredClone of the world, the series data and the log's unfed tail (ensemble.ts:213-220). A restore clones the copy's world and series and re-steps quietly (ensemble.ts:201-211, :298-329).
  • The runner's money feed is the plan's ensemble world as it stands (runner.ts:757-768). It is null unless month 1's frame has finance with pools (runner.ts:787-788).
  • filled carries chunkOf(plan, comparison, moneyOf(through), posted + 1, through) for months final in both ensembles (runner.ts:811-822). A refill withdraws months from from and the following filled re-posts them (runner.ts:688-700).

Design

Where the count is taken and kept

The count is taken at the end of each funded step and kept in the world, beside the line. The chunk reads it from the plan's world.

Decision The count is not a series field. The series is fed from a log, and when a stepped mark is fed the world may have stepped on (runner). The line at a past month cannot be read then. So the count must be taken inside the step, where the world is the month's. Kept in the world, it survives a clone and a restore as the world does, and the series layout (version: 5, 18 fields) is unchanged.
  • The funding line gains two fields: waitHomes, the count by model month, and waitThrough, the last model month recorded.
  • The funding system's shadow hook (system 7) records the count after stepShadows. Nothing in the step changes the line after it.
  • src/lib/sim/world/funding/system.ts holds the count (waitingHomes) and the record (recordWaiting). They need the line index, which imports columns.ts, so they cannot live in columns.ts.
  • src/lib/sim/world/funding/columns.ts holds the reader (waitingAt), which reads only the columns. score/series.ts imports it from there, as score/money.ts imports fundOf.
  • The series' extras gain waiting(world, from, through), which maps calendar months to model months with the series' own finalTable.
  • chunkOf fills waiting from the money feed's world, which is the plan's.

The count, in code:

// Scratch reused across calls: lot id to the stamp of the call that last saw it, and its slot.
let stamp = 0;
let seenAt = new Int32Array(0);
let slotOf = new Int32Array(0);
let most = new Int32Array(0);

export function waitingHomes(world: World): number {
  if (!('gone' in world.line)) return 0;
  const line = world.line as FundLine;
  const lots = world.lots;
  stamp++;
  // grow seenAt and slotOf to cover every lot id on the line, and most to line.n (doubling)
  let slots = 0;
  for (let i = 0; i < line.n; i++) {
    if (line.gone[i] === 1) continue;
    const lot = line.lot[i];
    // Rule 8's lazy guard, the same test as serveRow's: a lot no longer free waits for nothing.
    const li = lotRow(lots, lot);
    if (li >= 0 && lots.state[li] !== LOT_FREE) continue;
    // A lot with two applications counts once, by the larger.
    if (seenAt[lot] !== stamp) {
      seenAt[lot] = stamp;
      slotOf[lot] = slots;
      most[slots++] = line.units[i];
    } else if (line.units[i] > most[slotOf[lot]]) most[slotOf[lot]] = line.units[i];
  }
  let sum = 0;
  for (let k = 0; k < slots; k++) sum += most[k];
  return sum;
}
  • The count is one pass over the line's rows 0 to line.n - 1. It calls neither lineIndex nor rowOfSeq, sorts nothing and allocates nothing per lot: the scratch arrays live at module level, grow by doubling and are told apart from earlier calls by a stamp.
  • A row marked gone is not counted.
  • A lot with two applications counts once, by the larger units.
  • The homes of a row are its units: the gross homes the application would build, as an award passes them on.
  • A row whose lot has a lot row in a state other than LOT_FREE is not counted: its lot started another way, and the row is waiting only until the lazy guard drops it.
  • A row whose lot has no lot row is counted, as the guard treats that lot as free.
  • A row waiting on a closed pool, or one that will later lapse, is counted while it waits.
  • The sum is of whole numbers, so the order of the rows does not change it.
  • Imported names used per call (LOT_FREE, lotRow) are bound once at module top, as series.ts:18-22 does.
  • The code uses no Math function the determinism rule forbids and no **.

The record in the world

// src/lib/sim/world/funding/columns.ts
export interface FundLine extends LineColumns {
  // every column it has today, and:
  /** `[m]`: homes waiting at the end of model month m (`recordWaiting`); `[0]` is 0. */
  waitHomes: Int32Array;
  /** The last model month recorded in `waitHomes`; 0 before any. */
  waitThrough: number;
}

// emptyLine() adds:
//   waitHomes: new Int32Array(1),
//   waitThrough: 0

// src/lib/sim/world/funding/system.ts
shadow(ctx) {
  ensure(ctx);
  stepShadows(ctx);
  recordWaiting(ctx.world, ctx.month);
}
  • recordWaiting(world, month) throws Error('recordWaiting: month M is not after month T') when month <= line.waitThrough.
  • It grows waitHomes to hold index month, doubling its length, at least to 8.
  • Months from waitThrough + 1 to month - 1 take the value at waitThrough. Those are months in which no hook ran, so the line did not change. When the columns were made in a later month, the value at 0 is 0, which is right: the line was empty.
  • Then waitHomes[month] is the count and waitThrough is month.
  • waitingAt(world, m) throws RangeError unless m is a whole number with 0 <= m <= world.month.
  • waitingAt on a world without funding columns returns 0.
  • Otherwise it returns waitHomes[Math.min(m, waitThrough)]. A month after waitThrough and not after world.month had no hook, so the last value holds.
  • Both fields are plain typed array and number, so structuredClone(world) copies them.
  • The comparison's world records too, as the same funding system steps both. Its record is never read (chunk).

Model months and calendar months

The value for calendar month i is the line at the end of model month finalTable(statics)[i]: the model month that holds calendar month i's last day, the one whose step makes month i final.

Note The line is served once a model month, and inside a step joins and awards are not ordered by day (call 23). The value therefore includes what happens in the rest of that model month after the calendar month's last day, up to about 30 days: applications that join after that day are counted, and applications awarded after it are not. Two calendar months whose last days fall in one model month (a February between two model month ends) share a value.
  • Calendar month i with finalTable[i] = 0 (a dataset date on its month's last day) reads model month 0, which is 0: nothing waits at the dataset date.
  • Every calendar month a chunk carries is final, so finalTable[i] <= stepped <= world.month, and waitingAt never throws for it in the runner.

The view

The two fields keep the optional types contracts gives them (E2). This unit gives them values.

  • viewOf joins every chunk's waiting in order, as it joins tiers, reading an absent one as null.
  • viewOf always sets waitingMoney.
  • waitingMoney is null when the view's money is null.
  • waitingMoney is also null when any chunk's waiting is null or absent.
  • Otherwise waitingMoney has filledThrough + 1 entries.
  • chunksBefore trims waiting as it trims money: waiting: c.waiting ? c.waiting.slice(0, n) : null.
  • viewOf and chunksBefore still read only the chunks and the plain fields of ScoreStatics, so they run on a posted copy.

Restore and refill

  • A copy is a structuredClone of the world, so it holds the record through its month (month 0: the value 0).
  • A restore clones that world and re-steps quietly. Each quiet step records its month again, after the copy's waitThrough, so recordWaiting's order check holds.
  • The re-stepped months record the values of the new policy. A month before the edit's first difference records the same value as before, as the step is the same.
  • A kept world (an edit whose first difference is after the months stepped) keeps its record; the months it has stepped did not change.
  • A refill re-posts months from from. Their chunks read the world in use, so a refilled view equals a fresh open's.
  • The series and its data are not touched, so WorldSeriesData, its version and data() are unchanged.

Cost

  • The record runs once per funded world-month, on both worlds. It is one pass over the line's rows, with one lot row lookup per row not gone, so its cost grows with the line's length. On the bench city it adds about 100 µs to a funded world-month.
  • That cost is accepted. Keeping the count current as rows join, leave, are awarded or lapse, and as lots stop being free, would spread the count through the line's writers and the world core for one row of the tally.
  • The read costs one array read per calendar month of a chunk.
  • The record adds 4 bytes per model month to each world: under 2 KB for a 480-month window.
  • The bars it must stay under: one funded world-month at most 250 µs mean on the bench city (funded-month.perf.spec.ts, whose BAR_US this unit sets to 250, with its comment saying the month includes the waiting-homes record); no slice over 50 ms, first cells and first filled within 3 s, the whole window within 480 × 9 ms on the live city (host.perf.spec.ts, unchanged); one month's scoring for a pair within 1 ms at the median (chunk.perf.spec.ts, unchanged).
  • The funding system's shadow hook costs at most 150 µs mean per funded world-month more than on main, measured on the bench city in the same session on the same quiet machine, main and this branch run one after the other. The other hooks run code this unit does not change; their means are reported beside main's, and the funded world-month's 250 µs bar is the bar that covers them.
  • The implementer runs these on a quiet machine once the code is in. If a bar fails, the implementer stops and reports the numbers to the conductor; the counting rule is not changed to meet it.

Tests

All unit tests in the server project, colocated. Each calls expect.

funding/system.spec.ts and funding/columns.spec.ts

  • An empty line counts 0, and a world without funding columns counts 0.
  • A row marked gone is not counted, including one marked after the index was built.
  • A lot with a market application of 10 and an affordable one of 30 counts 30, whichever comes first on the line.
  • A row whose lot row is LOT_DONE, LOT_LIVE or LOT_HELD is not counted. A row whose lot has no lot row is counted.
  • On a funded world stepped through 480 months of the fundedMini() city (as score/money.spec.ts:277 builds it), after every step waitingAt(w, w.month) equals a reference count written in the test by a plain scan of the rows (a Map of lot to largest units, the same lot test). Some month's count is above 0.
  • waitingAt(w, 0) is 0. waitingAt throws RangeError for a month after w.month, below 0 or not whole.
  • recordWaiting throws for a month not after waitThrough. A record after a gap fills the gap with the last value.
  • A structuredClone of a world reads the same values. A clone and its original, stepped on alike, record the same values.
  • Stepping a world never changes an earlier month's value.

score/chunk.spec.ts, view.spec.ts, money.spec.ts

  • waitingMoney is null when the view's money is null, and when a chunk with money has waiting null.

Decisions

  • The count is kept in the world, not as a series field. The series is fed after the world may have stepped on, so only the step sees the line at its month.
  • It is recorded at the end of system 7. System 7 runs last in every funded month and compacts the line, so the record is the line as the month ends.
  • "No longer free" is the lazy guard's own test. The same test keeps the count and the award rule in step.
  • The count and the record live in system.ts, the reader in columns.ts. The count needs the line index, which imports columns.ts; the reader needs only the columns.
  • The count is one pass over the line's rows with stamped scratch. Reading the line index would rebuild it whenever it is stale, which costs a whole-line rebuild each month; a pass over the rows with module-level scratch builds nothing per step.
  • The record's cost of about 100 µs per funded world-month on the bench city is accepted, and the bench bar is 250 µs. The live city's window bars are what a player feels, and they hold; a count kept current incrementally would touch the line's writers and the world core.
  • Months with no hook carry the last value. No hook means the line did not change.
  • waitingAt on a world without funding columns is 0, not an error. Its line is empty, and moneyRowsOf treats such a world the same way.
  • chunkOf and viewOf always set the optional keys. A result then has one shape, null where there is no value.
  • The comparison's world records too. One funding system steps both worlds and cannot tell them apart; the cost is one walk of a line per month, and the record is never read.
