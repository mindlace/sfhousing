Closing: the journey, the reach check, the run bench and the documents

Proves the incremental loop end to end on the merged tree, asks the reach check its two questions, measures a run with drops, and makes every current document true to the game and its new name.

Purpose

This unit runs last, after every other unit of the design has merged into the integration branch. It produces no interface row and needs every row. Its job is to prove the package as a whole and to tell the next developer what the game now is.

  • The journeys: a new visitor paints to the room goal, starts, runs with "Collect for me", reads the tally, buys a node, runs again and takes the next goal; a keyboard-only player does the same with the ring; a player at the last rung reaches the ending.
  • Every existing e2e spec made true to one address, no header steps, no levels, no Remix and the name "SF Housing".
  • The reach check asks two questions on a built dataset: current law meets rung 0, and the full tree's document meets the last rung.
  • Two bench cases: a run on the citywide view with drops and a moving pointer, held to the map's pass bar; and the wait from a purchase to the next run's forecast being ready, measured on a laptop.
  • The game's developer document rewritten, and CLAUDE.md, README.md and the other current documents that carry the old name made true.
  • The accessibility checklist run for the game's page in each of its states.

It carries these rulings and calls:

  • P1: the journeys open the workshop and come back, so the forecasting tool is reachable.
  • P5 and call 6: one address; /sim redirects to /; the header has no steps.
  • P8 and call 15: the name "SF Housing" in the documents and the tests that expect it.
  • P9 and call 17: units come only from collected drops; "Collect for me" has no penalty.
  • P11: the brush is the opening only.
  • P13: no Remix in any test or document.
  • P15: no test reads or writes a five-level save.
  • D1 and the source model's "What changes in the app": the reach check's two questions, run before every dataset upload.
  • Call 22: the ladder has at most five rungs, so the ending is one seeded run away from any rung.
  • Calls 9 and 21: an e2e spec that seeds no game runs the open game, which shows the simulation at /; a test that needs the opening seeds a new visitor.
  • R7 and the global constraints: one future, timing measured only on a quiet machine, page text short.

Decisions

  • One goal amount, 1, for every journey. One stamp meets the room goal and every run meets its rung on fixture-0, so each run's outcome and the first lump are certain.
  • The journeys buy the first ready node. G6 guarantees one after the first run's lump, and choosing on the screen keeps the journeys true whatever T1 tunes.
  • The keyboard journey sweeps the ring row by row. The ring and drops are on a canvas with no page hook; Shift steps of 64 px with a 48 px radius cover the box, and a pass is shorter than a drop's 4,000 ms linger.
  • State is read from storage, not the screen. The saved game is G1's contract, while the screens' words are another unit's to choose.
  • The keyboard journey runs on chromium only. A keyboard on the phone layout is not a case the checklist asks for, and the pointer journey covers the phone.
  • The step clicks become the site-name link. Those tests are about a client navigation into the simulation, which the site name still gives.
  • The reach check is renamed reach-check. Level 2 no longer exists, and the check now asks about the first and last deadlines.
  • It reuses openEngine and fullTree. The check and the measurement that sets LADDER_YEARS then run the same document through the same engine.
  • It takes a published version as well as a directory. openEngine already reads one, so this package's run needs no local build.
  • Exit 1 when either question misses. Either miss means the game cannot be finished on that dataset, which must block an upload as D1 does.
  • The bench case seeds no run time and no amount. It measures the run a player gets; the record is on the live dataset, because fixture-0 has too few drops to load a frame.
  • The purchase-to-ready wait is measured on a laptop and reported, not barred. The source model asks for it before pacing numbers are fixed; a number with no target cannot fail a build, and the owner sets CLOCK.buyS from it. No phone is available to the agent.
  • The pointer path is a figure from the test, one move after another. Real input reaches the map and the run layer alike, and no timer paces it.
  • The reach check's documentation lives in game.md. The pipeline and deploy docs point there, so one place holds its lines and exits.
  • docs/lesscars/plan-v1.md keeps the old name. Its line is a dated source record.
