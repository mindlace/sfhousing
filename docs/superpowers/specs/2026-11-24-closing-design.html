Closing: the journey, the reach check, the run bench and the documents

Proves the incremental loop end to end on the merged tree, asks the reach check its two questions, measures a run with drops, and makes every current document true to the game and its new name.

Purpose

This unit runs last, after every other unit of the design has merged into the integration branch. It produces no interface row and needs every row. Its job is to prove the package as a whole and to tell the next developer what the game now is.

  • The journeys: a new visitor paints to the room goal, starts, runs with "Collect for me", reads the tally, buys a node, runs again and takes the next goal; a keyboard-only player does the same with the ring; a player at the last rung reaches the ending.

  • The game's developer document rewritten, and CLAUDE.md, README.md and the other current documents that carry the old name made true.
  • The accessibility checklist run for the game's page in each of its states.

Decisions

  • One goal amount, 1, for every journey. One stamp meets the room goal and every run meets its rung on fixture-0, which removes the old mid-test write of the key and makes each run's outcome certain.
  • No ladder seam. G6 makes RUNGS a constant; seeding a game at the last rung reaches the ending without changing a model commitment.
  • A fast-run seam of 500 to 60,000 ms. A 20 s run does not fit Playwright's 30 s test timeout, and signoff forbids raising it.
  • A run hook, window.__sfhRun. The ring is drawn on a canvas, so a keyboard journey can find a drop only from the page's own state.
  • The arrow step is at most the base radius. Otherwise a ring steered one step at a time can pass over a drop forever.
  • State is read from storage, not the screen. The saved game is G1's contract, while the words on the tally are another unit's to choose.
  • Nodes are found on the screen. The catalogue imports $lib, which Playwright cannot resolve.
  • The keyboard journey runs on chromium only. A keyboard on the phone layout is not a case the checklist asks for, and the pointer journey covers the phone.
  • The open game at / shows the workshop. Call 9 makes it the whole tool with no runs, tally or tree; the opening shows the brush only for a game in its opening.
  • gotoEditor makes a new visitor. The Paint specs then reach the brush with one change in one helper.
  • The step clicks become the site-name link. Those tests are about a client navigation into the simulation, which the site name still gives.
  • The title of / is expected to be "SF Housing". One page needs one title, and the design names the site "SF Housing".
  • The reach check is renamed reach-check. Level 2 no longer exists, and the check now asks about the first and last deadlines.
  • The full tree's document is built in the reach check by a written rule. The rule (catalogue order made topological, grants with the limits after each purchase) gives one document, which the check's test pins.
  • Exit 1 when either question misses. Either miss means the game cannot be finished on that dataset, which must block an upload as D1 does.
  • The reach check runs on a local rebuild of the published version. Nothing hashed changes, so the build is the published dataset, and nothing is uploaded.
  • The bench case seeds no run time and no amount. It measures the run a player gets; the record is on the live dataset, because fixture-0 has too few drops to load a frame.
