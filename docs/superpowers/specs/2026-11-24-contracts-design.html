Contracts: the incremental loop's shapes as code

New files under src/lib/game/ with real types, stubs that throw and constants with starting values, plus four optional additions to the map's and the score's types, so every other unit builds against the interface table.

Purpose

This unit lands first. It writes every interface row of the incremental loop design that can be code without changing behaviour, so the other eleven units build against one set of shapes with their own fakes.

  • It produces the shape of rows G1 to G6 and R1 as new files under src/lib/game/.
  • It produces the shape of rows E1, E2 and M1 as optional additions to existing types, and an empty setRunView on the map.
  • Rows G7, G8 and U1, and the props of RunLayer in R1, replace or add running code that other units own. Their contract is the design's code block, copied below. This unit writes no file for them (design, Contracts: "The components of R1 and U1 are not stubbed").
  • It changes no behaviour. The five-level game files stay as they are. The application builds and its tests pass after this unit merges.
  • It needs no row.

Rulings it carries: P10 (units by kind, from G1's Units), P15 (v: 2 in G1's types), and the design's Contracts section as written.

These rows and their sections are copied from the design document with no change. This unit produces the shape of every row; the owner named in each row makes it real. A change to one is a change to the design.

open
The open game: every control, no limit (call 9).
presets, measures
The permitting preset ids and funding preset ids that run.
bands, stories, reachM
The most bands a transit rule may have, its tallest band and its furthest band. All 0 before the first stop type is bought.
custom
Custom timing and custom route shares may be set.
FREE_MEASURES
state-off and federal-credits-off.
  • limitsOf folds the grants of every level bought. The largest stories, reach, bands, radius and linger win.
  • Once a stop type is bought, bands, stories and reachM are at least START_BANDS, START_STORIES and START_REACH_M.
  • BASE_HANDS is a radius of 48 px, a linger of 4,000 ms and no auto. Every Hands step in the catalogue is above it.
  • Once the last rung is met, stories is 80, bands 3, reachM 3219, every stop type is in, custom is true, and presets also holds observed, the preset a custom timing policy carries.
  • within does not read a policy's on.
  • A permitting policy is within the limits when its preset is in presets, and, unless custom, it has no custom edit and no custom route shares.
  • A transit rule is within the limits when its stop types are in stops, it has at most bands bands, no band is taller than stories and none is further than reachM.
  • A protection is within the limits once stops is not empty.
  • A painted area is within the limits only when open (P11).
  • A money policy is within the limits when it is given and its preset is in measures, or its preset is in FREE_MEASURES and measures is not empty. Any other money policy only when open (D4).
  • runnable keeps the policies within the limits and returns the same document when it drops none.
  • With OPEN_LIMITS, within is always true.

Unchanged: isGiven. Removed: Allowed, ALL_ALLOWED, allowedAt, unlocksAt, runs, playable, levelNeeded, simLocked, needsHigher.

// src/lib/game/grant.ts
import type { addChoices } from '$lib/timeline/add';

}

export function applyGrant(doc: SimPolicy4, grant: Grant, ctx: GrantCtx): SimPolicy4;
limits
The limits after the purchase.
GAME_TRANSIT_ID
The id of the one transit rule the game makes.
  • Every policy the function adds is on, with one span from month 1 and no end.
  • preset and measure: a policy of that kind that names the preset and is within ctx.limits is switched on when it is off. When there is none, one is added as "+" adds it today. A policy that names the preset and is outside ctx.limits is left as it is.
  • stop: the game's rule gains the stop type. When there is no such rule, one is added with every stop type in limits.stops and one band at limits.reachM and limits.stories.
  • stories: the innermost band of the game's rule takes the new cap, and so does every band that was as tall as it.
  • reach: the outermost band of the game's rule takes the new distance.
  • bands: the game's rule gains a band. Where there is room inside limits.reachM it goes beyond the outermost, as the editor adds one today. Where there is none the outermost band is split in two.
  • A grant whose policy the player removed or changed past recognition adds it again and leaves the player's own policies alone.
  • hands: the document is returned unchanged.
  • The result is within ctx.limits and passes parsePolicy4.
  • The function never removes a policy and changes no policy other than the one it adds, the game's rule, or a policy within ctx.limits that names the bought preset or measure.

  • sideShown returns the first SIDE_SHOWN goals whose ring is open and which are not met.
  • A side goal's read returns null when the view lacks what it reads.

Design

Rules for every stub file

  • Each file's text is given in full below. The implementer writes it as given.
  • Types, interfaces and their field names are the design's, letter for letter.
  • Every function body is the one statement throw new Error('not implemented');.
  • A stub's parameter names carry a leading _ so ESLint passes. The owning unit drops the _ when it writes the body. Parameter names are not part of a TypeScript signature's type.
  • An optional parameter that the design gives a default (nodes, goals) is written as optional, with no default, in the stub. The owner writes the default.
  • An import is type-only unless a constant's value needs it. The only value import is LADDER_YEARS in ladder.ts.
  • state.ts and save-shape.ts import nothing through $lib at run time: a $lib import is a type import, and a value import is relative. The e2e helper can then load them by relative path.
  • Every type that the props of RunLayer, Tally, Tree and GoalHeadline name exists in a stub: RunFeed, Hands, Sound, RunTake, RunResult, NodeView, NodeId, Units, Rung and SideGoal. Day is the existing one.
  • No stub imports a five-level file, so game-save can delete those files without touching a stub.
  • No stub constant is frozen. Nothing may change a constant's contents. game-core freezes the constants it makes real (NEW_GAME, BASE_HANDS, FREE_MEASURES, OPEN_LIMITS, SIDE_GOALS) when it writes their bodies.
  • Each file opens with one comment line naming its row and the unit that makes it real.

Where the files differ from the design's code blocks

The design's blocks are contracts, not files. These are the only differences, and none changes a type.

  • run-result.ts imports Goal, Day, GameState, Units and SideInput, which the design's block uses without importing.
  • side-goals.ts imports TimelineView, RunTake, GameState and Units, which the design's block uses without importing.
  • ladder.ts imports the value LADDER_YEARS to compute RUNGS. It does not import Units, which none of its stub's types use.
  • ladder.ts does not import RUNG_LUMP, and side-goals.ts does not import SIDE_TUNING: a stub body reads neither, and ESLint refuses an unused import. game-core adds both imports when it writes the bodies.
  • run/drops.ts does not import Hands or RunTake. The design's block imports them for RunLayerProps, which lives in RunLayer.svelte; in drops.ts they would be unused imports, which ESLint refuses. run-play imports them in RunLayer.svelte.
  • RunLayerProps is not written: it belongs to RunLayer.svelte, which this unit does not stub.
  • The four additions to existing types are optional, as the design's Contracts section says.

Decisions

  • Stub parameters carry _. ESLint refuses unused parameters otherwise, and a parameter's name is not part of the type.
  • isGiven throws. The design says every function throws, and the stub must not import allowed.ts, which game-save deletes.
  • OPEN_LIMITS uses literals tied by a test. It keeps limits.ts free of value imports from the editors, while a drift in any source fails a test.
  • OPEN_LIMITS.measures is empty in the stub. open already lets every money policy through, so the stub needs no list; game-core's body fills it with every funding preset id, so a consumer that forgets to test open still shows every measure.
  • OPEN_LIMITS.hands is BASE_HANDS. The open game has no runs, so the base values are as good as any and invent nothing.
  • NEW_GAME.units is {}. G2 reads a missing kind as 0, so an empty balance needs no entry.
  • No stub constant is frozen. Freezing changes how a mistaken write fails, which is the owner's call; game-core, the owner, freezes the constants it makes real. The contract's types are kept as written.
  • An absent existing reads as 0. It matches "a row whose marker has not begun carries 0" (E1).
  • Stubs leave out imports their bodies do not use. Hands and RunTake in drops.ts, Units and RUNG_LUMP in ladder.ts, and SIDE_TUNING in side-goals.ts would fail ESLint as unused.
