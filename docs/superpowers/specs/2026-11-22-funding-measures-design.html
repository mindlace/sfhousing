Funding measures design

Every funding preset ends, a pool's bar reads its lifetime money, the funding editors end at the window, and a given measure reads as fixed text.

Goal

This unit makes the funding presets that level 5 offers into finite, fixed measures and shows them so. It is the funding-measures subsystem of the incremental game design, built after finite-funding and pool-closing have merged (it needs F2 and F3) and against G3.

  • Every funding preset's money ends: the two with none today get a stated term, with its source and tier (D3, R2).
  • A given measure's dates are counted from the start the player chooses, through dateMeasure (M1); its span's end cuts what arrives after it (D4).
  • A pool's bar on the timeline shows what is left of all the money the pool receives in the window, and reads empty while the pool is closed (Finite public money).
  • The funding editors run to the window's last month (the calendar month that holds the window's last day), taken from the dataset date, and never offer "no end".
  • The federal tax-credit group is edited as any capped group, now that it has a yearly ceiling (F2).
  • The read-only summary of a given measure lists what it pays and when its money ends, word for word.
  • The funding sentences that D13 makes false are reworded.
  • "Your own pool", "City funding scale" and "Market terms" keep working in the code for level 6 (D4).

  • runs is false for a kind not in a.kinds.
  • runs is false for a money policy that is not given while a.money is 'given'.

  • An edit that changes what a given measure pays sets its preset to null.
  • isGiven is false for every zoning and permitting policy.
  • isGiven does not check the id against the presets on offer. A hand-made document can carry any id on any pool; nothing ranks one player against another, so that is accepted.

That amount pays the federal part of about 22.6 million affordable homes a year, more than fifty times the homes San Francisco has, and is above every amount an added pool may hold (MAX_DOLLARS), so no San Francisco policy reaches it and no added pool reads "No ceiling".

  • A pool's bar on the timeline reads empty in every month shut marks: what a closed pool still holds is never awarded.

// src/lib/sim-page/funding-presets.ts

/** `policy` with its money dated from its first span's start; `policy` itself when nothing moves. */

The first date
With start given it is start for every 'start' preset. Without it, each preset keeps today's default: nextFiscal(asOf) for the City and bank presets and the state scales, nextCalendar(asOf) for federal-credits-off, and 1 January of the later of 2028 and the year after asOf for federal-support.
Later dates
Each later date is yearsAfter(first, k): the bank's payments at k = 1 to 4, general-revenue's to at 29, federal-support's to at 9, state-double's second entry at 10.
  • Every pool a preset builds has only once inflows or yearly inflows whose to is not null.
  • A yearly inflow's to is the day of its last payment exactly, so inflowArrivals gives the stated number of payments.
  • state-double's scale content is two entries on the state pool: scale 2 from the first date, scale 1 from yearsAfter(first, 10).
  • state-off and federal-credits-off keep one entry at scale 0: they add no money, and their end is the end of the span the player gives them.
  • htf-2026 has dates: 'fixed' and ignores start; every other preset has dates: 'start'.
  • Every programme a preset builds has from equal to its pool's first payment and to: null; the money's end bounds it.
  • federal-support's yearly amount is the dollars of the baseline state pool's first arrival on or after asOf, from a once or a yearly inflow. It is held back only when the state pool has no arrival from asOf, with the reason "This data's state pool has no money to start from."
  • A date a preset builds may fall after the window; that money never arrives in the forecast and the preset keeps it.
  • With start given, PLAYER_START_PROVENANCE takes the place of NEXT_FISCAL_START_PROVENANCE and FEDERAL_SUPPORT_START_PROVENANCE in each preset's provenance.
  • general-revenue's provenance adds GENERAL_FUND_TERM_YEARS.provenance; federal-support's adds FEDERAL_SUPPORT_TERM_YEARS.provenance; state-double's is [STATE_DOUBLE_TERM_YEARS.provenance].

A measure's dates and its policy's spans

dateMeasure is this unit's row M1: its shape, when it returns its policy unchanged, and who calls it are there. A given measure is a money policy whose preset is a funding preset's id (G3). Its money still arrives only in months a span of its policy is in force.

dateMeasure tests a given measure with isGiven from $lib/game/allowed. How it re-dates, and what the spans then do to the payments:

  • Every span's effect becomes the content of fundingPresets(cal, policy.spans[0].from)'s preset named by policy.preset, with the policy's own pool and programme ids and its label.
  • A scale measure's entries move with its start in the same way.
  • The player's end cuts the measure: a payment dated after the last day of the policy's last span never arrives.
  • A gap between two spans loses the payments dated inside it.
  • Switching the policy off loses every payment while it is off, as today.
  • A preset whose dates are set in law (dates: 'fixed', htf-2026) keeps its dates; the player's start and end only cut them.
  • dateMeasure also returns policy itself when the policy's content, with every date left out, differs from the preset's. G3 already makes an edited measure not given; this guards a document that holds one.

A pool's lifetime level

Every pool's bar drains from full as its money is allocated and never refills at a yearly payment. A closed pool's bar reads empty.

Lifetime receipts
The dollars of every arrival the money track gives the pool over months 1 to WINDOW_MONTHS: createMoneyTrack(doc, { asOf, finance }) with finance holding the baseline pools, no programmes, no off spans, slope 0 and resolveTerms(MARKET_TERMS), and month m's levers moneyLeversOf(inForceAt(doc, monthFirstDay(asOf, m))). A pool with a yearly inflow with no end counts each payment up to the window's last month. An added pool's definitions are its spans' pools; a baseline pool's is the calibration's.
usedi
committed + spent + out + lostCredit at month i, as today.
shuti
money.shut[id][i] (F3); false where it is absent.
  • Month i's level is Σ(shuti ? 0 : leverage × lifetime − usedi) ÷ Σ(leverage × lifetime), over the pools given whose lifetime is not null.
  • A level is clamped to [0, 1], and is NaN where its denominator is 0.
  • lifetimes gives null, so the pool has no level and stays out of every sum, for a pool with a yearly inflow whose amount isNoCeiling (an older dataset's federal pool, F2), and for every pool when the money track throws for doc.
  • A pool with a lifetime reads 1 from month 0 until money is committed: all of it is still to come or free.
  • A pool whose policy is off, or whose payments all fall outside its spans, has a lifetime of 0 and no level.
  • A closed pool reads 0 in every month MoneyView.shut marks, whatever it still holds: money in a closed pool is never awarded (D13, F3). From the month an arrival opens it again it reads by the formula.
  • Loan repayments and released commitments lower usedi, so an open pool's level can rise; a yearly payment never raises it.
  • A scale policy changes a baseline pool's lifetime exactly as it changes the pool's arrivals: state-double doubles the state pool's lifetime receipts for its ten years.
  • levelSet keeps its signature and its LevelSet. Each fund policy's entry and "Current funding" read lifetimes(doc, baseline ?? [], asOf).
  • "Current funding" sums the baseline pools, so it drains through the window: today's sources with no end count their payments to the window's last month.
  • lifetimes is computed once per document, baseline and asOf: a new view with the same three reuses it.
  • Yearly payments still arrive in lumps (R7); the bar counts each one from the start, so a lump never shows as a refill.
  • Details carries the "ran out" line (F3).

Global constraints

  • Work happens in git worktrees under .claude/worktrees/. Commits follow Conventional Commits. No attribution to an AI anywhere.
  • Code style: 2-space indent, single quotes, no trailing commas, 100 columns.
  • Every Vitest test calls expect.
  • Signoff fails on server stderr, on timing crutches and on a retried flake. Each unit runs npm run lint, npm run check and the Vitest projects its files belong to before it hands back.
  • Port 4173 is shared by every session on this machine. A unit never kills a server it did not start; it waits.
  • Every agent runs every command in the foreground and never ends a turn while something it started is running.
  • Schema changes go through npm run db:generate. Nobody edits a migration.
  • No unit runs npm run signoff: its dataset step fails until the dataset is uploaded. closing runs it once, after the upload.
  • The dataset version changes in this build. The dataset is uploaded once, by closing, from the integration branch, after every unit has merged; no other unit uploads a dataset. reach-check builds one earlier to run the check and uploads nothing.
  • A unit that writes a hashed path regenerates the fixture dataset with npm run pipeline -- fixture and commits it.
  • WCAG 2.2 AA: every new control is at least 24 px and passes expectNoA11yViolations in light and dark.
  • Page text is short. No sentence says what something is not.
  • Nothing on the main screen says "RHNA". The goal is read from the Goal value, never from a constant.
  • The game's rules are read from src/lib/game/. No component compares a level to a number.
  • One future: no seed control, no band, no average over runs.
  • Published plans and policies, their ids and their pages keep working, including every policy published before this build.
  • A number that is a claim about the world carries its source and tier, in the existing Sourced, Unsourced and Evidence shapes.
  • A runtime dependency that ships in the bundle gets a credit in SOFTWARE. This build adds none.
  • CSP changes are interface changes. This build makes none.
  • Timing is measured only on a quiet machine. A unit that cannot get one defers the measurement and says so.
